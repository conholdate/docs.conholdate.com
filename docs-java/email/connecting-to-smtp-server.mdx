2. Set a password.

The following code snippet shows you how to connect SSL enabled SMTP server.

```Java
// For complete examples and data files, please go to https://github.com/aspose-email/Aspose.Email-for-Java

SmtpClient client = new SmtpClient("smtp.gmail.com");

```

## Connecting to Server via Socks Proxy Sever {#connecting-to-server-via-socks-proxy-sever}

Sometimes we use proxy servers for communicating with the outside world. In such cases, mail clients are not able to communicate over the Internet without specifying the proxy address. Aspose.Email provides support for versions 4, 4a and 5 of SOCKS proxy protocol. This article provides a working sample of sending email using a proxy mail server. To send an email via a proxy server:

1. Initialize Proxy with the required information, that is proxy address, port, and SOCKS version.
2. Initialize <a href="https://reference.aspose.com/email/java/com.aspose.email/smtpclient/" target="_blank" rel="nofollow noopener noreferrer">SmtpClient</a> with the host address, user name and password, and any other settings.
3. Set the client Proxy property to the <a href="https://reference.aspose.com/email/java/com.aspose.email/emailclient/#getProxy--" target="_blank" rel="nofollow noopener noreferrer">Proxy</a> object created earlier.

The following code snippet shows you how to connect to a server via proxy server.

```Java
// For complete examples and data files, please go to https://github.com/aspose-email/Aspose.Email-for-Java

SmtpClient client = new SmtpClient("smtp.domain.com", "username", "password");
client.setSecurityOptions(SecurityOptions.SSLImplicit);
String proxyAddress = "192.168.203.142"; // proxy address
int proxyPort = 1080; // proxy port
SocksProxy proxy = new SocksProxy(proxyAddress, proxyPort, SocksVersion.SocksV5);
client.setProxy(proxy);
client.send(new MailMessage("sender@domain.com", "receiver@domain.com", "Sending Email via proxy",
        "Implement socks proxy protocol for versions 4, 4a, 5 (only Username/Password authentication)"));
```

## Customize Authentication Mechanism {#customize-authentication-mechanism}

Retrieve the list of authentication mechanisms that are supported by the SMTP server using the <a href="https://reference.aspose.com/email/java/com.aspose.email/smtpclient/#getSupportedAuthentication--" target="_blank" rel="nofollow noopener noreferrer">getSupportedAuthentication</a> method of the <a href="https://reference.aspose.com/email/java/com.aspose.email/smtpclient/" target="_blank" rel="nofollow noopener noreferrer">SmtpClient</a> class. This method allows the client to determine which authentication methods are available for establishing a secure connection with the server. Then, using the <a href="https://reference.aspose.com/email/java/com.aspose.email/smtpclient/#setAllowedAuthentication-long-" target="_blank" rel="nofollow noopener noreferrer">setAllowedAuthentication</a> method which gets (or sets) enumeration of the authentication types allowed by user, choose the most appropriate authentication mechanism for the client-server communication. This allows you to set the authentication method for the mail client explicitly.

The following code sample shows how to customize email client authentication:

```java
smtpClient.setAllowedAuthentication(SmtpKnownAuthenticationType.Login);
```

## Using CRAM-MD5 authentication to Connect to a Server {#using-cram-md5-authentication-to-connect-to-a-server}

To ensure secure authentication and communication with the SMTP server, you can specify and enforce the use of CRAM-MD5 as the allowed authentication method for the SMTP client. The following code snippet shows how to configure the allowed authentication type for the <a href="https://reference.aspose.com/email/java/com.aspose.email/smtpclient/" target="_blank" rel="nofollow noopener noreferrer">SmtpClient</a>:

```java
smtpClient.setAllowedAuthentication(SmtpKnownAuthenticationType.CramMD5);
```

## Bind SMTP Client to Specific IP Address on Host {#bind-smtp-client-to-specific-ip-address-on-host}

The possibility of a host having multiple ports available for sending out emails cannot be ruled out. In such cases, the requirement may arise to bind the email sending client to a specific port on the host for sending out emails. This can be achieved with Aspose.Email API as well using the <a href="https://reference.aspose.com/email/java/com.aspose.email/smtpclient/" target="_blank" rel="nofollow noopener noreferrer">SmtpClient</a> <a href="https://reference.aspose.com/email/java/com.aspose.email/smtpclient/#bindIPEndPoint-com.aspose.email.BindIPEndPointHandler-" target="_blank" rel="nofollow noopener noreferrer">bindIPEndPoint</a> property. The API <a href="https://reference.aspose.com/email/java/com.aspose.email/smtpclient/" target="_blank" rel="nofollow noopener noreferrer">SmtpClient</a> can be set to use a specific IP address on the host by specifying the specific IP Endpoint. The following code snippet shows you how to bind SMTP Client to Specific IP Address on Host.

```Java
// For complete examples and data files, please go to https://github.com/aspose-email/Aspose.Email-for-Java

SmtpClient client = new SmtpClient("smtp.domain.com", // host
        587, // port
        "username", // username
        "password", // password
        SecurityOptions.Auto // Security Options
);
try {
    client.bindIPEndPoint(new BindIPEndPointHandler() {
        public InetSocketAddress invoke(InetSocketAddress remoteEndPoint) {
            return new InetSocketAddress(0);
        }
    });
    client.noop();
} finally {
    client.dispose();
}
```

## Validate Mail Server Credentials Without Sending Email {#validate-mail-server-credentials-without-sending-email}

Sometimes it is necessary to verify credentials without sending an email. Aspose.Email provides the <a href="https://reference.aspose.com/email/java/com.aspose.email/smtpclient/#validateCredentials--" target="_blank" rel="nofollow noopener noreferrer">validateCredentials()</a> method to perform this operation. If the validation is successful, the code inside the if statement is executed, typically used to perform further actions or retrieve data from the IMAP server. The following code snippet demonstrates the validation of credentials without sending an email:

```java
try (SmtpClient smtpClient = new SmtpClient(
        server.SmtpUrl, server.SmtpPort, "username", "password", SecurityOptions.Auto)) {
    smtpClient.setTimeout(4000);

    if (smtpClient.validateCredentials()) {
        // to do something
    }
}
```

## Using Cryptographic Protocols with SMTP {#using-cryptographic-protocols-with-smtp}

Aspose.Email supports SSL (obsolete) and TLS cryptographic protocols to provide communications security. You can enable cryptographic encryption to protect data exchange between your application and mail servers.

The supported values are listed in the <a href="https://reference.aspose.com/email/java/com.aspose.email/encryptionprotocols/" target="_blank" rel="nofollow noopener noreferrer">EncryptionProtocols</a> enumeration: `Ssl2`, `Ssl3`, `Tls`, `Tls11`, `Tls12` and `Tls13`. Values can be combined with the bitwise OR operator.

\{% alert color="primary" %\} Set only those versions of the protocol that are supported by your JRE. If a version is not supported, it is ignored and skipped, and no exception is generated. Use the `setSupportedEncryptionUnsafe` method if you want to set the protocols without any compatibility checks: `setSupportedEncryption` downgrades the encryption protocol to a supported level, while `setSupportedEncryptionUnsafe` throws an exception instead. \{% /alert %\}

The code example below shows you how to set TLS 1.3 for a <a href="https://reference.aspose.com/email/java/com.aspose.email/smtpclient/" target="_blank" rel="nofollow noopener noreferrer">SmtpClient</a> instance.

```java
try (SmtpClient smtpClient = new SmtpClient("host", 587, "username", "password", SecurityOptions.SSLExplicit)) {
    smtpClient.setSupportedEncryption(EncryptionProtocols.Tls13);

    // some code...
}
```

To allow more than one protocol version, combine the flags:

```java
try (SmtpClient smtpClient = new SmtpClient("host", 587, "username", "password", SecurityOptions.SSLExplicit)) {
    smtpClient.setSupportedEncryption(EncryptionProtocols.Tls12 | EncryptionProtocols.Tls13);

    // some code...
}
```

## Enable Activity Logging {#enable-activity-logging}

Activity logging is used for debugging, as well as for collecting and analyzing working information about the SMTP client. In Aspose.Email for Java, logging is configured in code through the properties inherited from the <a href="https://reference.aspose.com/email/java/com.aspose.email/emailclient/" target="_blank" rel="nofollow noopener noreferrer">EmailClient</a> class:

- `setEnableLogger(boolean)` - turns the logging on and off.
- `setLogFileName(String)` - specifies the relative or absolute path to the log file. The overload `setLogFileName(String, boolean)` also lets you append to an existing file instead of overwriting it.
- `setUseDateInLogFileName(boolean)` - adds the current date to the log file name, so that a separate file is written for every day.
- `resetLogSettings()` - restores the default logging settings.
- `EmailClient.setShowCredentialsInLog(boolean)` - a static switch that controls whether credentials appear in the log. Keep it disabled in production.

```java
try (SmtpClient smtpClient = new SmtpClient("host", 587, "username", "password", SecurityOptions.SSLExplicit)) {
    // Never write credentials into the log file
    EmailClient.setShowCredentialsInLog(false);

    smtpClient.setEnableLogger(true);
    smtpClient.setUseDateInLogFileName(true);
    smtpClient.setLogFileName("logs/smtp.log");

    // some code...
}
```

\{% alert color="primary" %\} The `appsettings.json` and `App.config` configuration options described in the Aspose.Email for .NET documentation do not apply to Java - enable logging in code as shown above. \{% /alert %\}
