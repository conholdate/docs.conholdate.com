The <a href="https://reference.aspose.com/email/java/com.aspose.email/pop3client/" target="_blank" rel="nofollow noopener noreferrer">Pop3Client</a> class allows applications to manage email boxes using the Post Office Protocol, Version 3 (POP3). To connect to a server, use the <a href="https://reference.aspose.com/email/java/com.aspose.email/pop3client/" target="_blank" rel="nofollow noopener noreferrer">Pop3Client</a> class. The <a href="https://reference.aspose.com/email/java/com.aspose.email/pop3client/" target="_blank" rel="nofollow noopener noreferrer">Pop3Client</a> class is the major entry for developers who want to add POP3 management to their .NET applications. This article explains how to use it. To connect to a POP3 server:

1. Create an instance of the <a href="https://reference.aspose.com/email/java/com.aspose.email/pop3client/" target="_blank" rel="nofollow noopener noreferrer">Pop3Client</a> class.
2. Specify the host, username, and password in the <a href="https://reference.aspose.com/email/java/com.aspose.email/pop3client/" target="_blank" rel="nofollow noopener noreferrer">Pop3Client</a> instance.

The following code snippet shows you how to connect with the POP3 server.

```Java
// For complete examples and data files, please go to https://github.com/aspose-email/Aspose.Email-for-Java

// Create an instance of the Pop3Client class
Pop3Client client = new Pop3Client();

// Specify host, username, password, Port and SecurityOptions for your client
client.setHost("pop.gmail.com");
client.setUsername("your.username@gmail.com");
client.setPassword("your.password");
client.setPort(995);
client.setSecurityOptions(SecurityOptions.Auto);
System.out.println("Connected to POP3 server.");
```

## Connecting with an APOP Server {#connecting-with-an-apop-server}

POP stands for Post Office Protocol. APOP stands for Authenticated Post Office Protocol. APOP is an extended version of the POP3 server setting that encrypts your username and password and uses an authentication mechanism designed to protect your POP3 account password when checking email. APOP authentication does not require the account password to be sent as plain text to the POP3 mail server.

## Connecting to Server via Proxy {#connecting-to-server-via-proxy}

Proxy servers are very common for communicating with the outside world. In such cases, proxy addresses are used for email clients to access mailboxes over the Internet. Aspose.Email provides support for versions 4, 4a and 5 of the SOCKS proxy protocol. This article provides a working sample of retrieving email using a proxy mail server. To retrieve email via a proxy server:

1. Initialize <a href="https://reference.aspose.com/email/java/com.aspose.email/proxy/" target="_blank" rel="nofollow noopener noreferrer">Proxy</a> with the required information, that is, proxy address, port, and SOCKS version.
2. Initialize <a href="https://reference.aspose.com/email/java/com.aspose.email/pop3client/" target="_blank" rel="nofollow noopener noreferrer">Pop3Client</a> with the host address, user name, password, and any other settings.
3. Set the client Proxy property to the <a href="https://reference.aspose.com/email/java/com.aspose.email/proxy/" target="_blank" rel="nofollow noopener noreferrer">Proxy</a> object created above.

The following code snippet shows you how to retrieve emails via proxy server.

```Java
// For complete examples and data files, please go to https://github.com/aspose-email/Aspose.Email-for-Java

// Create an instance of the Pop3Client class
Pop3Client client = new Pop3Client("pop.domain.com", "username", "password");

// Set proxy address, Port and Proxy
String proxyAddress = "192.168.203.142";
int proxyPort = 1080;
SocksProxy proxy = new SocksProxy(proxyAddress, proxyPort, SocksVersion.SocksV5);
client.setProxy(proxy);
Pop3MailboxInfo mailboxInfo = client.getMailboxInfo();
```

## Customize Authentication Mechanism {#customize-authentication-mechanism}

Retrieve the list of authentication mechanisms that are supported by the POP3 server using the <a href="https://reference.aspose.com/email/java/com.aspose.email/pop3client/#getSupportedAuthentication--" target="_blank" rel="nofollow noopener noreferrer">getSupportedAuthentication</a> method of the <a href="https://reference.aspose.com/email/java/com.aspose.email/pop3client/" target="_blank" rel="nofollow noopener noreferrer">Pop3Client</a> class. This method allows the client to determine which authentication methods are available for establishing a secure connection with the server. Then, using the <a href="https://reference.aspose.com/email/java/com.aspose.email/pop3client/#setAllowedAuthentication-long-" target="_blank" rel="nofollow noopener noreferrer">setAllowedAuthentication</a> method which gets (or sets) enumeration of the authentication types allowed by user, choose the most appropriate authentication mechanism for the client-server communication. This allows you to set the authentication method for the mail client explicitly.

The following code sample shows how to customize email client authentication:

```java
pop3Client.setAllowedAuthentication(Pop3KnownAuthenticationType.Plain);
```

## Validate Mail Server Credentials Without Sending Email {#validate-mail-server-credentials-without-sending-email}

Sometimes it is necessary to verify credentials without sending an email. Aspose.Email provides the <a href="https://reference.aspose.com/email/java/com.aspose.email/pop3client/#validateCredentials--" target="_blank" rel="nofollow noopener noreferrer">validateCredentials()</a> method to perform this operation. If the validation is successful, the code inside the if statement is executed, typically used to perform further actions or retrieve data from the IMAP server. The following code snippet demonstrates the validation of credentials without sending an email:

```java
try (Pop3Client pop3Client = new Pop3Client(
        server.Pop3Url, server.Pop3Port, "userName", "password", SecurityOptions.Auto)) {
    pop3Client.setTimeout(4000);

    if (pop3Client.validateCredentials()) {
        // to do something
    }
}
```

## Using Cryptographic Protocols with POP3 {#using-cryptographic-protocols-with-pop3}

Aspose.Email supports SSL (obsolete) and TLS cryptographic protocols to provide communications security. You can enable cryptographic encryption to protect data exchange between your application and mail servers.

The supported values are listed in the <a href="https://reference.aspose.com/email/java/com.aspose.email/encryptionprotocols/" target="_blank" rel="nofollow noopener noreferrer">EncryptionProtocols</a> enumeration: `Ssl2`, `Ssl3`, `Tls`, `Tls11`, `Tls12` and `Tls13`. Values can be combined with the bitwise OR operator.

\{% alert color="primary" %\} Set only those versions of the protocol that are supported by your JRE. If a version is not supported, it is ignored and skipped, and no exception is generated. Use the `setSupportedEncryptionUnsafe` method if you want to set the protocols without any compatibility checks: `setSupportedEncryption` downgrades the encryption protocol to a supported level, while `setSupportedEncryptionUnsafe` throws an exception instead. \{% /alert %\}

The code example below shows you how to set TLS 1.3 for a <a href="https://reference.aspose.com/email/java/com.aspose.email/pop3client/" target="_blank" rel="nofollow noopener noreferrer">Pop3Client</a> instance.

```java
try (Pop3Client pop3Client = new Pop3Client("host", 995, "username", "password", SecurityOptions.Auto)) {
    pop3Client.setSupportedEncryption(EncryptionProtocols.Tls13);

    // some code...
}
```

To allow more than one protocol version, combine the flags:

```java
try (Pop3Client pop3Client = new Pop3Client("host", 995, "username", "password", SecurityOptions.Auto)) {
    pop3Client.setSupportedEncryption(EncryptionProtocols.Tls12 | EncryptionProtocols.Tls13);

    // some code...
}
```

## Enable Activity Logging {#enable-activity-logging}

Activity logging is used for debugging, as well as for collecting and analyzing working information about the POP3 client. In Aspose.Email for Java, logging is configured in code through the properties inherited from the <a href="https://reference.aspose.com/email/java/com.aspose.email/emailclient/" target="_blank" rel="nofollow noopener noreferrer">EmailClient</a> class:

- `setEnableLogger(boolean)` - turns the logging on and off.
- `setLogFileName(String)` - specifies the relative or absolute path to the log file. The overload `setLogFileName(String, boolean)` also lets you append to an existing file instead of overwriting it.
- `setUseDateInLogFileName(boolean)` - adds the current date to the log file name, so that a separate file is written for every day.
- `resetLogSettings()` - restores the default logging settings.
- `EmailClient.setShowCredentialsInLog(boolean)` - a static switch that controls whether credentials appear in the log. Keep it disabled in production.

```java
try (Pop3Client pop3Client = new Pop3Client("host", 995, "username", "password", SecurityOptions.Auto)) {
    // Never write credentials into the log file
    EmailClient.setShowCredentialsInLog(false);

    pop3Client.setEnableLogger(true);
    pop3Client.setUseDateInLogFileName(true);
    pop3Client.setLogFileName("logs/pop3.log");

    // some code...
}
```

\{% alert color="primary" %\} The `appsettings.json` and `App.config` configuration options described in the Aspose.Email for .NET documentation do not apply to Java - enable logging in code as shown above. \{% /alert %\}
