## About Aspose iCalendar Object Model {#about-aspose-icalendar-object-model}

The Aspose.Email contains all the classes provided by the Aspose <a href="https://apireference.aspose.com/email/java/com.aspose.email/MapiCalendar" target="_blank" rel="nofollow noopener noreferrer">iCalendar</a> component <a href="https://apireference.aspose.com/email/java/com.aspose.email/RecurrencePattern" target="_blank" rel="nofollow noopener noreferrer">RecurrencePattern</a> and <a href="https://apireference.aspose.com/email/java/com.aspose.email/RecurrenceRule" target="_blank" rel="nofollow noopener noreferrer">RecurrenceRule</a> are the central classes of Aspose <a href="https://apireference.aspose.com/email/java/com.aspose.email/MapiCalendar" target="_blank" rel="nofollow noopener noreferrer">iCalendar</a>, and provide concrete implementations of the corresponding RFC 2445 elements.

The <a href="https://apireference.aspose.com/email/java/com.aspose.email/RecurrencePattern" target="_blank" rel="nofollow noopener noreferrer">RecurrencePattern</a> class represents the whole recurrence pattern. You can create a new recurrence pattern from scratch using the default constructor or load an existing pattern in <a href="https://apireference.aspose.com/email/java/com.aspose.email/CalendarRecurrence#CalendarRecurrence%5C%28java.lang.String%5C%29" target="_blank" rel="nofollow noopener noreferrer">CalendarRecurrence</a>. The <a href="https://apireference.aspose.com/email/java/com.aspose.email/RecurrenceRule" target="_blank" rel="nofollow noopener noreferrer">RecurrenceRule</a> class represents the RRULE or EXRULE part of a recurrence pattern. <a href="https://apireference.aspose.com/email/java/com.aspose.email/RecurrenceRule" target="_blank" rel="nofollow noopener noreferrer">RecurrenceRule</a> exposes a number of properties that directly map to their counterparts in the iCalendar standard. For example, ByMonth maps to BYMONTH in iCalendar and so on. By examining or setting values of the <a href="https://apireference.aspose.com/email/java/com.aspose.email/RecurrenceRule" target="_blank" rel="nofollow noopener noreferrer">RecurrenceRule</a> properties you can analyze or modify a recurrence rule. For more information and code samples, see <a href="https://apireference.aspose.com/email/java/com.aspose.email/RecurrencePattern" target="_blank" rel="nofollow noopener noreferrer">RecurrencePattern</a> and <a href="https://apireference.aspose.com/email/java/com.aspose.email/RecurrenceRule" target="_blank" rel="nofollow noopener noreferrer">RecurrenceRule</a> in the API Reference.

## Important iCalendar RFC 2445 Details {#important-icalendar-rfc-2445-details}

This section includes the following topics:

- Date and Time Formats.
- DATE.
- DATE-TIME with Local Time.
- DATE-TIME with UTC Time.
- DATE-TIME with Local Time and Time Zone.
- BYWEEKNO Provides ISO 8601 Compliance

### Date and Time Formats {#date-and-time-formats}

Dates, or dates with associated times, can be used in the DTSTART, UNTIL, EXDATE and RDATE elements when specifying a recurrence pattern. iCalendar defines the DATE value type to identify values that contains a calendar date and also defines the DATE-TIME type to identify values that specify a precise calendar date and time of day. DATE-TIME values can be specified in three forms, with:

- Local time.
- UTC time.
- Local time and time zone.

### DATE {#date}

According to the iCalendar standard, DATE values must follow the yyyyMMdd format. The following example represents July 14, 1997: 19970714

### DATE-TIME with Local Time {#date-time-with-local-time}

The date with local time form is simply a date-time value that does not contain the UTC designator, and doesn't reference a time zone. For example, the following represents Janurary 18, 1998, at 11 PM: DTSTART:19980118T230000. Date-time values of this type are said to be "floating" and are not bound to any time zone in particular. They are used to represent the same hour, minute, and second value regardless of which time zone is currently being observed.

### DATE-TIME with UTC Time {#date-time-with-utc-time}

The date with UTC time, or absolute time, is identified by a Latin CAPITAL LETTER Z suffix character, the UTC designator, appended to the time value. For example, the following represents January 19, 1998, at 0700 UTC: DTSTART:19980119T070000Z Please note that Aspose <a href="https://apireference.aspose.com/email/java/com.aspose.email/MapiCalendar" target="_blank" rel="nofollow noopener noreferrer">iCalendar</a> ignores the UTC format Z suffix and treats the time as local time. The RFC2445 standard states that a time portion specified in the UNTIL rule of a recurrence pattern must be in UTC format. This is a very strange statement, and in fact, there are examples in the standard that are calculated incorrectly. Aspose <a href="https://apireference.aspose.com/email/java/com.aspose.email/MapiCalendar" target="_blank" rel="nofollow noopener noreferrer">iCalendar</a> accepts time in any format in the UNTIL rule.

### DATE-TIME with Local Time and Time Zone {#date-time-with-local-time-and-time-zone}

To reference the time zone, DATE-TIME is modified with the TZID properyt. For example, the following represents 2 AM in New York on January 19, 1998: DTSTART;TZID=US-Eastern:19980119T020000. Please note that Aspose <a href="https://apireference.aspose.com/email/java/com.aspose.email/MapiCalendar" target="_blank" rel="nofollow noopener noreferrer">iCalendar</a> at the moment ignores the TZID parameter and treats the time as a local time.

### BYWEEKNO Provides ISO 8601 Compliance {#byweekno-provides-iso-8601-compliance}

Use BYWEEKNO only when conformance with <a href="https://en.wikipedia.org/wiki/ISO_8601" target="_blank" rel="nofollow noopener noreferrer">ISO 8601</a> is required. Week numbers as defined by ISO 8601 are very different from week numbers in the normal sense. According to ISO 8601, week number one of the calendar year is the first week of a calendar year that contains at least four days. This rule makes the algorithm specific to applications requiring conformance to ISO 8601 and make it almost inapplicable to other uses. ISO 8601 is supported by some European banking and financial applications. It is also used in television for booking commercials. The BYWEEKNO rule specifies a comma-delimited list of numbers identifying weeks of the year. Valid values are 1 to 53 and 1 to 53. This corresponds to weeks according to week numbering as defined in ISO 8601. BYWEEKNO is only valid for YEARLY rules.
