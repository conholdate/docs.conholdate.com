## Detect a File Format {#detect-a-file-format}

Aspose.Email API provides the capability to detect the file format of the provided message file. The <a href="https://reference.aspose.com/email/java/com.aspose.email/fileformatutil/#detectFileFormat-java.io.InputStream-" target="_blank" rel="nofollow noopener noreferrer">DetectFileFormat</a> method of the <a href="https://reference.aspose.com/email/java/com.aspose.email/fileformatutil/#detectFileFormat%28java.lang.String%29" target="_blank" rel="nofollow noopener noreferrer">FileFormatUtil</a> class can be used to achieve this. The following classes and methods can be used to detect the loaded file format.

- <a href="https://reference.aspose.com/email/java/com.aspose.email/fileformattype/" target="_blank" rel="nofollow noopener noreferrer">FileFormatType</a> Class
- <a href="https://reference.aspose.com/email/java/com.aspose.email/fileformatinfo/" target="_blank" rel="nofollow noopener noreferrer">FileFormatInfo</a> Class
- <a href="https://reference.aspose.com/email/java/com.aspose.email/fileformatutil/" target="_blank" rel="nofollow noopener noreferrer">FileFormatUtil</a> Class
- <a href="https://reference.aspose.com/email/java/com.aspose.email/fileformatutil/#detectFileFormat-java.io.InputStream-" target="_blank" rel="nofollow noopener noreferrer">FileFormatUtil.detectFileFormat(Stream)</a> Method
- <a href="https://reference.aspose.com/email/java/com.aspose.email/fileformatutil/#detectFileFormat-java.lang.String-" target="_blank" rel="nofollow noopener noreferrer">FileFormatUtil.detectFileFormat(String)</a> Method

The following code snippet shows you how to detect file formats.

```java
// For complete examples and data files, please go to https://github.com/aspose-email/Aspose.Email-for-Java
// The path to the resource directory.
String dataDir = Utils.getSharedDataDir(DetectingFileFormat.class) + "email/";
```

## Load an Email Message {#load-an-email-message}

To load a message with specific load options, Aspose.Email provides the <a href="https://reference.aspose.com/email/java/com.aspose.email/loadoptions/" target="_blank" rel="nofollow noopener noreferrer">LoadOptions</a> class that can be used as follow:

```java
// For complete examples and data files, please go to https://github.com/aspose-email/Aspose.Email-for-Java
// Loading with default options
// Load from eml
MailMessage eml = MailMessage.load("test.eml", new EmlLoadOptions());

// Load from html
MailMessage html = MailMessage.load("test.html", new HtmlLoadOptions());

// load from mhtml
MailMessage mhtml = MailMessage.load("test.mhtml", new MhtmlLoadOptions());

// load from msg
MailMessage msg = MailMessage.load("test.msg", new MsgLoadOptions());

// load from thef fomat
MailMessage thef = MailMessage.load("winmail.dat", new TnefLoadOptions());

// Loading with custom options
EmlLoadOptions opt = new EmlLoadOptions();
opt.setPreserveTnefAttachments(true);
MailMessage emlMailMessage = MailMessage.load("test.html", opt);

HtmlLoadOptions htmlOpt = new HtmlLoadOptions();
htmlOpt.shouldAddPlainTextView(true);
MailMessage htmlMailMessage = MailMessage.load("test.html", htmlOpt);
```

### Load from EML {#load-from-eml}

This section describes how to load an EML file into a MailMessage object using the <a href="https://reference.aspose.com/email/java/com.aspose.email/emlloadoptions/" target="_blank" rel="nofollow noopener noreferrer">EmlLoadOptions</a> class. The class provides options to customize how the EML file is loaded, such as preserving embedded message formats or controlling TNEF attachment loading behavior.

1. Initialize an instance of EmlLoadOptions.
2. Configure the load options as needed.
3. Use the `MailMessage.load()` method to load the EML file with the specified options.

```java
// Initialize EmlLoadOptions
EmlLoadOptions loadOptions = new EmlLoadOptions();

// Configure the load options
loadOptions.setPreferredTextEncoding(StandardCharsets.UTF_8);  // preferred encoding for the message
loadOptions.setPreserveEmbeddedMessageFormat(true);            // preserve the format of embedded messages
loadOptions.setPreserveTnefAttachments(true);                  // control TNEF attachment loading
loadOptions.setRemoveSignature(false);                         // do not remove the signature

// Load the EML file
MailMessage eml = MailMessage.load("file.eml", loadOptions);
```

#### Properties of EmlLoadOptions {#properties-of-emlloadoptions}

- `PreferredTextEncoding` - sets the preferred encoding for the message subject and body. The default is `null`.
- `PreserveEmbeddedMessageFormat` - indicates whether to preserve the format of embedded messages during loading. The default is `false`.
- `PreserveTnefAttachments` - controls TNEF attachment loading behavior. The default is `false`.
- `RemoveSignature` - specifies whether the signature should be removed while loading. The default is `false`.

### Load Message With Signature/Without Signature {#load-message-with-signaturewithout-signature}

Signature preservation is supported by default when loading EML files. To remove the signature, set `setRemoveSignature(true)`:

```java
EmlLoadOptions loadOptions = new EmlLoadOptions();
loadOptions.setRemoveSignature(true);

MailMessage msg = MailMessage.load("signed.eml", loadOptions);
```

### Load from HTML {#load-from-html}

The <a href="https://reference.aspose.com/email/java/com.aspose.email/htmlloadoptions/" target="_blank" rel="nofollow noopener noreferrer">HtmlLoadOptions</a> class is specifically designed to handle HTML content, with options to manage resources and add plain text views.

```java
// Initialize HtmlLoadOptions
HtmlLoadOptions loadOptions = new HtmlLoadOptions();

loadOptions.setPathToResources("resources/");                 // directory containing the resource files
loadOptions.setPreferredTextEncoding(StandardCharsets.UTF_8);
loadOptions.shouldAddPlainTextView(true);                     // add a plain text view of the body

// Load the HTML file
MailMessage html = MailMessage.load("file.html", loadOptions);
```

#### Properties of HtmlLoadOptions {#properties-of-htmlloadoptions}

- `PathToResources` - defines the path to the directory containing the resource files (images, for example).
- `PreferredTextEncoding` - sets the preferred encoding for the message subject and body. The default is `null`.
- `PreserveEmbeddedMessageFormat` - determines whether to preserve the format of embedded messages. The default is `false`.
- `shouldAddPlainTextView(boolean)` - specifies whether to add a plain text view of the message body. The default is `false`. Note the accessor name: it is not `setShouldAddPlainTextView`.

### Load from MHTML {#load-from-mhtml}

The <a href="https://reference.aspose.com/email/java/com.aspose.email/mhtmlloadoptions/" target="_blank" rel="nofollow noopener noreferrer">MhtmlLoadOptions</a> class offers options to manage encoding, preserve embedded message formats, and handle TNEF attachments.

```java
// Create MhtmlLoadOptions
MhtmlLoadOptions loadOptions = new MhtmlLoadOptions();

loadOptions.setPreferredTextEncoding(StandardCharsets.UTF_8);
loadOptions.setPreserveEmbeddedMessageFormat(true);
loadOptions.setPreserveTnefAttachments(true);
loadOptions.setRemoveSignature(false);

// Load the MHTML file
MailMessage mhtml = MailMessage.load("file.mht", loadOptions);
```

#### Properties of MhtmlLoadOptions {#properties-of-mhtmlloadoptions}

- `MessageFormat` - represents the mail message format, which can be EML, MSG or MHTML. The default is EML. The property is read-only in Java.
- `PreferredTextEncoding` - sets the preferred encoding for the message subject and body. The default is `null`.
- `PreserveEmbeddedMessageFormat` - determines whether to preserve the format of embedded messages. The default is `false`.
- `PreserveTnefAttachments` - controls TNEF attachment loading behavior. The default is `false`.
- `RemoveSignature` - specifies whether to remove the signature during loading. The default is `false`.

### Load from MSG {#load-from-msg}

The <a href="https://reference.aspose.com/email/java/com.aspose.email/msgloadoptions/" target="_blank" rel="nofollow noopener noreferrer">MsgLoadOptions</a> class offers various properties to handle how MSG files are loaded, including options to preserve RTF content or manage TNEF attachments.

```java
// Create MsgLoadOptions
MsgLoadOptions loadOptions = new MsgLoadOptions();

loadOptions.setKeepOriginalEmailAddresses(true);              // preserve the original email addresses
loadOptions.setPreferredTextEncoding(StandardCharsets.UTF_8);
loadOptions.setPreserveRtfContent(true);                      // keep the RTF content in the message
loadOptions.setPreserveTnefAttachments(true);
loadOptions.setRemoveSignature(false);
loadOptions.setTimeout(5000);                                 // limit the loading time to 5 seconds

// Load the MSG file
MailMessage msg = MailMessage.load("file.msg", loadOptions);
```

#### Properties of MsgLoadOptions {#properties-of-msgloadoptions}

- `KeepOriginalEmailAddresses` - indicates whether to keep the original email addresses. The default is `false`.
- `PreferredTextEncoding` - defines the preferred encoding for the message subject and body. The default is `null`.
- `PreserveEmbeddedMessageFormat` - determines whether the format of embedded messages should be preserved. The default is `false`.
- `PreserveRtfContent` - specifies whether to keep the RTF body content in the `MailMessage`. The default is `false`.
- `PreserveTnefAttachments` - manages TNEF attachment loading behavior. The default is `false`.
- `RemoveSignature` - decides whether to remove the signature during loading. The default is `false`.
- `Timeout` - limits the formatting time in milliseconds during conversion. The default is 3000 ms.
- `TimeoutReachedHandler` - the handler raised when the timeout expires.

#### Properties of TnefLoadOptions {#properties-of-tnefloadoptions}

- `PreferredTextEncoding` - sets the preferred encoding for the message subject and body. The default is `null`.
- `PreserveEmbeddedMessageFormat` - indicates whether to preserve the format of embedded messages. The default is `false`.
- `RemoveSignature` - specifies whether to remove the signature during loading. The default is `false`.

## Save and Convert Email Messages {#save-and-convert-email-messages}

Aspose.Email makes it easy to convert any message type to another format. To demonstrate this feature, the code in this article loads three types of messages from disk and saves them back in other formats. The base class <a href="https://reference.aspose.com/email/java/com.aspose.email/saveoptions/" target="_blank" rel="nofollow noopener noreferrer">SaveOptions</a> and the classes <a href="https://reference.aspose.com/email/java/com.aspose.email/emlsaveoptions/" target="_blank" rel="nofollow noopener noreferrer">EmlSaveOptions</a>, <a href="https://reference.aspose.com/email/java/com.aspose.email/msgsaveoptions/" target="_blank" rel="nofollow noopener noreferrer">MsgSaveOptions</a>, <a href="https://reference.aspose.com/email/java/com.aspose.email/mhtsaveoptions/" target="_blank" rel="nofollow noopener noreferrer">MhtSaveOptions</a>, <a href="https://reference.aspose.com/email/java/com.aspose.email/htmlsaveoptions/" target="_blank" rel="nofollow noopener noreferrer">HtmlSaveOptions</a> for additional settings when saving <a href="https://reference.aspose.com/email/java/com.aspose.email/mailmessage/" target="_blank" rel="nofollow noopener noreferrer">MailMessage</a> can be used for saving messages to other formats. The article shows how to use these classes to save a sample email as:

- EML format.
- Outlook MSG.
- MHTML format.
- HTML format.

#### Convert EML to MHTML with Optional Settings {#convert-eml-to-mhtml-with-optional-settings}

The <a href="https://reference.aspose.com/email/java/com.aspose.email/mhtsaveoptions/" target="_blank" rel="nofollow noopener noreferrer">MhtSaveOptions</a> class provides additional options for saving email messages to MHTML format. The enumerator <a href="https://reference.aspose.com/email/java/com.aspose.email/mhtformatoptions/" target="_blank" rel="nofollow noopener noreferrer">MhtFormatOptions</a> makes it possible to write additional email information to the output MHTML. The following additional fields can be written:

- WriteHeader - write the email header to the output file.
- WriteOutlineAttachments - write outline attachments to the output file.
- WriteCompleteEmailAddress - write the complete email address to the output file.
- NoEncodeCharacters - no transfer encoding of characters should be used.
- HideExtraPrintHeader - hide extra print header from the top of the output file.
- WriteCompleteToEmailAddress - write the complete recipient email address to the output file.
- WriteCompleteFromEmailAddress - write the complete sender email address to the output file.
- WriteCompleteCcEmailAddress - write the complete email addresses of any carbon-copied recipients to the output file.
- WriteCompleteBccEmailAddress - write the complete email address of any blind carbon-copied recipients to the output file.
- RenderCalendarEvent - write text from the calendar event to the output file.
- SkipByteOrderMarkInBody - write Byte Order Mark(BOM) bytes to the output file.
- RenderVCardInfo -write text from VCard AlternativeView to the output file.
- DisplayAsOutlook - display From header.
- RenderTaskFields - writes specific Task fields to the output file.
- None - No setting specified.

The following code snippet shows you how to convert EML files to MHTML with optional settings.

```java
// For complete examples and data files, please go to https://github.com/aspose-email/Aspose.Email-for-Java
MailMessage eml = MailMessage.load(dataDir + "test.eml");
// Save as Mht with header
MhtSaveOptions mhtSaveOptions = new MhtSaveOptions();
int iSaveOptions = MhtFormatOptions.WriteHeader | MhtFormatOptions.HideExtraPrintHeader;
mhtSaveOptions.setMhtFormatOptions(iSaveOptions);
eml.save(dataDir + "ConvertingToMHTMLWithOptionalSettings_out.mht", mhtSaveOptions);
```

### Save Email Message as HTML with Relative Path to Resources {#save-email-message-as-html-with-relative-path-to-resources}

When exporting email messages to HTML format, it is possible to choose to save email resources with relative paths. This feature provides more flexibility in how resources are linked in the output HTML file, making it easier to share and display saved emails on different systems. The <a href="https://reference.aspose.com/email/java/com.aspose.email/htmlsaveoptions/#getUseRelativePathToResources--" target="_blank" rel="nofollow noopener noreferrer">HtmlSaveOptions.UseRelativePathToResources</a> property provides ability to save resources with relative paths. Default property value is false (resources are saved with absolute paths). When set to true, resources are saved with relative paths. HTML files with relative paths are more portable and can be viewed correctly regardless of the hosting environment file structure. You can choose between absolute and relative paths depending on the requirements. You can define custom paths for resources using the <a href="https://reference.aspose.com/email/java/com.aspose.email/resourcehtmlrenderinghandler/" target="_blank" rel="nofollow noopener noreferrer">ResourceHtmlRenderingHandler</a> event.

**Save with Default Relative Path to Resources**

```java
MapiMessage msg = MapiMessage.load(sourceFileName);

HtmlSaveOptions htmlSaveOptions = new HtmlSaveOptions();
htmlSaveOptions.setResourceRenderingMode(ResourceRenderingMode.SaveToFile);
htmlSaveOptions.setUseRelativePathToResources(true);

msg.save("target.html", htmlSaveOptions);
```

In this case, resources will be saved in the \[html file name].files folder, in the same path as the .html file and the HTML will reference the resources via relative paths.

**Save with Absolute Path to Resources**

```java
MapiMessage msg = MapiMessage.load(sourceFileName);

HtmlSaveOptions htmlSaveOptions = new HtmlSaveOptions();
htmlSaveOptions.setResourceRenderingMode(ResourceRenderingMode.SaveToFile);
htmlSaveOptions.setUseRelativePathToResources(false);

msg.save("target.html", htmlSaveOptions);
```

As in the first case, resources will be saved in the \[html file name].files folder by default, but the HTML will reference resources using absolute paths.

**Custom Relative Path using ResourceHtmlRenderingHandler Event**

```java
MapiMessage msg = MapiMessage.load(sourceFileName);

HtmlSaveOptions htmlSaveOptions = new HtmlSaveOptions();
htmlSaveOptions.setResourceRenderingMode(ResourceRenderingMode.SaveToFile);
htmlSaveOptions.setUseRelativePathToResources(false);

htmlSaveOptions.setResourceHtmlRenderingHandler(new ResourceHtmlRenderingHandler() {
    @Override
    public void invoke(Object sender, ResourceHtmlRenderingEventArgs args) {
        if (sender instanceof AttachmentBase) {
            AttachmentBase attachment = (AttachmentBase) sender;
            // Since UseRelativePathToResources = true, you should assign a relative path to the PathToResourceFile property.
            args.setPathToResourceFile("images\\" + attachment.getContentType().getName());
        }
    }
});

msg.save(targetPath + "A Day in the Park.html", htmlSaveOptions);
```

By using the <a href="https://reference.aspose.com/email/java/com.aspose.email/resourcehtmlrenderinghandler/" target="_blank" rel="nofollow noopener noreferrer">ResourceHtmlRenderingHandler</a> event, you can set custom relative or absolute paths for resources. When customizing paths with the <a href="https://reference.aspose.com/email/java/com.aspose.email/resourcehtmlrenderinghandler/" target="_blank" rel="nofollow noopener noreferrer">ResourceHtmlRenderingHandler</a> event handler, and since <a href="https://reference.aspose.com/email/java/com.aspose.email/htmlsaveoptions/#getUseRelativePathToResources--" target="_blank" rel="nofollow noopener noreferrer">UseRelativePathToResources</a> is set to true, you should assign a relative path to the <a href="https://reference.aspose.com/email/java/com.aspose.email/resourcehtmlrenderingeventargs/#setPathToResourceFile-java.lang.String-" target="_blank" rel="nofollow noopener noreferrer">PathToResourceFile</a> property to ensure correct referencing.

#### Preserve Custom Icons in a Message while Converting to HTML {#preserve-custom-icons-in-a-message-while-converting-to-html}

Sometimes, the message contains in-line attachments, that are displayed as icon images in a message body. Such messages may create problems while converting them to HTML, since the icon images are lost. This is because attachment's icons are not held directly in the message.

The user of the Aspose.Email can customize the icons for attachments when converting the message to HTML. For that, the <a href="https://reference.aspose.com/email/java/com.aspose.email/htmlsaveoptions/#HtmlSaveOptions--" target="_blank" rel="nofollow noopener noreferrer">HtmlSaveOptions.ResourceHtmlRendering</a> event is used to customize the rendering of resource files (such as attachments) when saving an email message as an HTML file. In the code sample below, the event handler is used to dynamically set the path to resource files (icons) based on the content type of the attachment. This allows for customized rendering of resources in the HTML output based on their file type.

```java

 HtmlSaveOptions options = new HtmlSaveOptions();

options.setResourceHtmlRenderingHandler(new ResourceHtmlRenderingHandler() {

   @Override

   public void invoke(Object sender, ResourceHtmlRenderingEventArgs e) {

        AttachmentBase attachment = (AttachmentBase) sender;

        e.setCaption(attachment.getContentType().getName());

       if (attachment.getContentType().getName().endsWith(".pdf")) {

            e.setPathToResourceFile("pdf_icon.png");

       } else if (attachment.getContentType().getName().endsWith(".docx")) {

            e.setPathToResourceFile("word_icon.jpg");

       } else if (attachment.getContentType().getName().endsWith(".jpg")) {

            e.setPathToResourceFile("jpeg_icon.png");

       } else {

            e.setPathToResourceFile("not_found_icon.png");

       }

   }

});

options.setResourceRenderingMode(ResourceRenderingMode.SubstituteFromFile);

String fileName = "message.msg";

MailMessage mailMessage = MailMessage.load(fileName);

mailMessage.save("fileName.html", options);
```

#### Set Time and Timezone when Saving EML as HTML {#set-time-and-timezone-when-saving-eml-as-html}

Aspose.Email users can set the time and timezone display formats in <a href="https://reference.aspose.com/email/java/com.aspose.email/htmlsaveoptions/" target="_blank" rel="nofollow noopener noreferrer">HtmlSaveOptions</a>. The <a href="https://reference.aspose.com/email/java/com.aspose.email/headersformattingoptions/" target="_blank" rel="nofollow noopener noreferrer">HeadersFormattingOptions</a> class allows to specify headers formatting options when saving MailMessage to Mhtml or Html format. The following methods of the <a href="https://reference.aspose.com/email/java/com.aspose.email/htmlformatoptions/" target="_blank" rel="nofollow noopener noreferrer">HtmlFormatOptions</a> class specify the fields to be displayed in the output file:

- <a href="https://reference.aspose.com/email/java/com.aspose.email/htmlformatoptions/#RenderCalendarEvent" target="_blank" rel="nofollow noopener noreferrer">RenderCalendarEvent</a> - Indicates that text from calendar event should be written in output mhtml.
- <a href="https://reference.aspose.com/email/java/com.aspose.email/htmlformatoptions/#RenderVCardInfo" target="_blank" rel="nofollow noopener noreferrer">RenderVCardInfo</a> - Indicates that text from VCard AlternativeView should be written in output html.

The following code sample shows how to set the time and timezone when saving EML to HTML:

```java
MailMessage msg = MailMessage.load("fileName");
HtmlSaveOptions options = new HtmlSaveOptions();
options.setHtmlFormatOptions(HtmlFormatOptions.WriteHeader);
options.getFormatTemplates().set_Item("DateTime", "MM d yyyy HH:mm tt");
```
