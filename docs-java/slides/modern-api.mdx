## **Introduction**

Historically, Aspose Slides has a dependency on java.awt and has in the public API the following classes from there:

- <a href="https://docs.oracle.com/javase/8/docs/api/java/awt/Graphics2D.html" target="_blank" rel="nofollow noopener noreferrer">Graphics2D</a>
- <a href="https://docs.oracle.com/javase/8/docs/api/java/awt/image/BufferedImage.html" target="_blank" rel="nofollow noopener noreferrer">BufferedImage</a>

As of version 24.4, this public API is declared deprecated.

In order to get rid of dependencies on these classes, we added the so-called "Modern API" - i.e. the API that should be used instead of the deprecated one, whose signatures contain dependencies on <a href="https://docs.oracle.com/javase/8/docs/api/java/awt/image/BufferedImage.html" target="_blank" rel="nofollow noopener noreferrer">BufferedImage</a>. <a href="https://docs.oracle.com/javase/8/docs/api/java/awt/Graphics2D.html" target="_blank" rel="nofollow noopener noreferrer">Graphics2D</a> is declared deprecated and its support is removed from the public Slides API.

In current versions, treat the public API that depends on java.awt types as legacy/deprecated. Use the Modern API for new code and when migrating existing image-processing workflows.

## **Modern API**

Added the following classes and enums to the public API:

- <a href="https://reference.aspose.com/slides/java/com.aspose.slides/iimage/" target="_blank" rel="nofollow noopener noreferrer">IImage</a> - represents the raster or vector image.
- <a href="https://reference.aspose.com/slides/java/com.aspose.slides/imageformat/" target="_blank" rel="nofollow noopener noreferrer">ImageFormat</a> - represents the file format of the image.
- <a href="https://reference.aspose.com/slides/java/com.aspose.slides/images/" target="_blank" rel="nofollow noopener noreferrer">Images</a> - methods to instantiate and work with the <a href="https://reference.aspose.com/slides/java/com.aspose.slides/iimage/" target="_blank" rel="nofollow noopener noreferrer">IImage</a> interface.

Please note that <a href="https://reference.aspose.com/slides/java/com.aspose.slides/iimage/" target="_blank" rel="nofollow noopener noreferrer">IImage</a> is disposable and its use should be followed by a `dispose()` call or another convenient disposal pattern.

Use `getImage` to render a single slide or shape. Use `getImages` to render several presentation slides. Use <a href="https://reference.aspose.com/slides/java/com.aspose.slides/images/" target="_blank" rel="nofollow noopener noreferrer">Images</a> methods to load images, `addImage` with <a href="https://reference.aspose.com/slides/java/com.aspose.slides/iimage/" target="_blank" rel="nofollow noopener noreferrer">IImage</a> to add them to a presentation, and `replaceImage` with <a href="https://reference.aspose.com/slides/java/com.aspose.slides/iimage/" target="_blank" rel="nofollow noopener noreferrer">IImage</a> to update an existing presentation image.

A typical scenario of using the new API may look as follows:

```java
import com.aspose.slides.*;
import java.awt.Dimension;

Presentation pres = new Presentation();
try {
    IPPImage ppImage;
    // instantiate a disposable instance of IImage from the file on the disk.
    IImage image = Images.fromFile("image.png");
    try {
        // create a PowerPoint image by adding an instance of IImage to the presentation's images.
        ppImage = pres.getImages().addImage(image);
    } finally {
        if (image != null) image.dispose();
    }

    // add a picture shape on the slide #1
    pres.getSlides().get_Item(0).getShapes().addPictureFrame(ShapeType.Rectangle, 10, 10, 100, 100, ppImage);

    // get an instance of the IImage representing slide #1.
    IImage slideImage = pres.getSlides().get_Item(0).getImage(new Dimension(1920, 1080));
    try {
        // save the image on the disk.
        slideImage.save("slide1.jpeg", ImageFormat.Jpeg);
    } finally {
        if (slideImage != null) slideImage.dispose();
    }
} finally {
    if (pres != null) pres.dispose();
}
```

## **Replacing Old Code with Modern API**

In general, you will need to replace calls that use <a href="https://docs.oracle.com/javase/8/docs/api/java/awt/image/BufferedImage.html" target="_blank" rel="nofollow noopener noreferrer">BufferedImage</a> and ImageIO with the new methods that use <a href="https://reference.aspose.com/slides/java/com.aspose.slides/iimage/" target="_blank" rel="nofollow noopener noreferrer">IImage</a>.

Legacy/deprecated API:

```java
import java.awt.Dimension;
import java.awt.image.BufferedImage;
import java.io.File;
import java.io.IOException;
import javax.imageio.ImageIO;

BufferedImage slideImage = pres.getSlides().get_Item(0).getThumbnail(new Dimension(1920, 1080));
try {
    ImageIO.write(slideImage, "PNG", new File("image.png"));
} catch (IOException e) {
    e.printStackTrace();
}
```

Modern API:

```java
import com.aspose.slides.*;
import java.awt.Dimension;

Presentation pres = new Presentation("pres.pptx");
try {
    IImage slideImage = pres.getSlides().get_Item(0).getImage(new Dimension(1920, 1080));
    try {
        slideImage.save("image.png", ImageFormat.Png);
    } finally {
        if (slideImage != null) slideImage.dispose();
    }
} finally {
    if (pres != null) pres.dispose();
}
```

### **Getting a Presentation Thumbnail**

Legacy/deprecated API:

```java
import com.aspose.slides.*;
import java.awt.Dimension;
import java.awt.image.BufferedImage;
import java.io.File;
import java.io.IOException;
import javax.imageio.ImageIO;

Presentation pres = new Presentation("pres.pptx");
try {
    BufferedImage[] bitmaps = pres.getThumbnails(new RenderingOptions(), new Dimension(1980, 1028));
    for (int index = 0; index < bitmaps.length; index++)
    {
        try 
        {
            BufferedImage thumbnail = bitmaps[index];
            ImageIO.write(thumbnail, "PNG", new File("slide" + index + ".png"));
        } 
        catch (IOException e) 
        {
            e.printStackTrace();
        }
    }
} finally {
    if (pres != null) pres.dispose();
}
```

Modern API:

```java
import com.aspose.slides.*;
import java.awt.Dimension;

Presentation pres = new Presentation("pres.pptx");
try {
    IImage[] images = pres.getImages(new RenderingOptions(), new Dimension(1980, 1028));
    try
    {
        for (int index = 0; index < images.length; index++)
        {
            IImage thumbnail = images[index];
            thumbnail.save("slide" + index + ".png", ImageFormat.Png);
        }
    }
    finally
    {
        for (IImage image : images)
        {
            image.dispose();
        }
    }
} finally {
    if (pres != null) pres.dispose();
}
```

## **FAQ**

### Why was <a href="https://docs.oracle.com/javase/8/docs/api/java/awt/Graphics2D.html" target="_blank" rel="nofollow noopener noreferrer">Graphics2D</a> dropped?

Support for <a href="https://docs.oracle.com/javase/8/docs/api/java/awt/Graphics2D.html" target="_blank" rel="nofollow noopener noreferrer">Graphics2D</a> is deprecated in the public API to unify work with rendering and images, eliminate ties to platform-specific dependencies, and switch to a cross-platform approach with <a href="https://reference.aspose.com/slides/java/com.aspose.slides/iimage/" target="_blank" rel="nofollow noopener noreferrer">IImage</a>. Use `getImage` or `getImages` instead of rendering to <a href="https://docs.oracle.com/javase/8/docs/api/java/awt/Graphics2D.html" target="_blank" rel="nofollow noopener noreferrer">Graphics2D</a>.

### What is the practical benefit of <a href="https://reference.aspose.com/slides/java/com.aspose.slides/iimage/" target="_blank" rel="nofollow noopener noreferrer">IImage</a> compared to <a href="https://docs.oracle.com/javase/8/docs/api/java/awt/image/BufferedImage.html" target="_blank" rel="nofollow noopener noreferrer">BufferedImage</a>?

<a href="https://reference.aspose.com/slides/java/com.aspose.slides/iimage/" target="_blank" rel="nofollow noopener noreferrer">IImage</a> unifies working with both raster and vector images and simplifies saving to various formats via <a href="https://reference.aspose.com/slides/java/com.aspose.slides/imageformat/" target="_blank" rel="nofollow noopener noreferrer">ImageFormat</a>.

### Will the Modern API affect the performance of generating thumbnails?

Switching from `getThumbnail` to `getImage` does not worsen scenarios: the new methods provide the same capabilities for producing images with options and sizes, while retaining support for rendering options. The specific gain or drop depends on the scenario, but functionally the replacements are equivalent.
