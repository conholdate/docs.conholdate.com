**Aspose.TeX for Java** provides features for converting LaTeX files to a number of raster image formats.

## How to convert LaTeX to PNG {#how-to-convert-latex-to-png}

Let's take a closer look at the Java code providing the simplest way to convert LaTeX to PNG format.

Set `inputFile` to the full path of your LaTeX file, such as `hello-world.ltx`, and `outputDirectory` to an existing output folder. Import the classes from `com.aspose.tex` and `com.aspose.tex.rendering` used in each snippet. The calling method must handle or declare exceptions. Apply a license as described in the [licensing guide](/java/tex/licensing/) to avoid evaluation restrictions. The examples select noninteractive processing and close output resources. The PNG example sets the resolution to 300 DPI. For the single-page input `hello-world.ltx`, the automatic output files are `hello-world.png`, `hello-world.jpg`, `hello-world.tif`, `hello-world.bmp`, or `hello-world.svg`, depending on the selected format.

```java
// Convert LaTeX to PNG.
// inputFile is the full input path; outputDirectory is an existing output folder.
TeXOptions options = TeXOptions.consoleAppOptions(TeXConfig.objectLaTeX());
OutputFileSystemDirectory output = new OutputFileSystemDirectory(outputDirectory);
options.setOutputWorkingDirectory(output);
PngSaveOptions saveOptions = new PngSaveOptions();
saveOptions.setResolution(300);
options.setSaveOptions(saveOptions);
options.setInteraction(Interaction.NonstopMode);

ImageDevice device = new ImageDevice();
TeXJobResult result;
try {
    result = new TeXJob(inputFile, device, options).run();
} finally {
    device.dispose();
    output.close();
}
```

So, the first thing we need to do (sometimes not the very first, as we will find out later) is to create an instance of the <a href="https://reference.aspose.com/tex/java/com.aspose.tex/texoptions/" target="_blank" rel="nofollow noopener noreferrer">TeXOptions</a> class. The only static method that does this is <a href="https://reference.aspose.com/tex/java/com.aspose.tex/texoptions/#consoleAppOptions-com.aspose.tex.TeXConfig-" target="_blank" rel="nofollow noopener noreferrer">consoleAppOptions()</a>, so let's not bother with the meaning of its name. The method takes the <a href="https://reference.aspose.com/tex/java/com.aspose.tex/texconfig/#objectLaTeX--" target="_blank" rel="nofollow noopener noreferrer">objectLaTeX() instance</a> of the <a href="https://reference.aspose.com/tex/java/com.aspose.tex/texconfig/" target="_blank" rel="nofollow noopener noreferrer">TeXConfig</a> class, which is exactly suitable for converting a [LaTeX file](/net/tex/latex-io/#latex-file). This configuration instructs the Object TeX engine to load the Object LaTeX format and to be ready to accept the LaTeX file. Object LaTeX format is actually just the [LaTeX](/net/tex/what-is-latex/) format, except that it uses [Object TeX](/net/tex/aspose-tex-and-object-tex/#object-tex) specific primitives to set up the page metrics.

The first of the required options is <a href="https://reference.aspose.com/tex/java/com.aspose.tex/texoptions/#getOutputWorkingDirectory--" target="_blank" rel="nofollow noopener noreferrer">OutputWorkingDirectory</a> which defines the space, or area, where the TeX output will be written. [Here](/java/tex/aspose-tex-output/) are the details about the output directory concept in **Aspose.TeX for Java**. In this example, we use the <a href="https://reference.aspose.com/tex/java/com.aspose.tex/outputfilesystemdirectory/" target="_blank" rel="nofollow noopener noreferrer">OutputFileSystemDirectory</a> class, which allows us to write the output to the specified directory, or folder.

The second option is a <a href="https://reference.aspose.com/tex/java/com.aspose.tex.rendering/saveoptions/" target="_blank" rel="nofollow noopener noreferrer">SaveOptions</a> class instance which will control the transformation of the [object model](/net/tex/aspose-tex-and-object-tex/#why-the-new-tex-is-object) to the target format. Since we are converting LaTeX to PNG, it's the <a href="https://reference.aspose.com/tex/java/com.aspose.tex.rendering/pngsaveoptions/" target="_blank" rel="nofollow noopener noreferrer">PngSaveOptions</a> class instance, which allows us to specify the resolution of the output images.

Next, we need to create an instance of the <a href="https://reference.aspose.com/tex/java/com.aspose.tex/texjob/" target="_blank" rel="nofollow noopener noreferrer">TeXJob</a> class. Wanting to convert a LaTeX file stored in the file system, we use <a href="https://reference.aspose.com/tex/java/com.aspose.tex/texjob/#TeXJob-java.lang.String-com.aspose.tex.rendering.Device-com.aspose.tex.TeXOptions-" target="_blank" rel="nofollow noopener noreferrer">this</a> version of the constructor. We should specify the full path to the file. Otherwise, the engine will look for it in the current directory (which is defined <a href="https://docs.oracle.com/javase/7/docs/api/java/io/File.html" target="_blank" rel="nofollow noopener noreferrer">here</a>) and most likely will not find it. Nevertheless, we may omit the extension if our file has the *.tex* one. The engine will append it automatically. The second argument of the constructor is a <a href="https://reference.aspose.com/tex/java/com.aspose.tex.rendering/device/" target="_blank" rel="nofollow noopener noreferrer">Device</a> class instance. Since we are converting LaTeX to PNG, it's an <a href="https://reference.aspose.com/tex/java/com.aspose.tex.rendering/imagedevice/" target="_blank" rel="nofollow noopener noreferrer">ImageDevice</a> class (which is common to all supported image formats) instance. As the last argument, we pass the recently prepared conversion options.

All that we have to do now is to <a href="https://reference.aspose.com/tex/java/com.aspose.tex/texjob/#run--" target="_blank" rel="nofollow noopener noreferrer">run</a> the job.

Regardless of whether the run was successful or not, the first result that we'll see will be the terminal output. In case of success, it looks something like this:

```java
This is ObjectTeX, Version 3.1415926-1.0 (Aspose.TeX 21.8)
entering extended mode

(<input_directory>\hello-world.ltx
LaTeX2e <2011/06/27>
(article.cls
Document Class: article 2007/10/19 v1.4h Standard LaTeX document class
(size10.clo))
No file hello-world.aux.
[1]
(<output_directory>\hello-world.aux) )
Output written on hello-world.png (1 page).
Transcript written on hello-world.log.
```

We will find other products of the engine's run in the folder that we specified as the output directory. Those will be the transcript (.log) file and, **Voila!**, the main output PNG image file(s).

## An alternative way to write the main output PNG file(s) {#an-alternative-way-to-write-the-main-output-png-files}

There is another way to get image data as an array of byte arrays, each array in the second dimension represents image data for a separate page.

```java
// Convert LaTeX to PNG and save each page from the returned byte arrays.
// inputFile is the full input path; outputDirectory is an existing output folder.
TeXOptions options = TeXOptions.consoleAppOptions(TeXConfig.objectLaTeX());
OutputFileSystemDirectory output = new OutputFileSystemDirectory(outputDirectory);
options.setOutputWorkingDirectory(output);
PngSaveOptions saveOptions = new PngSaveOptions();
saveOptions.deviceWritesImages(false);
options.setSaveOptions(saveOptions);
options.setInteraction(Interaction.NonstopMode);

ImageDevice device = new ImageDevice();
TeXJobResult result;
try {
    result = new TeXJob(inputFile, device, options).run();
    byte[][] pages = device.getResult();
    for (int i = 0; i < pages.length; i++) {
        Files.write(Paths.get(outputDirectory, "page-" + (i + 1) + ".png"), pages[i]);
    }
} finally {
    device.dispose();
    output.close();
}
```

<a href="https://gist.github.com/aspose-com-gists/a30f406f6b8ace1b7d15c68a1df75c6d#file-example-convertlatextopng-alternative-java" target="_blank" rel="nofollow noopener noreferrer">Example-ConvertLaTeXToPNG-Alternative.java</a> hosted with ❤ by <a href="https://github.com/" target="_blank" rel="nofollow noopener noreferrer">GitHub</a>

The manual example also requires `java.nio.file.Files` and `java.nio.file.Paths`. It saves page data from `ImageDevice.getResult()` as `page-1.png`, `page-2.png`, and so on. Because it sets `deviceWritesImages(false)`, automatic PNG output is disabled and the manually saved pages are not duplicated in the output directory. This differs from [PDF stream output](/java/tex/latex-to-pdf/#an-alternative-way-to-write-the-main-output-pdf-file), where the stream defines the destination of a single PDF document.

## About input options {#about-input-options}

In case our main input file requires dependencies, for example, packages, that are not included in the basic LaTeX system and supported packages, we MUST set the <a href="https://reference.aspose.com/tex/java/com.aspose.tex/texoptions/#getRequiredInputDirectory--" target="_blank" rel="nofollow noopener noreferrer">RequiredInputDirectory</a> option the similar way we set the <a href="https://reference.aspose.com/tex/java/com.aspose.tex/texoptions/#getOutputWorkingDirectory--" target="_blank" rel="nofollow noopener noreferrer">OutputWorkingDirectory</a> option and put the dependencies in that directory. Dependencies may be arbitrarily organized in subdirectories. In case we have our own files to include along the typesetting process, say external graphics files, we MUST also set the <a href="https://reference.aspose.com/tex/java/com.aspose.tex/texoptions/#getInputWorkingDirectory--" target="_blank" rel="nofollow noopener noreferrer">InputWorkingDirectory</a> using the path to the location where those files are collected. We may also place the main input file somewhere inside the input directory and pass the relative path to the `TeXJob` constructor (or specify no path at all if the main input file is in the root). [Here](/java/tex/aspose-tex-input/) are the details about the input directory concept in **Aspose.TeX for Java** and provided implementations.

Other TeX job options are discussed [here](/java/tex/other-options/).

## How to convert LaTeX to SVG {#how-to-convert-latex-to-svg}

And yet another supported target format is <a href="https://en.wikipedia.org/wiki/SVG" target="_blank" rel="nofollow noopener noreferrer">**SVG**</a>. **Scalable Vector Graphics (SVG)** is an XML-based vector image format for defining two-dimensional graphics, having support for interactivity and animation.

**SVG** images are defined in a vector graphics format and stored in XML text files. This means that **SVG** images can be scaled in size without loss of quality, and **SVG** files can be searched, indexed, scripted, and compressed. The XML text files can be created and edited with text editors or vector graphics editors. Thay are rendered by the most-used web browsers.

Also, there is the <a href="https://products.aspose.com/svg/" target="_blank" rel="nofollow noopener noreferrer">**Aspose.SVG**</a> library that has various features based on the **SVG** format. These include creating, loading, editing and converting **SVG** documents.

The conversion to SVG is just as simple as the [conversion to raster image formats](/java/tex/latex-to-image/), except that in addition to the <a href="https://reference.aspose.com/tex/java/com.aspose.tex/texoptions/#getSaveOptions--" target="_blank" rel="nofollow noopener noreferrer">SaveOptions</a>, we have to change the device to an instance of the <a href="https://reference.aspose.com/tex/java/com.aspose.tex.rendering/svgdevice/" target="_blank" rel="nofollow noopener noreferrer">SvgDevice</a> class.

```java
// Convert LaTeX to SVG.

OutputFileSystemDirectory output = new OutputFileSystemDirectory(outputDirectory);

options.setInteraction(Interaction.NonstopMode);

SvgDevice device = new SvgDevice();

try {
    result = new TeXJob(inputFile, device, options).run();
} finally {

```
