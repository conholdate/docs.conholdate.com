This article describes how to detect, analyze, and process bounce messages (delivery failure notifications).

The `Aspose.Email.Bounce` namespace has classes and methods to detect and analyze bounce messages. The main features include:

- Detecting whether an email message is a bounce message
- Extracting bounce details (recipient, status code, reason, action)
- Accessing the original message from bounce notifications
- Handling different types of Delivery Status Notification (DSN) actions

## Checking if a Message is a Bounce {#checking-if-a-message-is-a-bounce}

To determine whether an email message is a bounce message, use the `CheckBounced()` method. This method returns a `BounceResult` object that contains information about the bounce.

:::info
The `CheckBounced()` method automatically detects bounce messages and extracts relevant information.
:::

```csharp
using Aspose.Email;
using Aspose.Email.Bounce;

// Load a message
MailMessage message = MailMessage.Load("message.eml");

// Check if it's a bounce
BounceResult result = message.CheckBounced();

if (result.IsBounced)
{
    Console.WriteLine($"This is a bounce message!");
}
```

## Extracting Bounce Details {#extracting-bounce-details}

Once a bounce is detected, you can extract detailed information about the delivery failure:

- **Recipient**: The original recipient address
- **Status**: DSN status code (e.g., "5.1.1", "4.2.2")
- **Reason**: Human-readable diagnostic code
- **Action**: The delivery action performed (Failed, Delayed, etc.)

```csharp
if (result.IsBounced)
{
    Console.WriteLine($"Failed to: {result.Recipient}");
    Console.WriteLine($"Status: {result.Status}");
    Console.WriteLine($"Reason: {result.Reason}");
    Console.WriteLine($"Action: {result.Action}");
}
```

## Accessing the Original Message {#accessing-the-original-message}

Bounce notifications may include the original message that was returned. You can access it through the `OriginalMessage` property of `BounceResult`:

```csharp
if (result.OriginalMessage != null)
{
    MailMessage original = result.OriginalMessage;
    Console.WriteLine($"Original subject: {original.Subject}");
    Console.WriteLine($"Original from: {original.From.Address}");
}
```

## Processing Multiple Bounce Messages {#processing-multiple-bounce-messages}

To process multiple bounce messages from a directory:

```csharp
foreach (string file in Directory.GetFiles("bounces", "*.eml"))
{
    MailMessage message = MailMessage.Load(file);
    BounceResult result = message.CheckBounced();

    if (result.IsBounced)
    {
        // Process each bounce
        Console.WriteLine($"Bounce for: {result.Recipient}");
    }
}
```

## Common Bounce Handling Patterns {#common-bounce-handling-patterns}

### Removing Invalid Recipients from Mailing List {#removing-invalid-recipients-from-mailing-list}

When a bounce has a `Failed` action, the recipient address should be removed from your mailing list:

```csharp
if (result.IsBounced && result.Action == DSNAction.Failed)
{
    string failedRecipient = result.Recipient;
    
	// Remove from your mailing list
}
```

### Logging Bounce Information {#logging-bounce-information}

For compliance and analytics, you may want to log bounce information:

```csharp
var bounceLog = new BounceLogEntry
{
    Recipient = result.Recipient,
    StatusCode = result.Status,
    Reason = result.Reason,
    Action = result.Action,
    BounceDate = DateTime.UtcNow
};

// Save to database or file
```

### Retrying Temporary Failures {#retrying-temporary-failures}

For temporary failures (`Delayed` action), add the recipient to a retry queue:

```csharp
if (result.Action == DSNAction.Delayed)
{
    // Add to retry queue
}
```

### Extracting and Saving the Original Message {#extracting-and-saving-the-original-message}

When the original message is included in the bounce notification, you may want to save it:

```csharp
if (result.OriginalMessage != null)
{
    string originalFileName = $"original_{Guid.NewGuid()}.eml";
    result.OriginalMessage.Save(originalFileName, SaveOptions.DefaultEml);
}
```

## IMAP Integration {#imap-integration}

When using IMAP, you can automatically detect and handle bounce messages:

```csharp
using (ImapClient client = new ImapClient("imap.domain.com", "user", "pass"))
{
    client.SelectFolder(ImapFolderInfo.InBox);

    ImapMessageInfoCollection messages = client.ListMessages();

    foreach (ImapMessageInfo info in messages)
    {
        MailMessage message = client.FetchMessage(info.UniqueId);
        BounceResult result = message.CheckBounced();

        if (result.IsBounced)
        {
            // Move bounce to special folder
            client.MoveMessage(info.UniqueId, "Bounced");
        }
    }
}
```

## Troubleshooting {#troubleshooting}

### Empty Recipient Field {#empty-recipient-field}

Some bounce messages may not populate the `Recipient` field. In such cases, check for the `X-Failed-Recipients` header:

```csharp
if (string.IsNullOrEmpty(result.Recipient))
{
    string failedRecipients = message.Headers["X-Failed-Recipients"];
    if (!string.IsNullOrEmpty(failedRecipients))
    {
        // Process failed recipients from header
    }
}
```

### Missing Original Message {#missing-original-message}

Many bounce notifications do not include the original message. Always check if it's available:

```csharp
if (result.OriginalMessage == null)
{
    Console.WriteLine("Original message not included in bounce notification");
    // Extract recipient from headers or other sources
}
```

## Best Practices {#best-practices}

1. **Regular Processing**: Process bounce messages regularly to keep your mailing lists clean
2. **Log Everything**: Maintain logs for compliance and troubleshooting
3. **Respect Temporary Failures**: Implement retry logic for `Delayed` bounces
4. **Immediate Removal**: Remove recipients immediately for `Failed` bounces
5. **Verify Headers**: Check `X-Failed-Recipients` header when `Recipient` is empty
6. **Use Dedicated Folder**: In IMAP, move bounces to a dedicated folder for easier processing
