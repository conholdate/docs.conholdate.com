<a href="https://products.groupdocs.com/viewer/net" target="_blank" rel="nofollow noopener noreferrer">GroupDocs.Viewer for .NET</a> allows to view the list of content of archive files and represent it in HTML, PDF, PNG and JPEG formats. It also allows to extract any arbitrary file from the archive. It does not require to use any third-party file archiver and/or compression software to display archive file contents within a .NET application (web or desktop).

Displaying a list of content of  archive files in GroupDocs.Viewer is similar to other formats. You need to create an instance of the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer" target="_blank" rel="nofollow noopener noreferrer">`Viewer`</a> class, and specify an archive document in its constructor <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer/viewer/#constructor_12" target="_blank" rel="nofollow noopener noreferrer">as a path to the file or a byte stream</a>. Optionally, you can pass a load options, where a password for opening an encoded archive document can be specified. Then you need to select a desired output format, in which the archive content will be represented: HTML (<a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/htmlviewoptions/" target="_blank" rel="nofollow noopener noreferrer">`HtmlViewOptions`</a>), PDF (<a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/pdfviewoptions/" target="_blank" rel="nofollow noopener noreferrer">`PdfViewOptions`</a>), PNG (<a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/pngviewoptions/" target="_blank" rel="nofollow noopener noreferrer">`PngViewOptions`</a>), or JPEG (<a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/jpgviewoptions/" target="_blank" rel="nofollow noopener noreferrer">`JpgViewOptions`</a>). Finally, call the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer/view/#view" target="_blank" rel="nofollow noopener noreferrer">`Viewer.View()`</a> instance method to obtain a result.

GroupDocs.Viewer for .NET had support of archive formats from its very beginning. However, starting from the <a href="https://releases.groupdocs.com/viewer/net/release-notes/2024/groupdocs-viewer-for-net-24-10-release-notes/#new-archive-converter" target="_blank" rel="nofollow noopener noreferrer">version 24.10</a> the archive processing module was completely reworked. In short, the way of displaying a list of entries from the archive was completely changed, as well as a final representation. Also, the performance was drastically improved. The public options are left the same, the only change in a public API is an `ItemsPerPage` property of <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/archiveoptions/" target="_blank" rel="nofollow noopener noreferrer">`ArchiveOptions`</a> class, which now is marked as obsolete because it has no effect now. This article explains and displays the new archive processing module. If you're using the older versions of the GroupDocs.Viewer before the 24.10, the old version of this article can be found [here](/net/viewer/rendering-basics/render-archives/old-archive-rendering/).

## Supported archive and compressed file formats

GroupDocs.Viewer supports the following archive file formats:

* <a href="https://docs.fileformat.com/compression/7z" target="_blank" rel="nofollow noopener noreferrer">.7Z (7-Zip Compressed File)</a>
* <a href="https://docs.fileformat.com/compression/bz2" target="_blank" rel="nofollow noopener noreferrer">.BZ2 (Bzip2 Compressed File)</a>
* <a href="https://docs.fileformat.com/compression/gz" target="_blank" rel="nofollow noopener noreferrer">.GZ (Gnu Zipped Archive)</a>
* <a href="https://docs.fileformat.com/compression/rar" target="_blank" rel="nofollow noopener noreferrer">.RAR (WinRAR Compressed Archive)</a>
* <a href="https://docs.fileformat.com/compression/tar" target="_blank" rel="nofollow noopener noreferrer">.TAR (Consolidated Unix File Archive)</a>
* <a href="https://docs.fileformat.com/compression/tgz/" target="_blank" rel="nofollow noopener noreferrer">.TGZ / .TAR.GZ (Gzipped Tar File)</a>
* <a href="https://docs.fileformat.com/compression/xz/" target="_blank" rel="nofollow noopener noreferrer">.TXZ / .TAR.XZ (XZ Compressed Tar Archive)</a>
* <a href="https://docs.fileformat.com/compression/xz/" target="_blank" rel="nofollow noopener noreferrer">.XZ (XZ Compressed Archive)</a>
* <a href="https://docs.fileformat.com/compression/zip" target="_blank" rel="nofollow noopener noreferrer">.ZIP (Zipped File)</a>
* <a href="https://docs.fileformat.com/compression/zst/" target="_blank" rel="nofollow noopener noreferrer">.ZST / .TAR.ZST / .TZST (Zstandard)</a>
* <a href="https://docs.fileformat.com/compression/iso/" target="_blank" rel="nofollow noopener noreferrer">.ISO (Optical Disk Image ISO-9660)</a>
* <a href="https://docs.fileformat.com/compression/lzh/" target="_blank" rel="nofollow noopener noreferrer">.LHA / .LZH (archive file format)</a>
* <a href="https://en.wikipedia.org/wiki/Cabinet_(file_format" target="_blank" rel="nofollow noopener noreferrer">.CAB (Cabinet)</a>)
* <a href="https://docs.fileformat.com/disc-and-media/wim/" target="_blank" rel="nofollow noopener noreferrer">.WIM (Windows Imaging Format file)</a>

GroupDocs.Viewer can detect the archive file format automatically based on information in the file header.

## Loading archives

The 1st stage of document processing using the GroupDocs.Viewer is loading the document, and archives are not the exceptions. The simplest way is just to path the absolute or relative path of the archive file to the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer/#constructors" target="_blank" rel="nofollow noopener noreferrer">constructor</a> of the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer" target="_blank" rel="nofollow noopener noreferrer">`Viewer`</a> class. If an archive document is represented as a <a href="https://learn.microsoft.com/en-us/dotnet/api/system.io.stream" target="_blank" rel="nofollow noopener noreferrer">stream</a>, this stream can be specified in the overload of the constructor of the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer" target="_blank" rel="nofollow noopener noreferrer">`Viewer`</a> class as well, but make sure that this stream is readable (<a href="https://learn.microsoft.com/en-us/dotnet/api/system.io.stream.canread" target="_blank" rel="nofollow noopener noreferrer">`CanRead`</a>) and its position points to the correct place. Finally, if an archive is encoded and password-protected, and you know this password, it should be specified in the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/loadoptions/" target="_blank" rel="nofollow noopener noreferrer">`LoadOptions`</a>, or a <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.exceptions/groupdocsviewerexception/" target="_blank" rel="nofollow noopener noreferrer">`GroupDocsViewerException`</a> exception will be thrown instead.

Code sample below shows loading of two archive files into two Viewer instances: 1st file is specified by path, while 2nd - by a stream and with load options with password.

```csharp
// ...

    // view it

{
    // view it
}
```

## Representation

After the archive document is loaded and an instance of the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer" target="_blank" rel="nofollow noopener noreferrer">`Viewer`</a> class is created, it can be viewed using a <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer/view/#view" target="_blank" rel="nofollow noopener noreferrer">`Viewer.View()`</a> instance method. The "viewing" means displaying a list of content, stored within an archive, in desired output format. In general, this is a tree view, with folders and files, stored within these folders, sorted by default Windows-based order. This means that within one folder all subfolders are located first, sorted in <a href="https://en.wikipedia.org/wiki/Lexicographic_order" target="_blank" rel="nofollow noopener noreferrer">lexicographic order</a>, followed by files, also sorted in lexicographic order. However, the GroupDocs.Viewer implements not a "pure" lexicographic order, but a Windows-like "natural" order, where "file10.txt" is located _after_ the "file9.txt", but not before it.

Like for all supported formats, GroupDocs.Viewer supports 4 output formats for the representation: HTML, PDF, PNG, and JPEG.

### Render archive files as HTML

For saving the documents (including archives) to the HTML format the GroupDocs.Viewer provides a <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/htmlviewoptions/" target="_blank" rel="nofollow noopener noreferrer">`HtmlViewOptions`</a> class. There are two ways of creating an instance of this class: using either <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/htmlviewoptions/forembeddedresources/#forembeddedresources" target="_blank" rel="nofollow noopener noreferrer">`ForEmbeddedResources`</a> or <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/htmlviewoptions/forexternalresources/#forexternalresources" target="_blank" rel="nofollow noopener noreferrer">`ForExternalResources`</a>  static methods. Usually, when the 1st method (<a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/htmlviewoptions/forembeddedresources/#forembeddedresources" target="_blank" rel="nofollow noopener noreferrer">`ForEmbeddedResources`</a>) is used, all the resources (stylesheets, raster and vector images, and fonts) are stored inside the HTML markup in base64 encoding. When the 2nd method (<a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/htmlviewoptions/forexternalresources/#forexternalresources" target="_blank" rel="nofollow noopener noreferrer">`ForExternalResources`</a>) is used, the HTML markup has only references to the resources, which are stored externally.

In the context of archive documents and their rendering to HTML format, the resultant HTML document, which contains a list of files and folders within the archive, contains only stylesheet and icons, representing the folder or format of the particular file, as SVG vector graphics. When saved with embedded resources, the stylesheet is placed in the `STYLE` element in the `HTML` -> `HEAD` section, while SVG images are located inside this stylesheet in base64 encoding. When saved with external resources, the stylesheet is also placed in the `STYLE` element in the `HTML` -> `HEAD` section, but it contains the references to the SVG images that are stored separately. Need to mention that the HTML document contains only those SVG icons, which are necessary for displaying the formats of only those files, which are present in the archive. For example, if a particular archive does not contain the PDF file(s), there will be no SVG icon, which represents the PDF format, in the HTML resources.

GroupDocs.Viewer by default produces paged HTML results - input documents are splitted on pages, and each page is represented by a separate HTML document. There is also a <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/htmlviewoptions/rendertosinglepage/" target="_blank" rel="nofollow noopener noreferrer">`HtmlViewOptions.RenderToSinglePage`</a> boolean property (flag) in the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/htmlviewoptions/" target="_blank" rel="nofollow noopener noreferrer">`HtmlViewOptions`</a> class - when enabled, the GroupDocs.Viewer produces a single HTML document for the whole input document with all its pages. But archives are pageless in their nature - they store files and folders, and have no concept of "pages" like PDF documents, for example. That's why for any input archive document the GroupDocs.Viewer produces only a single output HTML document, and there is no matter which value has the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/htmlviewoptions/rendertosinglepage/" target="_blank" rel="nofollow noopener noreferrer">`RenderToSinglePage`</a> boolean flag.

Code example below shows rendering of the same input archive file to the two similar HTML documents: 1st with embedded resources, while 2nd - with external.


<Tabs groupId="RenderToHTML">


<TabItem value="c" label="C#" default>

```csharp
using GroupDocs.Viewer;
using GroupDocs.Viewer.Options;
// ...

HtmlViewOptions htmlEmbeddedOptions = HtmlViewOptions.ForEmbeddedResources("Embedded.html");
HtmlViewOptions htmlExternalOptions = HtmlViewOptions.ForExternalResources("External.html", "External_files/resource-{1}", "External_files/resource-{1}");

using (Viewer viewer = new Viewer("Archive.zip"))
{
    viewer.View(htmlEmbeddedOptions);
    viewer.View(htmlExternalOptions);
}
```

</TabItem>


<TabItem value="vb-net" label="VB.NET">

```vb
Imports GroupDocs.Viewer
Imports GroupDocs.Viewer.Options
' ...

Dim htmlEmbeddedOptions As HtmlViewOptions = HtmlViewOptions.ForEmbeddedResources("Embedded.html")
Dim htmlExternalOptions As HtmlViewOptions = HtmlViewOptions.ForExternalResources("External.html",
                        "External_files/resource-{1}", "External_files/resource-{1}")
Using viewer As New Viewer("Archive.zip")
    viewer.View(htmlEmbeddedOptions)
    viewer.View(htmlExternalOptions)
End Using
```

</TabItem>


</Tabs>


After running this code sample there will be created two HTML files in the output folder: "Embedded.html" and "External.html". And for the second one, there will be an additional resource folder "External_files" with SVG files inside. Main HTML document will be connected to these SVG icons through relative URIs "External_files/resource-g.svg", "External_files/resource-g1.svg", "External_files/resource-g2.svg", and so on.

### Render archive files as PDF

PDF format by its nature has pages, so the list of files and folders from the archive is paginated when rendering to PDF format. Number of pages in this output PDF cannot be specified and it depends only on the number of entries (files and folders) within the input archive.

<a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/pdfviewoptions/" target="_blank" rel="nofollow noopener noreferrer">`PdfViewOptions`</a> class must be used in order to render archive documents as PDF. All standard PDF-related operations like protecting, watermarking, reordering pages, tuning the images quality and size, can be applied to the output PDF document and are described in the article "[Render to PDF](/net/viewer/developer-guide/rendering-documents/rendering-to-pdf/)" and its sub-articles.

Code example below shows how to display the list of content of a specified archive file in PDF format.


<Tabs groupId="RenderToPDF">


<TabItem value="c" label="C#" default>

```csharp
using GroupDocs.Viewer;
using GroupDocs.Viewer.Options;
// ...

PdfViewOptions pdfOptions = new PdfViewOptions("Output.pdf");

using (Viewer viewer = new Viewer("Archive.zip"))
{
    viewer.View(pdfOptions);
}
```

</TabItem>


<TabItem value="vb-net" label="VB.NET">

```vb

Imports GroupDocs.Viewer.Options
```

### Render archive files as PNG and JPEG images

<a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/pngviewoptions/" target="_blank" rel="nofollow noopener noreferrer">`PngViewOptions`</a> and <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/jpgviewoptions/" target="_blank" rel="nofollow noopener noreferrer">`JpgViewOptions`</a> are responsible for saving archives to the PNG and JPEG raster image formats respectively. Like for the PDF, if the list of archive content cannot fit into the area of one image, it will be paginated and spread across multiple images.

Size of the output images will be calculated automatically based on the specific archive and its content, but it is possible to change the image size using the `Width`, `Height`, `MaxWidth`, and `MaxHeight` properties of the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/pngviewoptions/" target="_blank" rel="nofollow noopener noreferrer">`PngViewOptions`</a> and <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/jpgviewoptions/" target="_blank" rel="nofollow noopener noreferrer">`JpgViewOptions`</a> classes. An article "[Render to PNG or JPEG](/net/viewer/developer-guide/rendering-documents/rendering-to-png-or-jpeg/)" describes the tuning and post-processing of PNG and JPEG images in detail.

Because one PNG or JPEG image may contain only the one "page", for the archives with a significant number of folders and files there will be created several "pages" and thus produced several images. The constructors of the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/pngviewoptions/" target="_blank" rel="nofollow noopener noreferrer">`PngViewOptions`</a> and <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/jpgviewoptions/" target="_blank" rel="nofollow noopener noreferrer">`JpgViewOptions`</a> classes have overload, which allows to specify the template string for the output image files, and the GroupDocs.Viewer fills this template while saving with a sequential page number, which starts from "1".

Code example below shows rendering of the same input archive file to the two folders with images: one folder with "PNG" name contains page images in PNG format, while another with "JPEG" name - in JPEG format. For both formats the same amount of "page-images" will be generated.


<Tabs groupId="RenderToPNGJPEG">


<TabItem value="c" label="C#" default>

```csharp
using GroupDocs.Viewer;
using GroupDocs.Viewer.Options;
// ...

string pngFolderPath = Directory.CreateDirectory("PNG").FullName;
string jpegFolderPath = Directory.CreateDirectory("JPEG").FullName;

PngViewOptions pngOptions = new PngViewOptions(Path.Combine(pngFolderPath, "page-{0}.png"));
JpgViewOptions jpegOptions = new JpgViewOptions(Path.Combine(jpegFolderPath, "page-{0}.jpeg"));

using (Viewer viewer = new Viewer("Archive.zip"))
{
    viewer.View(pngOptions);
    viewer.View(jpegOptions);
}
```

</TabItem>


<TabItem value="vb-net" label="VB.NET">


## Tuning the Archive options

All 4 option classes - <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/htmlviewoptions/" target="_blank" rel="nofollow noopener noreferrer">`HtmlViewOptions`</a>, <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/pdfviewoptions/" target="_blank" rel="nofollow noopener noreferrer">`PdfViewOptions`</a>, <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/pngviewoptions/" target="_blank" rel="nofollow noopener noreferrer">`PngViewOptions`</a>, and <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/jpgviewoptions/" target="_blank" rel="nofollow noopener noreferrer">`JpgViewOptions`</a> - contain a <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/baseviewoptions/archiveoptions/" target="_blank" rel="nofollow noopener noreferrer">`ArchiveOptions`</a> property of the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/archiveoptions/" target="_blank" rel="nofollow noopener noreferrer">`ArchiveOptions`</a> type. This class has two properties, which allow users to modify a rendering of the list of archive content and are described below.

### Render a specific folder

By default the GroupDocs.Viewer displays all content inside the archive - all folders, subfolders and files with any nesting level till the end. However, in some cases it is required to display only a part of the list of archive content, for example, only content of some specific folder (including its subfolders), which is located in the given archive.

The <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/archiveoptions/folder/" target="_blank" rel="nofollow noopener noreferrer">`Folder`</a> property of a <a href="https://learn.microsoft.com/en-us/dotnet/api/system.string" target="_blank" rel="nofollow noopener noreferrer">`System.String`</a> type allows to do that. It obtains a folder name or relative path, which is located inside the given archive, and if the archive truly contains such a folder - only its content will be displayed. Otherwise, if no folder with such name or path was found in the archive, the whole archive content will be listed, as usual.

### Specify the archive document name

When GroupDocs.Viewer renders a list of archive content, it displays the archive document name at the top of the output document, as a root node for all folders and files inside an archive. When an archive document is specified as a file, its filename will be used as the archive document name. If an archive document is specified as a stream, a standard template name will be used.

With the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/archiveoptions/filename/" target="_blank" rel="nofollow noopener noreferrer">`FileName`</a> property of the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/archiveoptions/" target="_blank" rel="nofollow noopener noreferrer">`ArchiveOptions`</a> type it is possible to specify a displayed archive document name explicitly. Just create an instance of the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/filename/" target="_blank" rel="nofollow noopener noreferrer">`FileName`</a> class, specify desired archive name in its constructor, and assign this instance to the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/archiveoptions/filename/" target="_blank" rel="nofollow noopener noreferrer">`ArchiveOptions.FileName`</a> property.

### Example

Code sample below shows using the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/archiveoptions/folder/" target="_blank" rel="nofollow noopener noreferrer">`Folder`</a> property and <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/archiveoptions/filename/" target="_blank" rel="nofollow noopener noreferrer">`FileName`</a> property simultaneously for the same loaded archive file. Rendering is performed to the HTML format with embedded resources. It is assumed that a valid license is set.


<Tabs groupId="RenderToHTMLWithOptions">


<TabItem value="c" label="C#" default>

```csharp
using GroupDocs.Viewer;
using GroupDocs.Viewer.Options;
// ...

HtmlViewOptions htmlEmbeddedOptions = HtmlViewOptions.ForEmbeddedResources("FolderAndFileName.html");
htmlEmbeddedOptions.ArchiveOptions.Folder = "Markdown/Html";
htmlEmbeddedOptions.ArchiveOptions.FileName = new FileName("The '/Markdown/Html/' subfolder with all its content is displayed");

using (Viewer viewer = new Viewer("Archive.zip"))
{
    viewer.View(htmlEmbeddedOptions);
}
```

</TabItem>


<TabItem value="vb-net" label="VB.NET">

```vb
Imports GroupDocs.Viewer
Imports GroupDocs.Viewer.Options
' ...

Dim htmlEmbeddedOptions As HtmlViewOptions = HtmlViewOptions.ForEmbeddedResources("FolderAndFileName.html")
htmlEmbeddedOptions.ArchiveOptions.Folder = "Markdown/Html"
htmlEmbeddedOptions.ArchiveOptions.FileName =
    New FileName("The '/Markdown/Html/' subfolder with all its content is displayed")
```

## Extracting files from archives

While displaying a list of files and folders inside the archives is the main purpose of the GroupDocs.Viewer, it also allows to extract files from archives by their paths. In the GroupDocs.Viewer terminology the files inside archives are so-called "attachments".

In general, the extracting of specific attachment (file) from the given archive document is made in the next steps:

1. Create a <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer" target="_blank" rel="nofollow noopener noreferrer">`Viewer`</a> instance and load an archive document into its constructor. Use <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/loadoptions/" target="_blank" rel="nofollow noopener noreferrer">`LoadOptions`</a> if necessary.
2. Get a list of all attachments (files), stored inside an archive, by calling a <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer/getattachments/#getattachments_1" target="_blank" rel="nofollow noopener noreferrer">`Viewer.GetAttachments()`</a> parameterless method or its cancellable overload.
3. Find and select a particular <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.results/attachment/" target="_blank" rel="nofollow noopener noreferrer">`Attachment`</a> instance from the list, which you want to save.
4. Prepare a destination stream, into which you want to write the attachment. Make sure that this stream is not null and is writable (<a href="https://learn.microsoft.com/en-us/dotnet/api/system.io.stream.canwrite" target="_blank" rel="nofollow noopener noreferrer">`CanWrite`</a>) and seekable (<a href="https://learn.microsoft.com/en-us/dotnet/api/system.io.stream.canseek" target="_blank" rel="nofollow noopener noreferrer">`CanSeek`</a>).
5. Write the previously selected attachment to a prepared stream using the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer/saveattachment/#saveattachment" target="_blank" rel="nofollow noopener noreferrer">`Viewer.SaveAttachment(Attachment, System.IO.Stream)`</a> method or its cancellable overload.
6. Alternatively, if you want to extract and save all files from the given archive, just iterate over the list of attachments and call a <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer/saveattachment/#saveattachment" target="_blank" rel="nofollow noopener noreferrer">`Viewer.SaveAttachment()`</a> method for every attachment in a step.

Take note that extracting files from the archive and viewing its content are different operations, which are not dependent on each other - you may render the list of archive contents without extracting the files, and vice versa.

Also technically step #2 is not necessary - if you know the exact full name (this includes its relative path) of the desired file to extract, there is no need to get a list of all attachments, because the instance of the Attachment class can be created manually and passed directly to the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer/saveattachment/#saveattachment" target="_blank" rel="nofollow noopener noreferrer">`Viewer.SaveAttachment()`</a> method.

Code example below shows all the described operations with the attachments.

```csharp
using GroupDocs.Viewer.Options;
using GroupDocs.Viewer.Results;
// ...

    IList<Attachment> allAttachments = viewer.GetAttachments();

        Console.WriteLine("- {0} - {1} - {2} bytes", attachment.FilePath, attachment.FileType, attachment.Size);
		MemoryStream destination = new MemoryStream();

    Attachment oneAttachment = new Attachment("/Images/PNG/Watermark.png", "/Images/PNG/Watermark.png");
    using (FileStream extractedFile = File.Create("Watermark.png"))

    }
}
```

## Retrieving information about archives

Like for all other supported formats, the GroupDocs.Viewer supports getting the view info for the archive documents. This means that for the loaded archive a GroupDocs.Viewer can grab metadata like exact format, whether or not it is password-protected, list of folders inside archive, and a number of pages, which the GroupDcos.Viewer will produce in case when rendering to PDF, PNG, or JPEG will be selected. More info about retrieving the document information in general may be found in the corresponding [article](/net/viewer/developer-guide/retrieving-document-information/).

In order to retrieve metadata about specific archive, the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer/getviewinfo/#getviewinfo" target="_blank" rel="nofollow noopener noreferrer">`Viewer.GetViewInfo()`</a> method must be called. This method obtains an instance of <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/viewinfooptions/" target="_blank" rel="nofollow noopener noreferrer">`ViewInfoOptions`</a> class, which can be created from its own or from existing view options. The GroupDocs.Viewer constructs the metadata about the archive in accordance to the passed <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/viewinfooptions/" target="_blank" rel="nofollow noopener noreferrer">`ViewInfoOptions`</a> and its specific settings. For example, for the HTML-based info options the number of returned <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.results/viewinfo/pages/" target="_blank" rel="nofollow noopener noreferrer">`Pages`</a> is always "1" (because the displaying to the HTML format is pageless), while for the PDF, PNG and JPEG there will be some specific page number depending on count of files and folders within the archive.

In the context of archives the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer/getviewinfo/#getviewinfo" target="_blank" rel="nofollow noopener noreferrer">`Viewer.GetViewInfo()`</a> method returns an instance of the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.results/archiveviewinfo/" target="_blank" rel="nofollow noopener noreferrer">`ArchiveViewInfo`</a> class, which is the direct inheritor of the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.results/viewinfo/" target="_blank" rel="nofollow noopener noreferrer">`ViewInfo`</a> class. Except for the properties present in the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.results/viewinfo/" target="_blank" rel="nofollow noopener noreferrer">`ViewInfo`</a>, the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.results/archiveviewinfo/" target="_blank" rel="nofollow noopener noreferrer">`ArchiveViewInfo`</a> provides a <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.results/archiveviewinfo/folders/" target="_blank" rel="nofollow noopener noreferrer">`Folders`</a> property of `List&lt;System.String&gt;` type - it contains a list of all folders, stored in the archive. Please note that the GroupDocs.Viewer creates a new `List` with folder names every time when method <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer/getviewinfo/#getviewinfo" target="_blank" rel="nofollow noopener noreferrer">`Viewer.GetViewInfo()`</a> is called. Also <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.results/archiveviewinfo/folders/" target="_blank" rel="nofollow noopener noreferrer">`ArchiveViewInfo.Folders`</a> property does not take into account the value of the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/archiveoptions/folder/" target="_blank" rel="nofollow noopener noreferrer">`ArchiveOptions.Folder`</a> property, even if <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/viewinfooptions/" target="_blank" rel="nofollow noopener noreferrer">`ViewInfoOptions`</a> was created from such an option - so <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.results/archiveviewinfo/folders/" target="_blank" rel="nofollow noopener noreferrer">`ArchiveViewInfo.Folders`</a> always returns a complete list of folders inside the archive.

Concluding: to get the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.results/archiveviewinfo/" target="_blank" rel="nofollow noopener noreferrer">`ArchiveViewInfo`</a>, just load the archive document to the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer" target="_blank" rel="nofollow noopener noreferrer">`Viewer`</a> <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer/#constructors" target="_blank" rel="nofollow noopener noreferrer">constructor</a>, create a relevant <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/viewinfooptions/" target="_blank" rel="nofollow noopener noreferrer">`ViewInfoOptions`</a>, call the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer/getviewinfo/#getviewinfo" target="_blank" rel="nofollow noopener noreferrer">`Viewer.GetViewInfo()`</a> and cast the returned <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.results/viewinfo/" target="_blank" rel="nofollow noopener noreferrer">`ViewInfo`</a> instance to the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.results/archiveviewinfo/" target="_blank" rel="nofollow noopener noreferrer">`ArchiveViewInfo`</a> type.

## Additional features

Despite the new archive processing module being introduced in the GroupDocs.Viewer version 24.10, it is consequentially and constantly improved with new features and enhancements.

First of all, we constantly add support for new archive formats. In the <a href="https://releases.groupdocs.com/viewer/net/release-notes/2025/groupdocs-viewer-for-net-25-1-release-notes/#lha-support" target="_blank" rel="nofollow noopener noreferrer">version 25.1</a> a support of LHA/LZH archive format was added. In the <a href="https://releases.groupdocs.com/viewer/net/release-notes/2025/groupdocs-viewer-for-net-25-2-release-notes/" target="_blank" rel="nofollow noopener noreferrer">version 25.2</a> a support of Cabinet (CAB) archive format was added, and in the <a href="https://releases.groupdocs.com/viewer/net/release-notes/2025/groupdocs-viewer-for-net-25-3-release-notes/" target="_blank" rel="nofollow noopener noreferrer">version 25.3</a> - support of Windows Imaging (WIM) format.

Also the version 25.2 has introduced an improvement - now the last modification date is shown also for the entries of CAB, ISO, and TAR archives.

But the most significant emerging feature was presented in the version 25.3 - starting from this version the GroupDocs.Viewer supports listing content of the nested archives - archives inside archives, - and this nesting level is indefinite. This means that one archive file may contain another, inner, and this inner contains other sub-inner archives, and so on… if these sub-archives are not password-protected, then the GroupDocs.Viewer will open them and explore their content. Screenshot below shows such a sample archive, rendered with the GroupDocs.Viewer.

![Listing nested archives inside outer archive](/net/viewer/images/rendering-basics/render-archive-files/Nested-archives-example.png)

Sample file "all-formats.zip", shown on a screenshot, actually has no _folders_ "sample.tar" and "sample.zip" - they are actually _files_, inner archives inside outer archive. But GroupDocs.Viewer has opened and listed their content and thus displayed them as the folders. Need to mention that rendering nested archives does not require any additional actions or tuning in the public API - it is enabled by default.

## Conclusion

Before the version 24.10 the archive documents were supported by the GroupDocs.Viewer in a specific way, without showing the tree hierarchy, only with a paged view, showing only one folder at a page. Performance was also not so good as it could be, especially on big archives.

Starting from the version 24.10, the completely new archive processing mechanism has completely replaced the old one. Now the list of contents of archives is rendered as archive entries are actually stored, in tree-like pageless view, where separation on pages are done only for paged formats like PDF, PNG, and JPEG, and now this page splitting is not dependent on specific folders. Performance was also drastically improved, especially while rendering archives to HTML.

This new archive processing mechanism is constantly improved from version to version with the new bugfixes, features and enhancements.
