<a href="https://products.groupdocs.com/viewer/net" target="_blank" rel="nofollow noopener noreferrer">GroupDocs.Viewer for .NET</a> allows you to render your Microsoft Word documents in HTML, PDF, PNG, and JPEG formats. You do not need to use Microsoft Word or other word processors to load and view Word documents within your .NET application (web or desktop). 

To start using the GroupDocs.Viewer API, create a <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer" target="_blank" rel="nofollow noopener noreferrer">Viewer</a> class instance. Pass a document you want to view to the class constructor. You can load the document from a file or stream. Call one of the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer/methods/view/index" target="_blank" rel="nofollow noopener noreferrer">Viewer.View</a> method overloads to convert the document to HTML, PDF, or image format. These methods allow you to render the entire document or specific pages.

## Supported Word Processing file formats

GroupDocs.Viewer supports the following Word Processing file formats:

* <a href="https://docs.fileformat.com/word-processing/docx" target="_blank" rel="nofollow noopener noreferrer">Microsoft Word Document</a> (.DOCX)
* <a href="https://docs.fileformat.com/word-processing/doc" target="_blank" rel="nofollow noopener noreferrer">Microsoft Word 97-2003 Document</a> (.DOC)
* <a href="https://docs.fileformat.com/word-processing/docm" target="_blank" rel="nofollow noopener noreferrer">Microsoft Word Macro-Enabled Document</a> (.DOCM)
* <a href="https://docs.fileformat.com/word-processing/dot" target="_blank" rel="nofollow noopener noreferrer">Microsoft Word 97-2003 Template</a> (.DOT)
* <a href="https://docs.fileformat.com/word-processing/dotm" target="_blank" rel="nofollow noopener noreferrer">Microsoft Word Macro-Enabled Template</a> (.DOTM)
* <a href="https://docs.fileformat.com/word-processing/dotx" target="_blank" rel="nofollow noopener noreferrer">Microsoft Word Template</a> (.DOTX)
* <a href="https://docs.fileformat.com/word-processing/odt" target="_blank" rel="nofollow noopener noreferrer">OpenDocument Text</a> (.ODT)
* <a href="https://docs.fileformat.com/word-processing/ott" target="_blank" rel="nofollow noopener noreferrer">OpenDocument Text Template</a> (.OTT)
* <a href="https://docs.fileformat.com/word-processing/rtf" target="_blank" rel="nofollow noopener noreferrer">Rich Text Document</a> (.RTF)
* <a href="https://docs.fileformat.com/word-processing/txt" target="_blank" rel="nofollow noopener noreferrer">Plain Text Document</a> (.TXT)

GroupDocs.Viewer can detect the document format automatically based on information in the file header.

## Render Word documents as HTML

Create an <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/htmlviewoptions" target="_blank" rel="nofollow noopener noreferrer">HtmlViewOptions</a> class instance and pass it to the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer/methods/view/index" target="_blank" rel="nofollow noopener noreferrer">Viewer.View</a> method to convert a Word file to HTML. The `HtmlViewOptions` class properties allow you to control the conversion process. For instance, you can embed all external resources in the generated HTML file, minify the output file, and optimize it for printing. Refer to the following documentation section for details: [Rendering to HTML](/net/viewer/developer-guide/rendering-documents/rendering-to-html/). 

### Create an HTML file with embedded resources

To save all elements of an HTML page (including text, graphics, and stylesheets) into a single file, call the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/htmlviewoptions/methods/forembeddedresources/index" target="_blank" rel="nofollow noopener noreferrer">HtmlViewOptions.ForEmbeddedResources</a> method and specify the output file name.


<Tabs groupId="example1">


<TabItem value="c" label="C#" default>

```csharp
using GroupDocs.Viewer;
using GroupDocs.Viewer.Options;
// ...

using (var viewer = new Viewer("resume.docx"))
{
    // Create an HTML file for each document page.
    // {0} is replaced with the current page number in the file name.
    var viewOptions = HtmlViewOptions.ForEmbeddedResources("page_{0}.html");
    viewer.View(viewOptions);
}
```

</TabItem>


<TabItem value="vb-net" label="VB.NET">

```vb
Imports GroupDocs.Viewer
Imports GroupDocs.Viewer.Options
' ...

Module Program
    Sub Main(args As String())
        Using viewer = New Viewer("resume.docx")
            ' Create an HTML file for each document page.
            ' {0} is replaced with the current page number in the file name.
            Dim viewOptions = HtmlViewOptions.ForEmbeddedResources("page_{0}.html")
            viewer.View(viewOptions)
        End Using
    End Sub
End Module
```

</TabItem>

### Create an HTML file with external resources

If you want to store an HTML file and additional resource files (such as fonts, images, and stylesheets) separately, call the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/htmlviewoptions/methods/forexternalresources/index" target="_blank" rel="nofollow noopener noreferrer">HtmlViewOptions.ForExternalResources</a> method and pass the following parameters:

  * The output file path format
  * The path format for the folder with external resources
  * The resource URL format


<Tabs groupId="example2">


<TabItem value="c" label="C#" default>

```csharp
using GroupDocs.Viewer;
using GroupDocs.Viewer.Options;
// ...

using (var viewer = new Viewer("resume.docx"))
{
    // Create an HTML file for each document page.
    // Specify the HTML file names and location of external resources.
    // {0} and {1} are replaced with the current page number and resource name, respectively.
    var viewOptions = HtmlViewOptions.ForExternalResources("page_{0}.html", "page_{0}/resource_{0}_{1}", "page_{0}/resource_{0}_{1}");
    viewer.View(viewOptions);
}
```

</TabItem>

## Define page margins

Use the following properties to specify the size of page margins in the output files when you convert your Word documents to HTML, PDF, and image formats: 

* <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/wordprocessingoptions/properties/topmargin" target="_blank" rel="nofollow noopener noreferrer">WordProcessingOptions.TopMargin</a> specifies the distance (in points) between document content and the top edge of the page.
* <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/wordprocessingoptions/properties/bottommargin" target="_blank" rel="nofollow noopener noreferrer">WordProcessingOptions.BottomMargin</a> specifies the distance (in points) between document content and the bottom edge of the page.
* <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/wordprocessingoptions/properties/leftmargin" target="_blank" rel="nofollow noopener noreferrer">WordProcessingOptions.LeftMargin</a> specifies the distance (in points) between document content and the left edge of the page.
* <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/wordprocessingoptions/properties/rightmargin" target="_blank" rel="nofollow noopener noreferrer">WordProcessingOptions.RightMargin</a> specifies the distance (in points) between document content and the right edge of the page.

You can access these properties for the following classes:

* <a href="https://reference.groupdocs.com/net/viewer/groupdocs.viewer.options/htmlviewoptions" target="_blank" rel="nofollow noopener noreferrer">HtmlViewOptions</a>
* <a href="https://reference.groupdocs.com/net/viewer/groupdocs.viewer.options/pdfviewoptions" target="_blank" rel="nofollow noopener noreferrer">PdfViewOptions</a>
* <a href="https://reference.groupdocs.com/net/viewer/groupdocs.viewer.options/pngviewoptions" target="_blank" rel="nofollow noopener noreferrer">PngViewOptions</a>
* <a href="https://reference.groupdocs.com/net/viewer/groupdocs.viewer.options/jpgviewoptions" target="_blank" rel="nofollow noopener noreferrer">JpgViewOptions</a> 

The example below converts a Word document to HTML and specifies page margins for the output file. 


<Tabs groupId="example6">


<TabItem value="c" label="C#" default>

```csharp
using GroupDocs.Viewer;
using GroupDocs.Viewer.Options;
// ...

using (var viewer = new Viewer("resume.docx"))
{
    // Create an HTML file for each document page.
    // {0} is replaced with the current page number in the file name.
    var viewOptions = HtmlViewOptions.ForEmbeddedResources("page_{0}.html");
    // Specify the size of page margins in points.
    viewOptions.WordProcessingOptions.TopMargin = 72;
    viewOptions.WordProcessingOptions.BottomMargin = 72;
    viewOptions.WordProcessingOptions.LeftMargin = 54;
    viewOptions.WordProcessingOptions.RightMargin = 54;
    viewer.View(viewOptions);
}
```

</TabItem>


## Render tracked changes

GroupDocs.Viewer does not render tracked changes (revisions made to a Word document) by default. If you want to display tracked changes in the output file, enable the <a href="https://reference.groupdocs.com/net/viewer/groupdocs.viewer.options/wordprocessingoptions/properties/rendertrackedchanges" target="_blank" rel="nofollow noopener noreferrer">WordProcessingOptions.RenderTrackedChanges</a> property for one of the following classes (depending on the output file format):

* <a href="https://reference.groupdocs.com/net/viewer/groupdocs.viewer.options/htmlviewoptions" target="_blank" rel="nofollow noopener noreferrer">HtmlViewOptions</a> 
* <a href="https://reference.groupdocs.com/net/viewer/groupdocs.viewer.options/pdfviewoptions" target="_blank" rel="nofollow noopener noreferrer">PdfViewOptions</a>
* <a href="https://reference.groupdocs.com/net/viewer/groupdocs.viewer.options/pngviewoptions" target="_blank" rel="nofollow noopener noreferrer">PngViewOptions</a>
* <a href="https://reference.groupdocs.com/net/viewer/groupdocs.viewer.options/jpgviewoptions" target="_blank" rel="nofollow noopener noreferrer">JpgViewOptions</a>

The following code example demonstrates how to render a Word document with tracked changes:


<Tabs groupId="example7">


<TabItem value="c" label="C#" default>

```csharp
using GroupDocs.Viewer;
using GroupDocs.Viewer.Options;
// ...

using (var viewer = new Viewer("TrackChanges.docx"))
{
    // Convert the document to PDF.
    var viewOptions = new PdfViewOptions("output.pdf");
    // Enable tracked changes rendering.
    viewOptions.WordProcessingOptions.RenderTrackedChanges = true;
    viewer.View(viewOptions);
}
```

</TabItem>


<TabItem value="vb-net" label="VB.NET">

```vb

Imports GroupDocs.Viewer.Options
' ...

    Sub Main(args As String())
        Using viewer = New Viewer("TrackChanges.docx")

            ' Enable tracked changes rendering.

            viewer.View(viewOptions)
        End Using
    End Sub
End Module
```

</TabItem>

## Unlink table of contents

When rendering to HTML or PDF, you can set <a href="https://reference.groupdocs.com/net/viewer/groupdocs.viewer.options/wordprocessingoptions/properties/unlinktableofcontents" target="_blank" rel="nofollow noopener noreferrer">WordProcessingOptions.UnlinkTableOfContents</a> to `true` to unlink table of contents. For HTML rendering, `<a>` tags with relative links will be replaced with `<span>` tags, removing functionality but preserving visual appearance. For PDF rendering, the table of contents will be rendered as plain text without links to document sections.

The code example below renders a Word document with table of contents as a plain text without links.

```csharp
using (var viewer = new Viewer("resume.docx"))

    // Unlink table of contents.
    viewOptions.WordProcessingOptions.UnlinkTableOfContents = true;

}
```

## Disable updating fields when saving

The most of formats inside the WordProcessing family of formats, like DOC, DOCX, ODT and so on, have the concept of <a href="https://support.microsoft.com/en-us/office/list-of-field-codes-in-word-1ad6d91a-55a7-4a8d-b535-cf7888659a51" target="_blank" rel="nofollow noopener noreferrer">fields</a>, which are processed when the document is opened in some viewer application like Microsoft Word. When the input WordProcessing document is loaded to the GroupDocs.Viewer and saved to the HTML (with embedded or external resources), PDF, PNG, or JPEG output formats, all the fields within the input document are updated while saving, and this mimics the Microsoft Word behavior. But in some scenarios, for example, when field values are incorrect, there is no necessary and even not desirable to update fields.

Starting from the version <a href="https://releases.groupdocs.com/viewer/net/release-notes/2024/groupdocs-viewer-for-net-24-12-release-notes/" target="_blank" rel="nofollow noopener noreferrer">24.12</a> the GroupDocs.Viewer for .NET has obtained an ability to disable updating fields while saving the documents. The new public property <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/wordprocessingoptions/updatefields/" target="_blank" rel="nofollow noopener noreferrer">`UpdateFields`</a> of the <a href="https://learn.microsoft.com/dotnet/api/system.boolean" target="_blank" rel="nofollow noopener noreferrer">`System.Boolean`</a> type was added to the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/wordprocessingoptions/" target="_blank" rel="nofollow noopener noreferrer">`Options.WordProcessingOptions`</a> class. By default the value of this property is set to `true`, so fields are updated, as before. In order to turn fields updating off, please set this property to `false`. Code sample below shows opening a sample DOCX document and saving to the HTML with embedded resources and PDF formats without updating fields during saving.


<Tabs groupId="example-UpdateFields">


<TabItem value="c" label="C#" default>

```csharp
using GroupDocs.Viewer;
using GroupDocs.Viewer.Options;
// ...

HtmlViewOptions htmlViewOptions = HtmlViewOptions.ForEmbeddedResources();
htmlViewOptions.WordProcessingOptions.UpdateFields = false;

PdfViewOptions pdfViewOptions = new PdfViewOptions("output.pdf");
pdfViewOptions.WordProcessingOptions.UpdateFields = false;

using (var viewer = new Viewer("resume.docx"))
{    
    viewer.View(htmlViewOptions);
	viewer.View(pdfViewOptions);
}
```

</TabItem>


<TabItem value="vb-net" label="VB.NET">

```vb
Imports GroupDocs.Viewer
Imports GroupDocs.Viewer.Options
```

## Remove or preserve JavaScript when saving to HTML

Most of WordProcessing formats like DOC, DOCX, ODT and so on are able to store the scripts, usually written on VBA. When the output format is PDF, PNG, or JPEG, there is no problem at all. But when the output format is HTML, this may lead to the situations when malicious or harmful VBA script(s) from input DOCX, for example, will be translated to the resultant HTML document. Before the <a href="https://releases.groupdocs.com/viewer/net/release-notes/2025/groupdocs-viewer-for-net-25-1-release-notes/" target="_blank" rel="nofollow noopener noreferrer">version 25.1</a> the was no possibility for the GroupDocs.Viewer to disable scripts preserving and translation - all the VBA scripts were translated to the JavaScript in HTML. Starting from the version 25.1, for the security purposes script translation is disabled by default - all the links containing JavaScript are replaced with the harmless `"javascript:void(0)"` string in the resultant HTML markup. But it is possible to enable script translation, as it was present in the GroupDocs.Viewer before, by using a new public property `RemoveJavaScript` of the <a href="https://learn.microsoft.com/dotnet/api/system.boolean" target="_blank" rel="nofollow noopener noreferrer">`System.Boolean`</a> type in the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/htmlviewoptions/" target="_blank" rel="nofollow noopener noreferrer">`Options.HtmlViewOptions`</a> class. By default this property has a `true` value - JavaScript will be removed from the resultant HTML document. For preserving the JavaScript, as it was in the previous versions of the GroupDocs.Viewer, the `false` value should be assigned to this property. Code sample below shows opening a sample DOCX document and rendering it to the HTML with embedded resources with and without JavaScript.


<Tabs groupId="example-RemoveJavaScript">


<TabItem value="c" label="C#" default>

```csharp
using GroupDocs.Viewer;
using GroupDocs.Viewer.Options;
// ...

HtmlViewOptions htmlViewOptionsWithoutJavaScript = HtmlViewOptions.ForEmbeddedResources("without-js-page{0}.html");

HtmlViewOptions htmlViewOptionsWithJavaScript = HtmlViewOptions.ForEmbeddedResources("with-js-page{0}.html");
htmlViewOptionsWithJavaScript.RemoveJavaScript = false;

using (var viewer = new Viewer("Doc-with-VBA.docx"))
{
    viewer.View(htmlViewOptionsWithoutJavaScript);
    viewer.View(htmlViewOptionsWithJavaScript);
}
```

</TabItem>


<TabItem value="vb-net" label="VB.NET">


## Specify DPI when rendering to raster formats

Before version 26.8, when rendering loaded WordProcessing documents to the raster formats ([PNG](#render-word-documents-as-png) and [JPEG](#render-word-documents-as-jpeg)), the horizontal and vertical resolution of the output image was always fixed and equal to `96` DPI (Dots Per Inch). As a result, it was impossible to significantly increase the quality of produced images. To solve this problem, the <a href="https://releases.groupdocs.com/viewer/net/release-notes/2026/groupdocs-viewer-for-net-26-8-release-notes/" target="_blank" rel="nofollow noopener noreferrer">version 26.8</a> contains two new properties in the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/wordprocessingoptions/" target="_blank" rel="nofollow noopener noreferrer">`WordProcessingOptions`</a> - the `HorizontalResolution` and `VerticalResolution`, both of `Int32` type, which are responsible for the horizontal resolution and vertical resolution respectively.

By default their values are `96` DPI - same as in all previous versions of GroupDocs.Viewer. But now a user can change these values. The minimum possible value is `72` DPI - even if a user will set a lesser number, the `72` DPI will be applied. There is also a maximum possible value - `600` DPI. Even if the bigger numbers are specified, the `600` DPI is applied. This is true for both `HorizontalResolution` and `VerticalResolution`.

Need to additionally emphasize that these two properties are valid only when rendering to the PNG and JPEG formats; for other formats they are ignored.

Source code below demonstrated rendering the loaded "sample.docs" to the PNG format with adjusted horizontal and vertical resolutions, which are both set to 192 DPI, and to the JPEG format, where horizontal resolution is intact and default (96 DPI), while only the vertical is adjusted - 120 DPI.


<Tabs groupId="example-SpecifyCustomResolution">


<TabItem value="c" label="C#" default>

```csharp
using GroupDocs.Viewer;
using GroupDocs.Viewer.Options;
// ...

PngViewOptions pngOpt = new PngViewOptions();
pngOpt.WordProcessingOptions.HorizontalResolution = pngOpt.WordProcessingOptions.VerticalResolution = 192;

JpgViewOptions jpegOpt = new JpgViewOptions();
jpegOpt.WordProcessingOptions.VerticalResolution = 120;

using (Viewer viewer = new Viewer("sample.docx"))
{
    viewer.View(pngOpt);
    viewer.View(jpegOpt);
}
```

</TabItem>


<TabItem value="vb-net" label="VB.NET">

```vb

' ...

    viewer.View(jpegOpt)

```

## Add page numbers during rendering

By default the GroupDocs.Viewer renders the input WordProcessing documents "as-is", without any changes. This applies to the page numbers as well: when they are present in the original file, they also will be present in the output PDF, HTML, PNG and JPEG, and vice versa. Initially there was no possibility to forcibly add the page numbers to the produced output documents.

However, this has changed since the version 26.8. Starting from this version it is possible to apply the page numeration to the WordProcessing documents. Important note: the input WordProcessing file are not changed in any case regardless of which options are applied. The described feature modifies only the output documents, generated by the GroupDocs.Viewer from input Words files.

This feature has the next behavior. A new property `PageNumberLocation` was added to the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/wordprocessingoptions/" target="_blank" rel="nofollow noopener noreferrer">`WordProcessingOptions`</a> class, that is accessible from the <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/baseviewoptions/wordprocessingoptions/" target="_blank" rel="nofollow noopener noreferrer">`WordProcessingOptions`</a> property. It is of enum type `WordsPageNumberLocation` and its default value is `NotApply` - this means that by default the input WordProcessing documents are rendered as before: when an input document has page numbers, they are present in the output documents, but when it has not - page numbers are absent. But when any other value of `WordsPageNumberLocation` enum except from of `NotApply` is specified in the `PageNumberLocation` property, the GroupDocs.Viewer forcibly adds the page numbers to the produced output documents. If the original document already had the page numbers, they are initially removed from the output documents, and then the new page numbers are added.

The `WordsPageNumberLocation` enum actually has 2 functions: it forcibly applies the page numbers to the pages and also specifies the position of where the page numbers should be located: `TopLeft`, `TopCenter`, `TopRight`, `BottomLeft`, `BottomCenter`, `BottomRight`.

Page numbers with different locations can be applied to different output formats for the same input WordProcessing document. The code sample above shows applying page numbers in the top left corner to the output PDF and page numbers in the bottom center side to the output HTML.


<Tabs groupId="example-AddingPageNumbers">


<TabItem value="c" label="C#" default>

```csharp
using GroupDocs.Viewer;
using GroupDocs.Viewer.Options;
// ...

PdfViewOptions pdfOpt = new PdfViewOptions();
pdfOpt.WordProcessingOptions.PageNumberLocation = WordsPageNumberLocation.TopLeft;

HtmlViewOptions htmlEmbeddedOpt = HtmlViewOptions.ForEmbeddedResources();
htmlEmbeddedOpt.WordProcessingOptions.PageNumberLocation = WordsPageNumberLocation.BottomCenter;

using (Viewer viewer = new Viewer("sample.docx"))
{
    viewer.View(pdfOpt);
    viewer.View(htmlEmbeddedOpt);
}
```

</TabItem>


<TabItem value="vb-net" label="VB.NET">

```vb
Imports GroupDocs.Viewer

' ...

htmlEmbeddedOpt.WordProcessingOptions.PageNumberLocation = WordsPageNumberLocation.BottomCenter
```
