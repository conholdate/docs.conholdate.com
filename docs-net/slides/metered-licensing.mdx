## **Introduction**

Metered licensing is a licensing mechanism that can be used alongside existing licensing methods. If you want to be billed based on your usage of Aspose.Slides API features, you choose metered licensing.

## **Apply Metered Keys**

When you purchase a metered license, you get keys (and not a license file). This metered key can be applied using the <a href="https://reference.aspose.com/slides/net/aspose.slides/metered/" target="_blank" rel="nofollow noopener noreferrer">Metered</a> class Aspose provided for metering operations. For more details, see <a href="https://purchase.conholdate.com/faqs/licensing/metered" target="_blank">Metered Licensing FAQ</a>.

1. Create an instance of the <a href="https://reference.aspose.com/slides/net/aspose.slides/metered/" target="_blank" rel="nofollow noopener noreferrer">Metered</a> class.
2. Pass your public and private keys to the <a href="https://reference.aspose.com/slides/net/aspose.slides/metered/setmeteredkey/" target="_blank" rel="nofollow noopener noreferrer">SetMeteredKey</a> method.
3. Do some processing (perform tasks).
4. Call the <a href="https://reference.aspose.com/slides/net/aspose.slides/metered/getconsumptionquantity/" target="_blank" rel="nofollow noopener noreferrer">GetConsumptionQuantity</a> method of the `Metered` class.

You should see the amount/quantity of API requests you have consumed so far.

This sample code shows you how to use metered licensing:

```cs
// Creates an instance of the Metered class
Aspose.Slides.Metered metered = new Aspose.Slides.Metered();

// Passes the public and private keys to the Metered object
metered.SetMeteredKey("<valid public key>", "<valid private key>");

// Gets the metered data quantity before API call
decimal amountBefore = Aspose.Slides.Metered.GetConsumptionQuantity();
Console.WriteLine("Amount consumed before: " + amountBefore.ToString());

// Do something with Aspose.Slides API here
// ...

// Gets the metered data amount after API call
decimal amountAfter = Aspose.Slides.Metered.GetConsumptionQuantity();
Console.WriteLine("Amount consumed after: " + amountAfter.ToString());
```

To use metered licensing, you need a stable internet connection because the licensing mechanism uses the internet to constantly interact with our services and perform calculations.

## **FAQ**

### Can I use a metered license together with a regular one (perpetual or temporary) in the same application?

Yes. Metered is an additional licensing mechanism that can be used alongside existing [licensing methods](/net/slides/licensing/). You choose which mechanism to apply when the application starts.

### What exactly counts as consumption under a metered license: operations or files?

API usage is counted, meaning the number of requests or operations. You can obtain the current consumption via <a href="https://reference.aspose.com/slides/net/aspose.slides/metered/" target="_blank" rel="nofollow noopener noreferrer">consumption-tracking methods</a>.

### Is metered suitable for microservices and serverless environments where instances restart frequently?

Yes. Since accounting is done at the API-call level, scenarios with frequent cold starts are compatible, provided there is stable network access for metered calculations.

### Does the library's functionality differ when using a metered license compared to a perpetual license?

No. This is only about the licensing and billing mechanism; the product's capabilities are the same.

### How does metered relate to the trial version and the temporary license?

The trial version has limitations and watermarks, the <a href="https://purchase.conholdate.com/temporary-license/" target="_blank">temporary license</a> removes limitations for 30 days, and metered removes limitations and charges based on actual usage.

### Can I control the budget by automatically reacting when a consumption threshold is exceeded?

Yes. A common practice is to periodically read current consumption via <a href="https://reference.aspose.com/slides/net/aspose.slides/metered/" target="_blank" rel="nofollow noopener noreferrer">tracking methods</a> and implement your own limits or alerts at the application or monitoring level.
