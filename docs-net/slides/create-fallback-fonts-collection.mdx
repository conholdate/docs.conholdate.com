## **Overview**

Aspose.Slides allows you to configure a collection of fallback font rules for a presentation. Each fallback rule is represented by the `FontFallBackRule` class and can be added to a `FontFallBackRulesCollection`, which implements the `IFontFallBackRulesCollection` interface.

After creating the collection, you can assign it to the `FontFallBackRulesCollection` property of the presentation's `FontsManager`. The `FontsManager` controls fonts across the presentation, and each `Presentation` instance has its own `FontsManager`.

Once the `FontsManager` is initialized with the fallback font collection, the specified fallback fonts are applied during presentation rendering.

## **Apply Fallback Rules**

Instances of <a href="https://reference.aspose.com/slides/net/aspose.slides/FontFallBackRule" target="_blank" rel="nofollow noopener noreferrer">FontFallBackRule</a> class can be organized into <a href="https://reference.aspose.com/slides/net/aspose.slides/fontfallbackrulescollection" target="_blank" rel="nofollow noopener noreferrer">FontFallBackRulesCollection</a>, that implements <a href="https://reference.aspose.com/slides/net/aspose.slides/ifontfallbackrulescollection" target="_blank" rel="nofollow noopener noreferrer">IFontFallBackRulesCollection</a> interface. It is possible to add or remove rules from the collection.

Then this collection may be assigned to <a href="https://reference.aspose.com/slides/net/aspose.slides/fontsmanager/properties/fontfallbackrulescollection" target="_blank" rel="nofollow noopener noreferrer">FontFallBackRulesCollection </a>property of the <a href="https://reference.aspose.com/slides/net/aspose.slides/fontsmanager" target="_blank" rel="nofollow noopener noreferrer">FontsManager</a> class. FontsManager controls fonts across the presentation.

Each <a href="https://reference.aspose.com/slides/net/aspose.slides/presentation" target="_blank" rel="nofollow noopener noreferrer">Presentation </a>has a <a href="https://reference.aspose.com/slides/net/aspose.slides/presentation/properties/fontsmanager" target="_blank" rel="nofollow noopener noreferrer">FontsManager </a>property with its own instance of the FontsManager class.

Here is an examples how to create fallback fonts rules collection and assign in into the FontsManager of a certain presentation:  

```csharp
using Aspose.Slides;

using (Presentation presentation = new Presentation())
{
	IFontFallBackRulesCollection userRulesList = new FontFallBackRulesCollection();

	userRulesList.Add(new FontFallBackRule(0x0B80, 0x0BFF, "Vijaya"));
	userRulesList.Add(new FontFallBackRule(0x3040, 0x309F, "MS Mincho, MS Gothic"));

	presentation.FontsManager.FontFallBackRulesCollection = userRulesList;
}
```

After FontsManager is initialised with fallback fonts collection, the fallback fonts are applied during presentation rendering.

## **FAQ**

### Will my fallback rules be embedded into the PPTX file and visible in PowerPoint after saving?

No. Fallback rules are runtime rendering settings; they are not serialized into PPTX and will not appear in PowerPoint's UI.

### Does fallback apply to text inside SmartArt, WordArt, charts, and tables?

Yes. The same glyph-substitution mechanism is used for any text in these objects.

### Does Aspose distribute any fonts with the library?

No. You add and use fonts on your side and under your own responsibility.

### Can replacement/substitution for missing fonts and fallback for missing glyphs be used together?

Yes. They are independent stages of the same font-resolution pipeline: first the engine resolves font availability ([replacement](/net/slides/font-replacement/)/[substitution](/net/slides/font-substitution/)), then fallback fills gaps for missing glyphs in available fonts.
