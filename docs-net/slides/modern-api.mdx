## **Introduction**

Historically, Aspose Slides has a dependency on System.Drawing and has in the public API the following classes from there:

- <a href="https://learn.microsoft.com/en-us/dotnet/api/system.drawing.graphics" target="_blank" rel="nofollow noopener noreferrer">Graphics</a>
- <a href="https://learn.microsoft.com/en-us/dotnet/api/system.drawing.image" target="_blank" rel="nofollow noopener noreferrer">Image</a>
- <a href="https://learn.microsoft.com/en-us/dotnet/api/system.drawing.bitmap" target="_blank" rel="nofollow noopener noreferrer">Bitmap</a>
- <a href="https://learn.microsoft.com/en-us/dotnet/api/system.drawing.printing.printersettings" target="_blank" rel="nofollow noopener noreferrer">PrinterSettings</a>

As of version 24.4, this public API is declared deprecated.

Since System.Drawing support in versions .NET6 and above is removed for non-Windows versions (<a href="https://learn.microsoft.com/en-us/dotnet/core/compatibility/core-libraries/6.0/system-drawing-common-windows-only" target="_blank" rel="nofollow noopener noreferrer">breaking change</a>), Slides has implemented a two-package approach:

- <a href="https://www.nuget.org/packages/Aspose.Slides.NET" target="_blank" rel="nofollow noopener noreferrer">Aspose.Slides.NET</a> - support for .NET6+ for Windows, .NETStandard for Windows/Linux/MacOS, .NETFramework 2+ (Windows).
  - has a dependence on <a href="https://www.nuget.org/packages/System.Drawing.Common/" target="_blank" rel="nofollow noopener noreferrer">System.Drawing.Common</a>.
- <a href="https://www.nuget.org/packages/Aspose.Slides.NET6.CrossPlatform" target="_blank" rel="nofollow noopener noreferrer">Aspose.Slides.NET6.CrossPlatform</a> - Windows/Linux/MacOS version without dependencies.

The inconvenience of <a href="https://www.nuget.org/packages/Aspose.Slides.NET6.CrossPlatform" target="_blank" rel="nofollow noopener noreferrer">Aspose.Slides.NET6.CrossPlatform</a> is that it implements its own version of System.Drawing in the same namespace (to support backward compatibility with the public API). Thus, when Aspose.Slides.NET6.CrossPlatform and System.Drawing from .NET Framework or System.Drawing.Common package are used at the same time, a name conflict occurs unless alias is used.

In order to get rid of dependencies on System.Drawing in the main Aspose.Slides.NET package, we added the so-called "Modern API" - i.e. the API that should be used instead of the deprecated one, whose signatures contain dependencies on the following types from System.Drawing: <a href="https://learn.microsoft.com/en-us/dotnet/api/system.drawing.image" target="_blank" rel="nofollow noopener noreferrer">Image</a> and <a href="https://learn.microsoft.com/en-us/dotnet/api/system.drawing.bitmap" target="_blank" rel="nofollow noopener noreferrer">Bitmap</a>. <a href="https://learn.microsoft.com/en-us/dotnet/api/system.drawing.printing.printersettings" target="_blank" rel="nofollow noopener noreferrer">PrinterSettings</a> and <a href="https://learn.microsoft.com/en-us/dotnet/api/system.drawing.graphics" target="_blank" rel="nofollow noopener noreferrer">Graphics</a> are declared deprecated and their support is removed from the public Slides API.

In current versions, treat the public API that depends on System.Drawing as legacy/deprecated. Use the Modern API for new code and when migrating existing image-processing workflows.

## **Modern API**

Added the following classes and enums to the public API:

- <a href="https://reference.aspose.com/slides/net/aspose.slides/iimage/" target="_blank" rel="nofollow noopener noreferrer">Aspose.Slides.IImage</a> - represents the raster or vector image.
- <a href="https://reference.aspose.com/slides/net/aspose.slides/imageformat/" target="_blank" rel="nofollow noopener noreferrer">Aspose.Slides.ImageFormat</a> - represents the file format of the image.
- <a href="https://reference.aspose.com/slides/net/aspose.slides/images/" target="_blank" rel="nofollow noopener noreferrer">Aspose.Slides.Images</a> - methods to instantiate and work with the <a href="https://reference.aspose.com/slides/net/aspose.slides/iimage/" target="_blank" rel="nofollow noopener noreferrer">IImage</a> interface.

Please note that <a href="https://reference.aspose.com/slides/net/aspose.slides/iimage/" target="_blank" rel="nofollow noopener noreferrer">IImage</a> is disposable (it implements the <a href="https://learn.microsoft.com/en-us/dotnet/api/system.idisposable" target="_blank" rel="nofollow noopener noreferrer">IDisposable</a> interface and its use should be wrapped in using or disposed in another convenient way).

Use `GetImage` to render a single slide or shape. Use `GetImages` to render several presentation slides. Use <a href="https://reference.aspose.com/slides/net/aspose.slides/images/" target="_blank" rel="nofollow noopener noreferrer">Images</a> methods to load images, `AddImage` with <a href="https://reference.aspose.com/slides/net/aspose.slides/iimage/" target="_blank" rel="nofollow noopener noreferrer">IImage</a> to add them to a presentation, and `ReplaceImage` with <a href="https://reference.aspose.com/slides/net/aspose.slides/iimage/" target="_blank" rel="nofollow noopener noreferrer">IImage</a> to update an existing presentation image.

A typical scenario of using the new API may look as follows:

```csharp
using System.Drawing;
using Aspose.Slides;

using (Presentation pres = new Presentation())
{
    IPPImage ppImage;
    // instantiate a disposable instance of IImage from the file on the disk.  
    using (IImage image = Images.FromFile("image.png"))
    {
        // create a PowerPoint image by adding an instance of IImage to the presentation's images.
        ppImage = pres.Images.AddImage(image);
    }

    // add a picture shape on the slide #1
    pres.Slides[0].Shapes.AddPictureFrame(ShapeType.Rectangle, 10, 10, 100, 100, ppImage);

    // get an instance of the IImage representing slide #1.
    using (var slideImage = pres.Slides[0].GetImage(new Size(1920, 1080)))
    {
        // save the image on the disk.
        slideImage.Save("slide1.jpeg", ImageFormat.Jpeg);
    }
}
```

## **Replacing Old Code with Modern API**

For ease of transition, the interface of the new <a href="https://reference.aspose.com/slides/net/aspose.slides/iimage/" target="_blank" rel="nofollow noopener noreferrer">IImage</a> repeats the separate signatures of the <a href="https://learn.microsoft.com/en-us/dotnet/api/system.drawing.image" target="_blank" rel="nofollow noopener noreferrer">Image</a> and <a href="https://learn.microsoft.com/en-us/dotnet/api/system.drawing.bitmap" target="_blank" rel="nofollow noopener noreferrer">Bitmap</a> classes. In general, you will just need to replace the call to the old method using System.Drawing with the new one.

### **Getting a Slide Thumbnail**

Legacy/deprecated API:

```csharp
using Aspose.Slides;

using (Presentation pres = new Presentation("pres.pptx"))
{
    pres.Slides[0].GetThumbnail().Save("slide1.png");
}
```

Modern API:

```csharp
using Aspose.Slides;

using (Presentation pres = new Presentation("pres.pptx"))
{
    pres.Slides[0].GetImage().Save("slide1.png");
}
```

### **Getting a Presentation Thumbnail**

Legacy/deprecated API:

```csharp
using System.Drawing;
using Aspose.Slides;
using Aspose.Slides.Export;

using (Presentation pres = new Presentation("pres.pptx"))
{
    var bitmaps = pres.GetThumbnails(new RenderingOptions(), new Size(1980, 1028));
    try
    {
        for (var index = 0; index < bitmaps.Length; index++)
        {
            Bitmap thumbnail = bitmaps[index];
            thumbnail.Save($"slide{index}.png", ImageFormat.Png);
        }
    }
    finally
    {
        foreach (Bitmap bitmap in bitmaps)
        {
            bitmap.Dispose();
        }
    }
}
```

Modern API:

```csharp
using System.Drawing;
using Aspose.Slides;
using Aspose.Slides.Export;

using (Presentation pres = new Presentation("pres.pptx"))
{
    var images = pres.GetImages(new RenderingOptions(), new Size(1980, 1028));
    try
    {
        for (var index = 0; index < images.Length; index++)
        {
            IImage thumbnail = images[index];
            thumbnail.Save($"slide{index}.png", ImageFormat.Png);
        }
    }
    finally
    {
        foreach (IImage image in images)
        {
            image.Dispose();
        }
    }
}
```

### **Adding a Picture to a Presentation**

Legacy/deprecated API:

```csharp
using System.Drawing;
using Aspose.Slides;

using (Presentation pres = new Presentation())
{
    IPPImage ppImage;
    using (Image image = Image.FromFile("image.png"))
    {
        ppImage = pres.Images.AddImage(image);
    }

    pres.Slides[0].Shapes.AddPictureFrame(ShapeType.Rectangle, 10, 10, 100, 100, ppImage);
}
```

Modern API:

```csharp
using Aspose.Slides;

using (Presentation pres = new Presentation())
{
    IPPImage ppImage;
    using (IImage image = Aspose.Slides.Images.FromFile("image.png"))
    {
        ppImage = pres.Images.AddImage(image);
    }

    pres.Slides[0].Shapes.AddPictureFrame(ShapeType.Rectangle, 10, 10, 100, 100, ppImage);
}
```

## **API Support for Graphics and PrinterSettings**

In Aspose Slides, use the Modern API image-rendering methods instead of the API that renders to <a href="https://learn.microsoft.com/en-us/dotnet/api/system.drawing.graphics" target="_blank" rel="nofollow noopener noreferrer">Graphics</a>:
<a href="https://reference.aspose.com/slides/net/aspose.slides/islide/" target="_blank" rel="nofollow noopener noreferrer">ISlide</a>

## **FAQ**

### Why was <a href="https://learn.microsoft.com/en-us/dotnet/api/system.drawing.graphics" target="_blank" rel="nofollow noopener noreferrer">Graphics</a> dropped?

Support for <a href="https://learn.microsoft.com/en-us/dotnet/api/system.drawing.graphics" target="_blank" rel="nofollow noopener noreferrer">Graphics</a> is deprecated in the public API to unify work with rendering and images, eliminate ties to platform-specific dependencies, and switch to a cross-platform approach with <a href="https://reference.aspose.com/slides/net/aspose.slides/iimage/" target="_blank" rel="nofollow noopener noreferrer">IImage</a>. Use `GetImage` or `GetImages` instead of rendering to <a href="https://learn.microsoft.com/en-us/dotnet/api/system.drawing.graphics" target="_blank" rel="nofollow noopener noreferrer">Graphics</a>.

### What is the practical benefit of <a href="https://reference.aspose.com/slides/net/aspose.slides/iimage/" target="_blank" rel="nofollow noopener noreferrer">IImage</a> compared to <a href="https://learn.microsoft.com/en-us/dotnet/api/system.drawing.image" target="_blank" rel="nofollow noopener noreferrer">Image</a>/<a href="https://learn.microsoft.com/en-us/dotnet/api/system.drawing.bitmap" target="_blank" rel="nofollow noopener noreferrer">Bitmap</a>?

<a href="https://reference.aspose.com/slides/net/aspose.slides/iimage/" target="_blank" rel="nofollow noopener noreferrer">IImage</a> unifies working with both raster and vector images, simplifies saving to various formats via <a href="https://reference.aspose.com/slides/net/aspose.slides/imageformat/" target="_blank" rel="nofollow noopener noreferrer">ImageFormat</a>, reduces dependence on `System.Drawing`, and makes code more portable across environments.

### Will the Modern API affect the performance of generating thumbnails?

Switching from `GetThumbnail` to `GetImage` does not worsen scenarios: the new methods provide the same capabilities for producing images with options and sizes, while retaining support for rendering options. The specific gain or drop depends on the scenario, but functionally the replacements are equivalent.
