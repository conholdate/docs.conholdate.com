> This article describes how to obtain edited document content from client, process it and save to the resultant document of some specified format.

In a nutshell, the core process of document editing, where a user types some text across the pages of the document, inserts images, makes some edits, removes words or paragraphs, or moves some document parts from one location to another, is performed in some 3rd party software with GUI outside of the GroupDocs.Editor. This software may be, for example, but not limiting to:

- a web-based WYSIWYG HTML-editor, that is usually a pure client-side application, written on JavaScript and running in the browser. This may be, for example, a TinyMCE or CKEditor;
- desktop (like WinForms or WPF) application;
- mobile application, running on Android or iOS.

The core requirement for this application is to be able to open, view and edit HTML content. The GroupDocs.Editor on its side accepts various document formats (WordProcessing, Spreadsheet, Presentation, and many more) and prepares them for editing in external applications by converting to the HTML markup and placing it in the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a> container. So when calling the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor" target="_blank" rel="nofollow noopener noreferrer">Editor</a>.<a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor/edit" target="_blank" rel="nofollow noopener noreferrer">Edit()</a> method, the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a> with the **original content** inside it is generated.

Then the user obtains this **original content** from the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a>, pushes it to the external HTML-editor, makes edits, and when these edits are done, a user has the **modified content**. In the GroupDocs.Editor terminology saving a document means obtaining the **modified content** and generating the document in output format (WordProcessing, Spreadsheet, Presentation, and many more) from it. And this article explains how to do this.

In short, saving a document implies the next three steps:

1. Obtain the **modified content** from somewhere (HTML-editor or any other storage or method) and create an instance of <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a> from it. <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a> actually serves as an object-oriented wrapper of the document content.
2. Select a desired output format, into which the **modified content** should be saved, and optional parameters.
3. Save the **modified content** to the document of previously chosen format by specified file path or into specified stream using the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor" target="_blank" rel="nofollow noopener noreferrer">Editor</a>.<a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor/save" target="_blank" rel="nofollow noopener noreferrer">Save()</a> method.

These three steps are explained in detail and with code samples below.

## Obtaining the modified content

Different content editors provide the content in different forms. Some may return HTML markup as a <a href="https://learn.microsoft.com/en-us/dotnet/api/system.string" target="_blank" rel="nofollow noopener noreferrer">`System.String`</a>, while the external resources like stylesheet(s) and/or image(s) are located in some specific folder as files. Others may return both main content and resources as a collection of byte streams. Some HTML-editors may generate a single string, which already contains all HTML markup with resources baked into it using base64 encoding. There may be unlimited possibilities to do that, and thus the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a> class has different static factories, which obtain **modified content** of the HTML document in different forms on input and according to this generate the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a> instance:

1. <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument/fromfile" target="_blank" rel="nofollow noopener noreferrer">`FromFile` method</a> is designed for opening HTML-documents from disk - it obtains path to \*.html file (that contains HTML-markup) and an optional path to corresponding resource folder that contains different resources, like stylesheets, images, font files, audio files and so on.
2. <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument/frommarkup" target="_blank" rel="nofollow noopener noreferrer">`FromMarkup` method</a> is designed for opening HTML-documents from memory - it obtains the HTML-markup as a <a href="https://docs.microsoft.com/en-us/dotnet/api/system.string?view=net-6.0" target="_blank" rel="nofollow noopener noreferrer">`System.String`</a> and an optional list of <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.htmlcss.resources/ihtmlresource" target="_blank" rel="nofollow noopener noreferrer">IHtmlResource</a> items, like stylesheets, images, fonts, audio resources and so on.
3. <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument/frommarkupandresourcefolder" target="_blank" rel="nofollow noopener noreferrer">`FromMarkupAndResourceFolder` method</a> is designed for opening HTML-documents from mixed storages - it obtains the HTML-markup as a <a href="https://docs.microsoft.com/en-us/dotnet/api/system.string?view=net-6.0" target="_blank" rel="nofollow noopener noreferrer">`System.String`</a>, but resources are obtained from a path to corresponding resource folder, which, unlike previous methods, is mandatory (such directory should exist).

More information about creating <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a> instances from files or markup with resources can be found in corresponding article "[Create EditableDocument from file or markup](/net/editor/developer-guide/editabledocument/create-editabledocument-from-file-or-markup/)".

## Create and adjust saving options

When the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a> instance with the **modified content** is created, it's time to save it to the resultant document of some defined format, and the GroupDocs.Editor needs to know this format. Like with load and edit options, every family format has its own class that implements <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/isaveoptions" target="_blank" rel="nofollow noopener noreferrer">ISaveOptions</a> interface. These classes are listed below.

| Format family | Example formats | Save options class | Format class |
| --- | --- | --- | --- |
| WordProcessing | DOC, DOCX, DOCM, DOT, ODT | <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingsaveoptions" target="_blank" rel="nofollow noopener noreferrer">WordProcessingSaveOptions</a> | <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.formats/wordprocessingformats" target="_blank" rel="nofollow noopener noreferrer">WordProcessingFormats</a> |
| Spreadsheet | XLS, XLSX, XLSM, XLSB | <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/spreadsheetsaveoptions" target="_blank" rel="nofollow noopener noreferrer">SpreadsheetSaveOptions</a> | <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.formats/spreadsheetformats" target="_blank" rel="nofollow noopener noreferrer">SpreadsheetFormats</a> |
| Delimiter-Separated Values (DSV) | CSV, TSV | <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/delimitedtextsaveoptions" target="_blank" rel="nofollow noopener noreferrer">DelimitedTextSaveOptions</a> | <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.formats/spreadsheetformats/" target="_blank" rel="nofollow noopener noreferrer">SpreadsheetFormats</a> |
| Presentation | PPT, PPTX, PPS, POT | <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/presentationsaveoptions" target="_blank" rel="nofollow noopener noreferrer">PresentationSaveOptions</a> | <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.formats/presentationformats" target="_blank" rel="nofollow noopener noreferrer">PresentationFormats</a> |
| Plain Text documents | TXT | <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/textsaveoptions" target="_blank" rel="nofollow noopener noreferrer">TextSaveOptions</a> | <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.formats/textualformats" target="_blank" rel="nofollow noopener noreferrer">TextualFormats</a> |
| Fixed-layout format | PDF | <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/pdfsaveoptions" target="_blank" rel="nofollow noopener noreferrer">PdfSaveOptions</a> | <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.formats/fixedlayoutformats" target="_blank" rel="nofollow noopener noreferrer">FixedLayoutFormats</a> |
| Fixed-layout format | XPS | <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/xpssaveoptions" target="_blank" rel="nofollow noopener noreferrer">XpsSaveOptions</a> | <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.formats/fixedlayoutformats" target="_blank" rel="nofollow noopener noreferrer">FixedLayoutFormats</a> |
| Email | EML, EMLX, TNEF, MSG, HTML, MHTML, ICS, VCF, PST, MBOX, OFT | <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/emailsaveoptions" target="_blank" rel="nofollow noopener noreferrer">EmailSaveOptions</a> | <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.formats/emailformats" target="_blank" rel="nofollow noopener noreferrer">EmailFormats</a> |
| e-Books | ePub, Mobi, AZW3 | <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/ebooksaveoptions/" target="_blank" rel="nofollow noopener noreferrer">EbookSaveOptions</a> | <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.formats/ebookformats" target="_blank" rel="nofollow noopener noreferrer">EBookFormats</a> |

So, let's say it is necessary to save the **modified content** to the document of DOCX format. DOCS is the part of WordProcessing family. So the instance of the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingsaveoptions" target="_blank" rel="nofollow noopener noreferrer">WordProcessingSaveOptions</a> class should be created, and the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.formats/wordprocessingformats/docx/" target="_blank" rel="nofollow noopener noreferrer">WordProcessingFormats.Docx</a> value should be specified in its constructor. Like this:

<TabItem value="c" label="C#" default>

```csharp
WordProcessingSaveOptions saveOptions = new WordProcessingSaveOptions(WordProcessingFormats.Docx);
```

</TabItem>


<TabItem value="vb-net" label="VB.NET">

```vb
Dim saveOptions As WordProcessingSaveOptions = New WordProcessingSaveOptions(WordProcessingFormats.Docx)
```

</Tabs>


If it is also necessary to encode the resultant document with the password, it can be done using one line of code:


</TabItem>


<TabItem value="vb-net" label="VB.NET">

Of course, different formats have different options. For example, there is a `Password` property in <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingsaveoptions" target="_blank" rel="nofollow noopener noreferrer">WordProcessingSaveOptions</a>, <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/spreadsheetsaveoptions" target="_blank" rel="nofollow noopener noreferrer">SpreadsheetSaveOptions</a>, <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/presentationsaveoptions" target="_blank" rel="nofollow noopener noreferrer">PresentationSaveOptions</a>, but there is no anything similar in <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/xpssaveoptions" target="_blank" rel="nofollow noopener noreferrer">XpsSaveOptions</a>, <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/emailsaveoptions" target="_blank" rel="nofollow noopener noreferrer">EmailSaveOptions</a>, <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/textsaveoptions" target="_blank" rel="nofollow noopener noreferrer">TextSaveOptions</a>, and <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/ebooksaveoptions/" target="_blank" rel="nofollow noopener noreferrer">EbookSaveOptions</a>, because these formats do not support password protection.

Also need to mention that the format of input document with **original content** and format of the resultant document with **modified content** may be different. For example, the original document can be some WordProcessing formats, while the output document can be TXT or PDF. Or the original document can be a PDF, while output - DOCX. Same transitions are allowed between Spreadsheets and DSV (two-ways). But, of course, they are not allowed, where formats are theoretically incompatible in their essence, like WordProcessing and Spreadsheet.

## Saving modified content to the document

Finally, when the instance of <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a> class with modified content inside is created, and the format of the resultant document is defined, it is possible to generate this resultant document using the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor" target="_blank" rel="nofollow noopener noreferrer">Editor</a>.<a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor/save" target="_blank" rel="nofollow noopener noreferrer">Save()</a> method. This method has two overloads. These overloads differ only with the way how output document is specified: as path, where file should be created, or as a byte stream, into which the document content should be written. All other parameters are the same.

Here is a signature:

<Tabs groupId="Save signature">


<TabItem value="c" label="C#" default>

```csharp
Save(EditableDocument inputDocument, string filePath, ISaveOptions saveOptions)
Save(EditableDocument inputDocument, Stream outputDocument, ISaveOptions saveOptions)
```

</TabItem>


<TabItem value="vb-net" label="VB.NET">

```vb
Save(inputDocument As EditableDocument, filePath As String, saveOptions As ISaveOptions)
Save(inputDocument As EditableDocument, outputDocument As Stream, saveOptions As ISaveOptions)
```

</TabItem>


</Tabs>

Here:
- The 1st parameter - `EditableDocument inputDocument` - is a <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a> instance with **modified content** inside, created on the 1st step.
- The 2nd parameter is a <a href="https://learn.microsoft.com/en-us/dotnet/api/system.io.stream" target="_blank" rel="nofollow noopener noreferrer">stream</a>, into which the resultant document of defined format should be written, or a `string`, that represents a file path, where the resultant document of defined format should be stored.
- The 3rd parameter is an instance of some save options, which defines the format of the resultant document and additional adjustments, created on the 2nd step.

In the <a href="https://releases.groupdocs.com/editor/net/release-notes/2025/groupdocs-editor-for-net-25-7-release-notes/" target="_blank" rel="nofollow noopener noreferrer">version 25.7</a> a new overload of the `Editor.Save()` method was added:


<Tabs groupId="Save simplified">


<TabItem value="c" label="C#" default>

```csharp
Save(EditableDocument inputDocument, string filePath)
```

</TabItem>


<TabItem value="vb-net" label="VB.NET">

```vb
Save(inputDocument As EditableDocument, filePath As String)
```

</TabItem>


</Tabs>


This overload is essentially a wrapper for the previously mentioned overload - it analyzes the file extension of the `filePath` argument and inferes the default saving options automatically.

## Complete code example

Because the WYSIWYG HTML-editor is not a part of the GroupDocs.Editor, it is hard to provide a lightweight code example with fully functional editing. So in this sample the content will be edited programmatically, using a <a href="https://learn.microsoft.com/ru-ru/dotnet/api/system.string.replace" target="_blank" rel="nofollow noopener noreferrer">`String.Replace`</a> method.


<Tabs groupId="Full example">


<TabItem value="c" label="C#" default>

```csharp
using GroupDocs.Editor.Formats;
using GroupDocs.Editor.Options;
// ...

// Create Editor class by loading an input document in DOCX format by path
Editor editor = new Editor("input.docx");

// Open document for edit and obtain EditableDocument
EditableDocument original = editor.Edit();

// Get the original content as a string
string originalContent = original.GetEmbeddedHtml();

// Get the modified content by editing original content
string modifiedContent = originalContent.Replace("old", "new");

// Create EditableDocument from modified content
EditableDocument modified = EditableDocument.FromMarkup(modifiedContent, null);

// Create and adjust 2 different saving options
WordProcessingSaveOptions docxSaveOptions = new WordProcessingSaveOptions(WordProcessingFormats.Docx);
PdfSaveOptions pdfSaveOptions = new PdfSaveOptions();

// Save modified content to the 2 documents
editor.Save(modified, "output.docx", docxSaveOptions);
editor.Save(modified, "output.pdf", pdfSaveOptions);

// Dispose all
original.Dispose();
modified.Dispose();
editor.Dispose();
```

</TabItem>


<TabItem value="vb-net" label="VB.NET">

```vb
Imports GroupDocs.Editor.Formats
Imports GroupDocs.Editor.Options
' ...

' Create Editor class by loading an input document in DOCX format by path
Dim editor As Editor = New Editor("input.docx")

' Open document for edit And obtain EditableDocument
Dim original As EditableDocument = editor.Edit()

' Get the original content as a string
Dim originalContent As String = original.GetEmbeddedHtml()

' Get the modified content by editing original content

' Create EditableDocument from modified content
Dim modified As EditableDocument = EditableDocument.FromMarkup(modifiedContent, Nothing)

' Create And adjust 2 different saving options

' Save modified content to the 2 documents

editor.Save(modified, "output.pdf", pdfSaveOptions)

' Dispose all
original.Dispose()
modified.Dispose()
editor.Dispose()
```

</TabItem>


</Tabs>


In this example 2 different save options are created and two different <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor" target="_blank" rel="nofollow noopener noreferrer">Editor</a>.<a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor/save" target="_blank" rel="nofollow noopener noreferrer">Save()</a> calls are made for saving the modified content to the DOCX and PDF formats.
