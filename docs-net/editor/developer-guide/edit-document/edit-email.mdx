> This example demonstrates the standard open-edit-save pipeline with Email documents, using different options on every step.

## Introduction

There is a group of <a href="https://docs.fileformat.com/email/" target="_blank" rel="nofollow noopener noreferrer">Email file formats</a>, which usually are intended for storing individual mail letters, or contact data, personal information, calendar and so on. There are plenty of them, because almost every email program uses its own set of such formats. 

From its emergence the GroupDocs.Editor for .NET had no support for editing the such documents in Email formats. But starting from the <a href="https://docs.groupdocs.com/editor/net/groupdocs-editor-for-net-22-7-release-notes/" target="_blank" rel="nofollow noopener noreferrer">version 22.7</a> we finally released this possibility! And this article explains in detail how to edit different Email files, because due to their nature their editing differs from editing common text documents.

## Loading

Loding of the Email documents is usual and the same as for other formats. Like with text, XPS and e-Book formats, and unlike the PDF and Office formats, there is no loading options for the Email documents - just specify a path to the file or a <a href="https://docs.microsoft.com/en-us/dotnet/api/system.IO.Stream?view=net-6.0" target="_blank" rel="nofollow noopener noreferrer">byte stream</a> with the document content in the constructor of the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor" target="_blank" rel="nofollow noopener noreferrer">`GroupDocs.Editor.Editor`</a> class and that's all.

Code example below demonstrates loading a single EML file to the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor" target="_blank" rel="nofollow noopener noreferrer">`Editor`</a> instance through the file path and byte stream.

```csharp
const string emlFilename = "Attachments.eml";
string emlInputPath = System.IO.Path.Combine(Common.TestHelper.EmailFolder, emlFilename);

using (FileStream emlStream = File.OpenRead(emlInputPath))
using (Editor editorFromPath = new Editor(emlInputPath))//from the path
using (Editor editorFromStream = new Editor(emlStream))//from the stream
{
	//Here two Editor instances can separately work with one file
}
```

## Editing

Like for all other formats, there is a special <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/emaileditoptions" target="_blank" rel="nofollow noopener noreferrer">`EmailEditOptions`</a> class for adjusting editing of the Email documents. Instance of this class should be specified in the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor/edit/#edit" target="_blank" rel="nofollow noopener noreferrer">`Editor.Edit(IEditOptions editOptions)`</a> method. And, like for all other formats, it is possible to use a parameterless overload of the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor/edit" target="_blank" rel="nofollow noopener noreferrer">`Editor.Edit()`</a> - in this case, if Email document was loaded to the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor" target="_blank" rel="nofollow noopener noreferrer">`Editor`</a> instance, the GroupDocs.Editor will automatically apply the default <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/emaileditoptions" target="_blank" rel="nofollow noopener noreferrer">`EmailEditOptions`</a>.

<a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/emaileditoptions" target="_blank" rel="nofollow noopener noreferrer">`EmailEditOptions`</a> class has only one member - a <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/emaileditoptions/mailmessageoutput" target="_blank" rel="nofollow noopener noreferrer">`MailMessageOutput`</a> property of a <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/mailmessageoutput" target="_blank" rel="nofollow noopener noreferrer">`MailMessageOutput`</a> type. <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/mailmessageoutput" target="_blank" rel="nofollow noopener noreferrer">`MailMessageOutput`</a> is a flagged enum that controls, which parts of the mail message should be delivered to the output <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">`EditableDocument`</a> and then to the emitted HTML. The <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/mailmessageoutput" target="_blank" rel="nofollow noopener noreferrer">`MailMessageOutput`</a> enum has both *atomic* values that are responsible for a single part of the mail message, as well as *combined* values, like `Common` and `All`. It is allowed to use not only these combined values, but any user-defined combination of atomic values is acceptable. For example, it is possible to create a combination `Subject | Date | To | Cc | Bcc | From`, which processes only a metadata, but not the body and attachments list.

It is important to mention that currently the GroupDocs.Editor cannot process the content of the attachments, it can only display a list of attachment names. So the `MailMessageOutput.Attachments` flag, when specified, emits a list of attachment names, if they are present in the mail message.

Code example below shows adjusting of the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/mailmessageoutput" target="_blank" rel="nofollow noopener noreferrer">`MailMessageOutput`</a> and generating two different <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">`EditableDocument`</a> for editing from a single input Email document.

```csharp
//0. Prepare a sample file
const string emlFilename = "Attachments.eml";
string emlInputPath = System.IO.Path.Combine(Common.TestHelper.EmailFolder, emlFilename);

//1. Load to the Editor class
Editor editor = new Editor(emlInputPath);

//2. Create 1st edit options with only metadata
Options.EmailEditOptions editOptionsMetadata = new EmailEditOptions(MailMessageOutput.Subject | MailMessageOutput.From | MailMessageOutput.To | MailMessageOutput.Cc | MailMessageOutput.Bcc | MailMessageOutput.Date);

//2. Create 2nd edit options with only subject, body and attachments list
Options.EmailEditOptions editOptionsBody = new EmailEditOptions(MailMessageOutput.Subject | MailMessageOutput.Body | MailMessageOutput.Attachments);

//3. Generate two different EditableDocument with these options from single input "Attachments.eml"
EditableDocument onlyMetadata = editor.Edit(editOptionsMetadata);
EditableDocument onlyBody = editor.Edit(editOptionsBody);

//4. Then emit HTML/CSS and send to the WYSIWYG-editor on the client-side
```

## Saving

Saving the edited Email documents in general follows the same principles, like for other document formats, but with several distinctions. As usual, after obtaining an edited HTML-content from the client-side WYSIWYG-editor an instance of the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">`EditableDocument`</a> should be created, and then need to pass it to the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor/save" target="_blank" rel="nofollow noopener noreferrer">`GroupDocs.Editor.Editor.Save()`</a> method.

Like for all other formats, during saving, along with the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">`EditableDocument`</a> and a path or a stream, an inheritor of the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/isaveoptions" target="_blank" rel="nofollow noopener noreferrer">`ISaveOptions` interface</a> should be specified, and for email documents it is a <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/emailsaveoptions" target="_blank" rel="nofollow noopener noreferrer">`EmailSaveOptions`</a> class. Like the previously described <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/emaileditoptions" target="_blank" rel="nofollow noopener noreferrer">`EmailEditOptions`</a>, this class has only one member - a <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/emailsaveoptions/mailmessageoutput" target="_blank" rel="nofollow noopener noreferrer">`MailMessageOutput`</a> property of a <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/mailmessageoutput" target="_blank" rel="nofollow noopener noreferrer">`MailMessageOutput`</a> type. The only distinction between this `MailMessageOutput` property in `EmailEditOptions` and `EmailSaveOptions` is that in the first case the `MailMessageOutput` property controls, which parts of the mail message will be processed while generating <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">`EditableDocument`</a> from the input Email file, while in the second case the `MailMessageOutput` property controls, which parts of the mail message will be processed while generating output Email file from <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">`EditableDocument`</a>, obtained after editing. So it is possible, for example, send to the WYSIWYG-editor a full mail message with 100% all content, but generate an output file only with a `Subject` and `Body` content, for example.

Email format family consists of many different formats, but the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/emailsaveoptions" target="_blank" rel="nofollow noopener noreferrer">`EmailSaveOptions`</a> does not allow to specify the format for the output document - it automatically be the same, as the format of the original Email document, loaded into the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor" target="_blank" rel="nofollow noopener noreferrer">`GroupDocs.Editor.Editor`</a> class. So, for example, if you loaded the MSG file, then the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor/save" target="_blank" rel="nofollow noopener noreferrer">`GroupDocs.Editor.Editor.Save()`</a> method will also generate the MSG file, and no matter which file extension you specify.

Code example below shows full load-edit-save pipeline for the Email documents. It loads a document, makes it editable with `MailMessageOutput.All` combined flag, and then generates to output Email documents: first one is saved to the file with `MailMessageOutput.Common`, while second is saved to the stream with customly created combined flag.

```csharp
//0. Prepare a sample file
const string msgFilename = "ComplexExample.msg";
string msgInputPath = System.IO.Path.Combine(Common.TestHelper.EmailFolder, msgFilename);

//1. Load to the Editor class
Editor msgEditor = new Editor(msgInputPath);

//2. Create edit options with all content
Options.EmailEditOptions editOptions = new EmailEditOptions(MailMessageOutput.All);

//3. Generate an editable document
EditableDocument originalDoc = msgEditor.Edit(editOptions);

//4. Emit HTML from EditableDocument, send it to the client-side, edit it there in WYSIWYG-editor (omitted here)
string savedHtmlContent = originalDoc.GetEmbeddedHtml();

//5. Obtain edited content from the client-side and generate a new EditableDocument from it (omitted here)
EditableDocument editedDoc = EditableDocument.FromMarkup(savedHtmlContent, null);

//6. Create 1st save options
EmailSaveOptions saveOptions1 = new EmailSaveOptions(MailMessageOutput.Common);

//7. Create 2nd save options
EmailSaveOptions saveOptions2 = new EmailSaveOptions(MailMessageOutput.Body | MailMessageOutput.Attachments);

//8. Generate and save 1st output MSG to the file
string outputMsgPath = System.IO.Path.Combine(Common.TestHelper.OutputFolder, "OutputFile.msg");
msgEditor.Save(editedDoc, outputMsgPath, saveOptions1);

//9. Generate and save 2nd output MSG to the stream
Stream outputMsgStream = File.Create(Path.Combine(Common.TestHelper.OutputFolder, "OutputStream.msg"));
msgEditor.Save(editedDoc, outputMsgStream, saveOptions2);

//10. Dispose all resources
outputMsgStream.Dispose();
editedDoc.Dispose();
originalDoc.Dispose();
msgEditor.Dispose();
```

## Obtaining Email document info

Article <a href="https://docs.groupdocs.com/editor/net/extracting-document-metainfo/" target="_blank" rel="nofollow noopener noreferrer">Extracting document metainfo</a> describes the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor/getdocumentinfo" target="_blank" rel="nofollow noopener noreferrer">`GetDocumentInfo()` method</a>, that allows to detect the document format and extract its metadata without editing it. Actually, after adding Email support to the GroupDocs.Editor, this mechanism also works with Email documents.

When the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor/getdocumentinfo" target="_blank" rel="nofollow noopener noreferrer">`GetDocumentInfo()` method</a> is called for the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor" target="_blank" rel="nofollow noopener noreferrer">`Editor` class</a> instance that is loaded with an Email document, the method will return a <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.metadata/emaildocumentinfo" target="_blank" rel="nofollow noopener noreferrer">`GroupDocs.Editor.Metadata.EmailDocumentInfo`</a> instance - it is a common class for all Email formats like EML, EMLX, MSG and so on.

As all <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.metadata/idocumentinfo" target="_blank" rel="nofollow noopener noreferrer">`IDocumentInfo`</a> implementations, it has four properties:

1. <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.metadata/emaildocumentinfo/format" target="_blank" rel="nofollow noopener noreferrer">`Format`</a> property of <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.formats/emailformats" target="_blank" rel="nofollow noopener noreferrer">`Formats.EmailFormats`</a> type. It indicates the specific format of the given Email document.
2. <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.metadata/emaildocumentinfo/pagecount" target="_blank" rel="nofollow noopener noreferrer">`PageCount`</a> property of <a href="https://docs.microsoft.com/en-us/dotnet/api/system.int32?view=net-6.0" target="_blank" rel="nofollow noopener noreferrer">integer (`Int32`)</a> type. It always return 1, because email documents don't have paged view
3. <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.metadata/emaildocumentinfo/size" target="_blank" rel="nofollow noopener noreferrer">`Size`</a> property of a <a href="https://docs.microsoft.com/en-us/dotnet/api/system.int64?view=net-6.0" target="_blank" rel="nofollow noopener noreferrer">long integer (`Int64`)</a> type. Returns a file size in bytes.
4. <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.metadata/emaildocumentinfo/isencrypted" target="_blank" rel="nofollow noopener noreferrer">`IsEncrypted` property</a> of a <a href="https://docs.microsoft.com/en-us/dotnet/api/system.boolean?view=net-6.0" target="_blank" rel="nofollow noopener noreferrer">`Boolean`</a> type. Because email documents cannot be encrypted with password, this property always returns `false`.

Code example below displays extracting document info from three different Email documents of different formats. Source code is represented as a unit-test, written with NUnit framework.

```csharp
const string emlFilename = "Attachments.eml";
string emlInputPath = System.IO.Path.Combine(Common.TestHelper.EmailFolder, emlFilename);

const string msgFilename = "ComplexExample.msg";
string msgInputPath = System.IO.Path.Combine(Common.TestHelper.EmailFolder, msgFilename);

const string pstFilename = "PersonalStorage.pst";
string pstInputPath = System.IO.Path.Combine(Common.TestHelper.EmailFolder, pstFilename);

Editor emlEditor = new Editor(emlInputPath);
Editor msgEditor = new Editor(msgInputPath);
Editor pstEditor = new Editor(pstInputPath);

IDocumentInfo emlDocInfo = emlEditor.GetDocumentInfo(null);
IDocumentInfo msgDocInfo = msgEditor.GetDocumentInfo(null);
IDocumentInfo pstDocInfo = pstEditor.GetDocumentInfo(null);

Assert.IsTrue(emlDocInfo is EmailDocumentInfo);
Assert.IsTrue(msgDocInfo is EmailDocumentInfo);
Assert.IsTrue(pstDocInfo is EmailDocumentInfo);

Assert.AreEqual(GroupDocs.Editor.Formats.EmailFormats.Eml, emlDocInfo.Format);
Assert.AreEqual(GroupDocs.Editor.Formats.EmailFormats.Msg, msgDocInfo.Format);
Assert.AreEqual(GroupDocs.Editor.Formats.EmailFormats.Pst, pstDocInfo.Format);

emlEditor.Dispose();
msgEditor.Dispose();
pstEditor.Dispose();
```
