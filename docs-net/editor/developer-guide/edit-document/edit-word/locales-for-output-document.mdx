<a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingsaveoptions" target="_blank" rel="nofollow noopener noreferrer">WordProcessingSaveOptions</a> class contains 3 very similar properties of the same type `System.Globalization.CultureInfo`:

```csharp
public System.Globalization.CultureInfo Locale { get; set; }
public System.Globalization.CultureInfo LocaleBi { get; set; }
public System.Globalization.CultureInfo LocaleFarEast { get; set; }
```

In most cases the output WordProcessing document, which is generated from the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a> instance by the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor/save" target="_blank" rel="nofollow noopener noreferrer">`editor.Save()</a> method, contains valid locales for the textual content. But in some cases it is necessary to forcibly and explicitly set a some specific locale for the output document. These three options provide such possibility. However keep in mind that they are suitable only when document should have some single locale. If document is multi-language and contains, for example, English and Spanish text, setting the locale to English ("en-GB", for example) will mark the Spanish text as English too, so spell checking in MS Word, for example, will not work properly for such text.

By default all these three locale-related properties are not specified, their values are NULL. In such case MS Word (or other program) will detect (or choose) the document locale according to its own settings or other factors. Additionally, if document is multi-language, it is strongly encouraged to enable the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingeditoptions/enablelanguageinformation" target="_blank" rel="nofollow noopener noreferrer">`EnableLanguageInformation`</a> property in the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingeditoptions" target="_blank" rel="nofollow noopener noreferrer">WordProcessingEditOptions</a> class while editing original document, and not to use these 3 properties.

The <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingsaveoptions/locale" target="_blank" rel="nofollow noopener noreferrer">`Locale`</a> property is intended to set the locale for usual left-to-right text, which consists of letters.  
The <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingsaveoptions/localebi" target="_blank" rel="nofollow noopener noreferrer">`LocaleBi`</a> property should be used when text is right-to-left (RTL), for example, <a href="https://en.wikipedia.org/wiki/Arabic_script" target="_blank" rel="nofollow noopener noreferrer">Arabic script</a> or <a href="https://en.wikipedia.org/wiki/Hebrew_alphabet" target="_blank" rel="nofollow noopener noreferrer">Hebrew alphabet</a>.  
The <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingsaveoptions/localefareast" target="_blank" rel="nofollow noopener noreferrer">`LocaleFarEast`</a> property should be used for East-Asian (Far-East) text, including <a href="https://en.wikipedia.org/wiki/CJK_characters" target="_blank" rel="nofollow noopener noreferrer">CJK characters</a>.
