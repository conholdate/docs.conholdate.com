The <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingsaveoptions/password" target="_blank" rel="nofollow noopener noreferrer">Password</a> property, if set, enables document protection from opening by encrypting it with specified password. However, almost all WordProcessing formats support a document protection from writing, which is completely different from opening. Document protection, like document encoding, also implies a password as a form of key, but it also supports different levels of protection: some of them allow only read-only mode, other allow to edit form-fields etc.

<a href="https://products.groupdocs.com/editor/net" target="_blank" rel="nofollow noopener noreferrer">**GroupDocs.Editor**</a> allows to apply the document protection via the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingsaveoptions/protection" target="_blank" rel="nofollow noopener noreferrer">Protection</a> property in the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingsaveoptions" target="_blank" rel="nofollow noopener noreferrer">WordProcessingSaveOptions</a> class. By default this property has a NULL value, which means that GroupDocs.Editor will not apply the protection to the document.

The <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingsaveoptions/protection" target="_blank" rel="nofollow noopener noreferrer">Protection</a> property has a <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingprotection" target="_blank" rel="nofollow noopener noreferrer">WordProcessingProtection</a> type. This type is a class, which, it turn, consists of two properties: <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingprotection/password" target="_blank" rel="nofollow noopener noreferrer">Password</a> and a <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingprotection/protectiontype" target="_blank" rel="nofollow noopener noreferrer">ProtectionType</a>.

<a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingprotection" target="_blank" rel="nofollow noopener noreferrer">WordProcessingProtection</a> class has two constructors. <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingprotection/wordprocessingprotection/#constructor" target="_blank" rel="nofollow noopener noreferrer">First one</a> is parameterless, it sets both class properties to their default values. If user will use this constructor, and then will not set values to the properties in class instance, the protection will not be applied to the document. <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingprotection/wordprocessingprotection/#constructor_1" target="_blank" rel="nofollow noopener noreferrer">Second constructor</a>, in counterpart, has two parameters, which set values to the properties; so, when using this constructor, there is no need to use properties at all.

The <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingprotection/password" target="_blank" rel="nofollow noopener noreferrer">Password</a> property is responsible for setting a password for the document protection. By default it is NULL - protection is not applied. If user wants to apply the document protection, he *needs* to assign some string to this property (through <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingprotection/wordprocessingprotection/#constructor_1" target="_blank" rel="nofollow noopener noreferrer">constructor</a> or property itself); otherwise protection will not be applied regardless from the value of the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingprotection/protectiontype" target="_blank" rel="nofollow noopener noreferrer">ProtectionType</a> property.

<a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingprotection/protectiontype" target="_blank" rel="nofollow noopener noreferrer">ProtectionType</a> property has type <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingprotectiontype" target="_blank" rel="nofollow noopener noreferrer">WordProcessingProtectionType</a>, which is a simple enum, and value of this enum determines the level of protection. By default enum has a `NoProtection` value, which means that no protection will be applied. Other values are:

1. `AllowOnlyRevisions` - User can only add revision marks to the document.
2. `AllowOnlyComments` - User can only modify comments in the document.
3. `AllowOnlyFormFields` - User can only enter data in the form fields in the document.
4. `ReadOnly` - No changes are allowed to the document.

Take a note that both the properties <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingprotection/password" target="_blank" rel="nofollow noopener noreferrer">Password</a> and a <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingprotection/protectiontype" target="_blank" rel="nofollow noopener noreferrer">ProtectionType</a> are bound to each other. If user set a valid non-NULL not-empty <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingprotection/password" target="_blank" rel="nofollow noopener noreferrer">Password</a>, but the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingprotection/protectiontype" target="_blank" rel="nofollow noopener noreferrer">ProtectionType</a> property has a <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingprotectiontype" target="_blank" rel="nofollow noopener noreferrer">WordProcessingProtectionType</a>. `NoProtection` value, the protection will not be applied. And vice versa, if <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingprotection/protectiontype" target="_blank" rel="nofollow noopener noreferrer">ProtectionType</a> property has a `AllowOnlyFormFields` value, for example, but <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingprotection/password" target="_blank" rel="nofollow noopener noreferrer">Password</a> is NULL or empty string, then the protection will not be applied too.
