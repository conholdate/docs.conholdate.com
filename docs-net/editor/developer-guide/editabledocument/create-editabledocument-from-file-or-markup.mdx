> This demonstration shows how to create instance of the EditableDocument class from HTML files from disk or from HTML markup with resources

## Introduction

When working with <a href="https://products.groupdocs.com/editor/net" target="_blank" rel="nofollow noopener noreferrer">**GroupDocs.Editor**</a> in usual way by loading, opening, editing and saving documents, the instances of <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a> class are produced by the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor/edit" target="_blank" rel="nofollow noopener noreferrer">Editor.Edit</a> method and accepted by the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor/save" target="_blank" rel="nofollow noopener noreferrer">Editor.Save</a> method. However, in some cases it is required to create a <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a> instance from existing HTML markup with optional resources. For example, some document was loaded to `Editor` class, opened for editing, and then <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a> was saved to the disk as a set of HTML file and connected resources. Then this HTML document was passed to the WYSIWYG-editor, edited, and save back to the disk as modified HTML. Or raw output from the WYSIWYG-editor was saved to the `string` variable. In order to save it to some final format like DOCX or XLSX, user needs to pass the document to the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor/save" target="_blank" rel="nofollow noopener noreferrer">Editor.Save</a> method in a form of <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a> instance. This means that user should create an instance of <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a> class manually.

<a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a> contains three public static methods for creating its instances: <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument/fromfile" target="_blank" rel="nofollow noopener noreferrer">FromFile</a>, <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument/frommarkup" target="_blank" rel="nofollow noopener noreferrer">FromMarkup</a> and <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument/frommarkupandresourcefolder" target="_blank" rel="nofollow noopener noreferrer">FromMarkupAndResourceFolder</a>. Before version 21.10 there also was a method <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument/frommarkupandresourcefolder/" target="_blank" rel="nofollow noopener noreferrer">FromBodyMarkupAndResourceFolder</a>, but then it was removed due to its uselessness. This article reviews all of them.

## Opening from file

Let's suppose that we have an HTML file with edited document content, that is saved on the disk. There is also a folder with resources (images, fonts, stylesheets), that are used by this document, and document has correct links to this resources. Let's say, HTML document has name "document.html" and is located in the "input" folder. Resource folder is located in the same "input" folder and has name "document\_resources". And, what is most important, HTML markup from "document.html" has proper links to files from "document\_resources" folder. For example, there will be

&lt;link rel = "stylesheet" type = "text/css" href = "document\_resources/style.css" /&gt;

in the "document.html", and "document\_resources" folder actually contains "style.css" file.

In that case creating the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a> instance is the most simple:

```csharp
string inputHtmlPath = "C://input/document.html";
EditableDocument document = EditableDocument.FromFile(inputHtmlPath, null);
```

The <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument/fromfile" target="_blank" rel="nofollow noopener noreferrer">FromFile</a> method accepts two parameters, where first is a path to HTML file, while second is a path to resource folder. If HTML file contains correct links, as it is described above, second parameter is not necessary: GroupDocs.Editor will scan the links and automatically find the resource folder and correct resources. However, if path to resource folder doesn't match to the links in HTML file, it is possible to specify a resource folder forcibly, what is illustrated in code below:

```csharp
string inputHtmlPath = "C://input/document.html";
string inputResourceFolderPath = "C://input/document_resources/";
EditableDocument document = EditableDocument.FromFile(inputHtmlPath, inputResourceFolderPath);
```

If HTML file contains a link to same resource, that is not present in the resource folder, it will be omitted.

## Opening from markup and prepared resources

In some cases edited HTML document is not present as a file. It may be stored in database, obtained from remote storage, or something else. In such cases <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a> class delivers a <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument/frommarkup" target="_blank" rel="nofollow noopener noreferrer">FromMarkup</a> method. This method, like previous, has two parameters:

* `string newHtmlContent` - string, that contains raw HTML markup. This parameter is mandatory.
* IEnumerable&lt;<a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.htmlcss.resources/ihtmlresource" target="_blank" rel="nofollow noopener noreferrer">IHtmlResource</a>&gt;&gt; resources - this is a set of prepared resources (images, fonts, stylesheets, audio files), that are used or may be used in the HTML document. User needs to prepare this collection by himself. This parameter is optional, user may pass NULL or empty collection. As with previous method, if HTML markup refers to some resource, that is not found in "resources" collection, than it will be skipped (omitted).

The code example below demonstrates this approach.

```csharp
string inputHtmlMarkup = "<HTML><HEAD><TITLE>Edited document</TITLE>.....";
JpegImage image1 = new JpegImage("image1.jpg", /* stream or base64 text*/);
PngImage image2 = new PngImage("image2.png", /* stream or base64 text*/);
CssText stylesheet = new CssText("stylesheet.css", "p {color: black; text-align: left; }......", System.Text.Encoding.UTF8);

List<IHtmlResource> allResources = new List<IHtmlResource>();
allResources.Add(image1);
allResources.Add(image2);
allResources.Add(stylesheet);

EditableDocument document = EditableDocument.FromMarkup(inputHtmlMarkup, allResources);
```

Starting from the <a href="https://releases.groupdocs.com/editor/net/release-notes/2025/groupdocs-editor-for-net-25-7-release-notes/" target="_blank" rel="nofollow noopener noreferrer">version 25.7</a> a new simplified overload of the `FromMarkup` method was implemented: `EditableDocument.FromMarkup(string newHtmlContent)`. This overload is useful when there is no any external HTML resources for the given HTML markup. This usually happens when the whole document content with HTML- and CSS-markup and all the resources is packed inside a single string (resources are packed to the HTML-markup using the <a href="https://en.wikipedia.org/wiki/Data_URI_scheme" target="_blank" rel="nofollow noopener noreferrer">data URI scheme</a> with base64 encoding). So, in case when the `inputHtmlMarkup` string variable from the example above contains all resources inside it, and there are no any external images, fonts, or stylesheets, the whole example above can be rewritten as below:

## Opening from markup and resource folder

In some cases there is an HTML markup of edited document, but resources are represented as a set of files, located in some specific folder. For example, original document was converted to <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a> and then saved to the disk as an HTML document with *.html file and a folder with resources. Then it was loaded to the WYSIWYG-editor, edited by the end-user, and edited content was obtained back from the front-end to the back-end. So now there is an edited HTML markup, available as a stream, and a resource folder. In such case a new method <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument/frommarkupandresourcefolder" target="_blank" rel="nofollow noopener noreferrer">FromMarkupAndResourceFolder</a> was introduced in version 21.10. Here is an example of its usage.

```csharp
string inputHtmlMarkup = "<HTML><HEAD><TITLE>Edited document</TITLE>.....";
string inputResourceFolderPath = "C://input/document_resources/";
  
EditableDocument document = EditableDocument.FromMarkupAndResourceFolder inputHtmlMarkup, inputResourceFolderPath);
```

The <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument/frommarkupandresourcefolder" target="_blank" rel="nofollow noopener noreferrer">FromMarkupAndResourceFolder</a> method obtains two parameters of a <a href="https://docs.microsoft.com/en-us/dotnet/api/system.string?view=net-5.0" target="_blank" rel="nofollow noopener noreferrer">string</a> type, both of which are mandatory. First one - `newHtmlContent` -  is a HTML markup, while second - `resourceFolderPath` - a full valid path to the resource folder, which do exist and contains the resources. If the folder doesn't exist, an exception will be thrown.

A lot of (or even most) WYSIWYG-editors modify the HTML structure of a document by removing the HTML, HEAD, BODY elements and some others, even a whole HEAD-block with metadata. In fact, most of client-side WYSIWYG HTML-editors like TinyMCE and CKEditor are working only with inner content of BODY element: they can obtain only such markup on input and produce such markup on output. External stylesheet(s) are usually included in the HTML-editor settings or somewhere else, but not through HTML-markup (excepting the inline styles in the "style" attribute). For passing a HTML->BODY markup _into_ the HTML-editor there is a <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument/getbodycontent" target="_blank" rel="nofollow noopener noreferrer">GetBodyContent()</a> method, that returns an inner content of HTML-BODY element. Problem is that when edited HTML markup is obtained back from WYSIWYG-editor, it usually doesn't contain links to the external stylesheets at all.

The <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument/frommarkupandresourcefolder" target="_blank" rel="nofollow noopener noreferrer">FromMarkupAndResourceFolder</a> method is very useful in especially such cases, because it scans the resource folder, specified in a `resourceFolderPath` parameter, reads all found *.css files, and applies parsed stylesheets to the document content. This is the main distinction between this method and previously described <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument/fromfile" target="_blank" rel="nofollow noopener noreferrer">FromFile</a>, - this one applies all stylesheets in the folder to the document, while <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument/fromfile" target="_blank" rel="nofollow noopener noreferrer">FromFile</a> applies only those stylesheets, which are explicitly referenced from HTML markup.

So, concluding. When the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument/frommarkupandresourcefolder" target="_blank" rel="nofollow noopener noreferrer">FromMarkupAndResourceFolder()</a> is invoked, the GroupDocs.Editor scans a folder, specified in the `resourceFolderPath` parameter, founds all *.css files, opens them, parses their content, and if this content is valid, applies these stylesheets for the document. If any stylesheet is referencing on external images and/or fonts, GroupDocs.Editor will try to find these resources in this resource folder too. Also, if HTML markup, specified in the 1st parameter, contains external images, referenced using an IMG element, GroupDocs.Editor will try to find these images in this resource folder too. In other words, the <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument/frommarkupandresourcefolder" target="_blank" rel="nofollow noopener noreferrer">FromMarkupAndResourceFolder()</a> method "assumes" that the `resourceFolderPath` contains resources for that specific HTML document, which markup is specified in the 1st parameter.
