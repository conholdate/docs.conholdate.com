Docker proporciona un entorno aislado para servicios y aplicaciones. En este tema contenedorizamos una aplicación de ejemplo que utiliza GroupDocs.Viewer. Puede obtener más información sobre la contenerización en <a href="https://learn.microsoft.com/en-us/dotnet/core/docker/introduction" rel="nofollow">Introducción a .NET y Docker</a>.

Ejecutar GroupDocs.Viewer en Docker es sencillo. En primer lugar, preparamos una aplicación de ejemplo que utiliza el paquete <a href="https://www.nuget.org/packages/GroupDocs.Viewer.CrossPlatform" rel="nofollow">GroupDocs.Viewer.CrossPlatform</a> de NuGet y, a continuación, compilamos una imagen de Docker y ejecutamos la aplicación en un contenedor de Docker.

En este artículo de documentación utilizaremos <a href="https://learn.microsoft.com/en-us/dotnet/architecture/microservices/net-core-net-framework-containers/official-net-docker-images" rel="nofollow">la imagen oficial de Docker para .NET</a>, que se basa en la distribución de Linux Debian.

## Requisitos previos

**Docker:** Docker debe estar instalado en su sistema. Consulte la documentación oficial de Docker para obtener instrucciones detalladas de instalación en <a href="https://docs.docker.com/get-docker/" rel="nofollow">Instalar Docker</a>.

**Aplicación .NET:** En este tema ejecutaremos una aplicación de ejemplo basada en .NET 8. Puede descargarla desde [aquí](/net/viewer/v26.4.0/sample-files/how-to-run-groupdocs-viewer-in-docker/DemoApp.zip). Como alternativa, puede utilizar su propia aplicación basada en los fragmentos de código proporcionados a continuación.

```xml
    </None>
  </ItemGroup>

```

<TabItem value="program-cs" label="Program.cs">

```cs
using GroupDocs.Viewer;
using GroupDocs.Viewer.Options;
// ...

namespace DemoApp
{
    class Program
    {
        static void Main(string[] args)
        {
            // Instantiate Viewer and pass file name
            using (Viewer viewer = new Viewer("formatting.docx"))
            {
                // Configure view options
                HtmlViewOptions viewOptions =
                    HtmlViewOptions.ForEmbeddedResources("output/page-{0}.html");

                // Render DOCX to HTML
                viewer.View(viewOptions);
            }
        }
    }
}
```

## Agregar Dockerfile

Para crear una imagen de Docker, agregue un archivo `Dockerfile` y un archivo `.dockerignore` a su proyecto. 

<Tabs groupId="dockerfile">

<TabItem value="dockerfile" label="Dockerfile" default>

```Dockerfile
FROM mcr.microsoft.com/dotnet/sdk:8.0
WORKDIR /app

# Add `contrib` archive area to package sources list
RUN sed -i 's/^Components: main$/& contrib/' /etc/apt/sources.list.d/debian.sources

# Download the package lists from the repositories
# and install two packages `fontconfig` and `ttf-mscorefonts-installer`
RUN apt update && apt install -y \
    fontconfig \
    ttf-mscorefonts-installer 

# Copy the application and restore packages
COPY . .
RUN dotnet restore 

# Run the application
ENTRYPOINT ["dotnet", "run"]
```

</TabItem>

<TabItem value="dockerignore" label=".dockerignore">

```txt
**/.dockerignore
**/Dockerfile*
**/.vs
**/.vscode
**/*.*proj.user
**/bin
**/obj
```

</TabItem>

</Tabs>

En este punto, el árbol de carpetas debería verse similar a la siguiente estructura de directorios:

```Directory
📂 DemoApp
 ├──DemoApp.csproj
 ├──Program.cs
 ├──formatting.docx
 ├──Dockerfile
 └──.dockerignore
```

El `Dockerfile` contiene instrucciones para instalar dos dependencias requeridas por GroupDocs.Viewer:

**fontconfig:** Esta biblioteca configura y personaliza el acceso a las fuentes.

**ttf-mscorefonts-installer:** Este paquete proporciona las fuentes core TrueType de Microsoft. Está disponible en el área de repositorio <a href="https://www.debian.org/doc/debian-policy/ch-archive#s-contrib" rel="nofollow">contrib</a>. (Nota: El uso de fuentes no libres puede tener implicaciones de licencia; por lo tanto, asegúrese de revisar los términos de la licencia.)

## Compilación de la imagen Docker

En este punto ya estamos listos para compilar la imagen Docker. Asegúrese de que Docker esté activo y en ejecución, diríjase al directorio `DemoApp` y ejecute el siguiente comando en la línea de comandos para compilar la imagen.

```bash
docker build -t viewer-demo-app .
```

`-t`: se utiliza para nombrar y etiquetar la imagen. Nombramos la imagen como `viewer-demo-app` sin etiqueta.

`.`: ruta del contexto de compilación. En este ejemplo, es el directorio actual.

## Ejecutar el contenedor de Docker

Para ejecutar nuestra aplicación contenida en un contenedor, utilice el siguiente comando en el directorio `DemoApp`.

```bash
docker run --rm -v ${pwd}/output:/app/output viewer-demo-app
```

`--rm`: Elimina el contenedor y limpia el sistema de archivos al finalizar.

`-v ${pwd}/output:/app/output`: Mapea el directorio `./output` del sistema operativo anfitrión al directorio `/app/output` dentro del contenedor Docker.

Después de ejecutar la aplicación, el directorio `./output` contendrá dos archivos: `page-1.html` y `page-2.html`, debido a las limitaciones de la versión de evaluación. Para procesar todos los archivos, debe configurar una licencia válida. Obtenga más información sobre las limitaciones de la evaluación y la versión de prueba gratuita en [Cómo evaluar GroupDocs.Viewer](/net/viewer/v26.4.0/licensing-and-evaluation/).
