## Renderizado de documentos

Utilizamos el termino ["renderizado"](/net/viewer/developer-guide/rendering-documents/) en GroupDocs.Viewer para describir el proceso de convertir un documento en un formato de archivo paginado o que tenga el concepto de paginas. Por ejemplo, si tiene un archivo DOCX con tres paginas, al renderizar este archivo a HTML obtendra tres archivos HTML en la salida, cada uno representando una de las paginas del documento.

![Rendering diagram](/net/viewer/images/getting-started/features-overview/rendering.png)

### Renderizado a HTML

El renderizado a HTML es la opcion mas adecuada cuando se cumplen los siguientes requisitos:

* Estas desarrollando una aplicacion basada en web;
* El contenido del documento debe mostrarse dentro de un navegador web;
* Necesitas la capacidad de interactuar con el texto del documento renderizado: seleccionarlo, copiarlo o buscar en el;
* Deseas visualizar las paginas del documento por separado;
* Necesitas ampliar (zoom) el documento sin perdida de calidad en la mayoria de los casos;
* Quieres rotar, reordenar paginas o anadir marcas de agua.

GroupDocs.Viewer for .NET ofrece dos opciones para la gestion de recursos (CSS, fuentes, imagenes, etc.):

* **Renderizado a HTML con recursos externos**: almacena los recursos de la pagina junto al archivo HTML, lo que permite reutilizar recursos comunes entre paginas distintas y reduce significativamente el tamano y el tiempo de carga de cada pagina.
* **Renderizado a HTML con recursos incrustados**: integra todos los recursos de la pagina directamente en el HTML, haciendo que cada pagina del documento sea autonoma. La desventaja es que el tamano de la pagina y el tiempo de carga pueden aumentar.

### Renderizado a PNG o JPEG

El renderizado a PNG o JPEG es la opcion mas adecuada cuando se cumplen los siguientes requisitos:

* Estas desarrollando cualquier tipo de aplicacion;
* No necesitas renderizar contenido textual o deseas restringir la interaccion con el texto del documento renderizado. Por ejemplo: evitar la copia de texto. Aun asi, sigues teniendo la posibilidad de extraer el texto del documento si deseas anadir una capa de texto seleccionable sobre la imagen de la pagina (descrita a continuacion);
* Deseas visualizar las paginas del documento por separado;
* Quieres rotar, reordenar paginas o anadir marcas de agua.

A continuacion se presenta una breve descripcion de ambos formatos de imagen, la cual puede ayudarte a elegir el mas adecuado para tu caso:

* **Formato PNG**: es un formato de graficos rasterizados sin perdida que admite imagenes a todo color y soporta transparencia. No es posible ajustar la calidad de la imagen PNG guardada. PNG es una buena opcion para almacenar dibujos a linea, texto y graficos iconicos con tamanos de archivo reducidos.
* **Formato JPEG**: es un formato de archivo con compresion con perdida que permite ajustar la calidad de la imagen guardada: al reducirse la calidad, se eliminan detalles y se anade ruido a la imagen, aunque el tamano del archivo se vuelve mas compacto. JPEG es optimo para imagenes con un gran numero de colores (por ejemplo, fotografias). Es una opcion habitual en la web debido a su eficaz compresion.

### Renderizado a PDF

GroupDocs.Viewer renderiza un documento como un unico archivo PDF, por lo que el renderizado a PDF es la opcion mas adecuada cuando se cumplen los siguientes requisitos:

* Vas a imprimir documentos;
* Deseas enviar documentos por correo electronico;
* No deseas mostrar las paginas del documento por separado, ya que todas las paginas del documento original se renderizan como un unico archivo PDF.

## Obtencion de informacion del documento

GroupDocs.Viewer for .NET permite obtener informacion basica sobre los documentos fuente, como el tipo de archivo, el numero de paginas, el texto con coordenadas, etc.

Para los siguientes formatos de documento, tambien es posible extraer informacion adicional:

* **Archivos comprimidos (archives)**: lista de carpetas contenidas en el archivo;
* **CAD**: lista de capas y disenos en un documento CAD;
* **Correo electronico (email)**: lista de carpetas contenidas en un archivo de datos de Outlook;
* **PDF**: informacion sobre las restricciones de impresion del documento;
* **Gestion de proyectos (Project Management)**: fechas de inicio y finalizacion del proyecto.

### Extraccion de texto

Puedes optar por extraer el texto del documento al renderizar a PNG o JPEG, y el texto puede extraerse junto con las coordenadas de cada palabra individual.

Esto puede resultar util si deseas anadir una capa de texto seleccionable sobre la imagen de la pagina.

## Procesamiento de adjuntos

En GroupDocs.Viewer utilizamos el termino *adjuntos* para referirnos a archivos adjuntos de correo electronico, archivos incrustados y archivos comprimidos.

Con GroupDocs.Viewer puedes listar y guardar:

* Archivos adjuntos de correo electronico;
* Archivos incrustados en documentos PDF;
* Mensajes de correo electronico contenidos en archivos de datos de Outlook y LotusNotes;
* Archivos comprimidos.

## Transformacion de salida

GroupDocs.Viewer for .NET proporciona un conjunto de opciones para aplicar distintas transformaciones a las paginas del documento:

* **Rotar paginas**: cambiar la orientacion de las paginas al renderizar a HTML, JPG, PNG y PDF;
* **Anadir marca de agua de texto**: anadir una marca de agua de texto a cada pagina renderizada;
* **Reordenar paginas**: renderizar las paginas en el orden que prefieras o reordenarlas al renderizar a PDF.

## Almacenamiento en cache de resultados

GroupDocs.Viewer for .NET proporciona una API de visor de documentos que admite almacenamiento en cache para acelerar la carga de documentos y optimizar el rendimiento de la aplicacion.

De forma predeterminada, la cache de documentos se guarda en el disco local. No obstante, la API del visor de documentos tambien proporciona interfaces para la cache de documentos que pueden implementarse para admitir almacenamientos de terceros: FTP, Amazon S3, Dropbox, Google Drive, Microsoft Azure, Redis o cualquier otro.
