GroupDocs.Viewer dispone de una funcionalidad para recopilar y devolver todas las fuentes utilizadas dentro del documento, cargadas en la instancia de la clase <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer" target="_blank" rel="nofollow noopener noreferrer">`Viewer`</a>. Estas fuentes se devuelven como un array, donde cada elemento representa una única fuente con sus metadatos y contenido binario. GroupDocs.Viewer puede devolver tanto las fuentes incrustadas dentro del documento (almacenadas en el propio archivo del documento) como las fuentes del sistema, que se almacenan en la carpeta del sistema operativo y están _utilizadas_ en el contenido textual del documento. Es necesario mencionar que algunos formatos de documento pueden contener fuentes que están referenciadas o incluso almacenadas dentro del documento, pero que no se aplican al texto del mismo; GroupDocs.Viewer intenta detectar y excluir dichas fuentes de la lista devuelta.

Asimismo, es necesario mencionar que GroupDocs.Viewer solo puede extraer y devolver fuentes de aquellos formatos de documento que _pueden tener_ fuentes. Por ejemplo, los formatos PDF, DOCX, XLSX, PPTX y otros formatos similares admiten y utilizan fuentes para representar su contenido textual, por lo que GroupDocs.Viewer puede encontrar y devolver estas fuentes. Sin embargo, formatos como texto sin formato (TXT), imágenes rasterizadas (como PNG y JPEG), archivos comprimidos, entre otros, no admiten fuentes. En caso de que se cargue uno de estos documentos en GroupDocs.Viewer y el usuario intente obtener la lista de fuentes, se devolverá un array vacío.

Para obtener las fuentes utilizadas en un documento determinado, dicho documento debe cargarse en una instancia de la clase <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer" target="_blank" rel="nofollow noopener noreferrer">`Viewer`</a> mediante uno de sus constructores. Tras cargar el documento, se debe invocar el método de instancia <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer/getallfonts/" target="_blank" rel="nofollow noopener noreferrer">`GetAllFonts()`</a>. Este método devuelve una lista con todas las fuentes utilizadas como un array de tipo `IFontInfo[]`, donde `IFontInfo` es una interfaz que describe una fuente con sus metadatos y contenido binario. Como ya se indicó anteriormente, si el documento dado no utiliza ninguna fuente o, debido a su formato, no puede utilizar fuentes (por ejemplo, archivos comprimidos o imágenes rasterizadas), se devolverá un array vacío.

El breve ejemplo de código siguiente demuestra cómo cargar un documento DOCX en la clase <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer" target="_blank" rel="nofollow noopener noreferrer">`Viewer`</a>, obtener la lista de todas las fuentes utilizadas y, a continuación, recorrer dicha lista y mostrar información sobre cada fuente incluida en ella.

using GroupDocs.Viewer;
// ...

const string filename = "sample.docx";
string inputPath = "\full\path\" + filename;

using (Viewer viewer = new Viewer(inputPath))
{
    Fonts.IFontInfo[] allFonts = viewer.GetAllFonts();
    Console.WriteLine("{0} fonts found in the '{1}' document", allFonts.Length, filename);
    foreach (Fonts.IFontInfo font in allFonts)
    {
        Console.WriteLine("Font '{0}' of {1} style has {2} bytes and is of {3} format",
            font.FamilyName,
            font.Style,
            font.Content.Length,
            font.Format);
    }
}

## Explicación de IFontInfo {#explaining-ifontinfo}

GroupDocs.Viewer admite la extracción de fuentes de 4 familias de formatos principales: PDF, Procesamiento de Texto, Hojas de Cálculo y Presentaciones, y cada una de ellas tiene un concepto ligeramente distinto de las fuentes. Por ejemplo, el contenido de la fuente puede estar incrustado dentro del documento PDF, de Procesamiento de Texto y de Presentación, pero no en la Hoja de Cálculo. Las fuentes de Procesamiento de Texto y Hoja de Cálculo proporcionan un número que representa un conjunto de caracteres, mientras que las de PDF y Presentación no lo hacen. Las fuentes de Procesamiento de Texto pueden tener nombres alternativos de fuente. Además, la sustitución de fuentes solo existe para los documentos de Procesamiento de Texto. Como resultado, cada familia de formatos tiene su propio tipo relacionado con las fuentes:

1. Procesamiento de Texto — `WordProcessingFontInfo` y `WordProcessingSubstitutedFontInfo`.
2. Hojas de Cálculo — `SpreadsheetFontInfo`.
3. Presentaciones — `PresentationFontInfo`.
4. PDF — `PdfFontInfo`.

Y la interfaz `IFontInfo` declara el conjunto mínimo de propiedades comunes a todos los tipos de fuentes:

- <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.fonts/IFontInfo/FamilyName/" target="_blank" rel="nofollow noopener noreferrer">`FamilyName`</a> de un <a href="https://learn.microsoft.com/en-us/dotnet/api/system.string" target="_blank" rel="nofollow noopener noreferrer">`System.String`</a>: nombre único de la familia de fuentes (sin incluir el nombre del estilo de fuente), nunca es nulo ni una cadena vacía.
- <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.fonts/IFontInfo/style/" target="_blank" rel="nofollow noopener noreferrer">`Style`</a> de un <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.fonts/fontstyles/" target="_blank" rel="nofollow noopener noreferrer">`FontStyles`</a>: estilo de la fuente dada. Puede ser uno de los siguientes valores: `Regular` (predeterminado), `Bold`, `Italic` y `BoldItalic`. La estructura <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.fonts/fontstyles/" target="_blank" rel="nofollow noopener noreferrer">`FontStyles`</a> representa todos los estilos de fuente posibles y proporciona propiedades convenientes para trabajar con ellos.
- <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.fonts/IFontInfo/content/" target="_blank" rel="nofollow noopener noreferrer">`Content`</a> de un `byte[]`: matriz de bytes que contiene el contenido completo de la fuente dada. En casos muy raros puede ser `null`, cuando la fuente es una fuente del sistema y el entorno de ejecución no puede obtener su contenido. Esto suele ocurrir en Linux.
- <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.fonts/IFontInfo/format/" target="_blank" rel="nofollow noopener noreferrer">`Format`</a> de un <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.fonts/fontformat/" target="_blank" rel="nofollow noopener noreferrer">`FontFormat`</a>: indica el formato de la fuente dada. Los formatos actualmente admitidos son: formato de fuente TrueType (TTF), formato de fuente OpenType (OTF), formato de colección de fuentes TrueType (TTC) y formato de fuente OpenType incrustada (EOT). Si GroupDocs.Viewer no puede obtener el contenido binario de una fuente del sistema (propiedad `Content` es `null`), esta propiedad puede devolver el valor `FontFormat.Unknown`.

**Nota importante**. Es necesario distinguir entre _familia de fuentes_ y _estilo de fuente_. Por ejemplo, un documento DOCX puede utilizar la familia de fuentes "Arial" tanto para texto normal, como para negrita, cursiva y negrita cursiva. En tal caso, GroupDocs.Viewer devolverá 4 instancias de <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.fonts/WordProcessingFontInfo/" target="_blank" rel="nofollow noopener noreferrer">`WordProcessingFontInfo`</a>; todas ellas tendrán el nombre de familia "Arial", pero distintos <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.fonts/fontstyles/" target="_blank" rel="nofollow noopener noreferrer">styles</a> ("Arial Regular", "Arial Bold", "Arial Italic", "Arial BoldItalic"), y cada una tendrá un contenido binario distinto.

## Explicación de la sustitución de fuentes {#explaining-font-substitution}

Existe un escenario bastante frecuente, aplicable únicamente a la familia de formatos de Procesamiento de Texto, en el que un documento como DOC/DOCX/DOCM se crea en la máquina del autor y utiliza fuentes _únicas_, que no están preinstaladas por defecto en el sistema operativo, sino que fueron instaladas manualmente en la máquina del autor. Posteriormente, este documento se transfiere a una máquina destino donde GroupDocs.Viewer se ejecuta e intenta extraer y devolver las fuentes. Sin embargo, el problema es que dichas fuentes únicas originales no están presentes en la máquina destino, y GroupDocs.Viewer no puede obtener su contenido.

En tal caso, GroupDocs.Viewer imita el comportamiento de Microsoft Word e inicia el **mecanismo de sustitución de fuentes**. Este es, de hecho, un algoritmo que reemplaza las fuentes ausentes por otras disponibles en la máquina destino y que se supone son las más similares a las fuentes faltantes. Dichas fuentes, que no se usaban en el documento original pero se seleccionan para reemplazar las fuentes ausentes, se denominan **sustitutas**. GroupDocs.Viewer proporciona un tipo especial para ellas: la estructura `WordProcessingSubstitutedFontInfo`. Este tipo contiene el nombre de familia y estilo de la fuente original ausente en la máquina destino, así como el nombre, formato y contenido binario de la fuente sustituta, que sí está presente y se utiliza en su lugar.

## Línea temporal {#timeline}

Inicialmente, la funcionalidad de extracción de fuentes se introdujo en la <a href="https://releases.groupdocs.com/viewer/net/release-notes/2025/groupdocs-viewer-for-net-25-3-release-notes/" target="_blank" rel="nofollow noopener noreferrer">versión 25.3</a>: existía un único tipo universal `UsedFontInfo` para representar cualquier información de fuente.

En la <a href="https://releases.groupdocs.com/viewer/net/release-notes/2025/groupdocs-viewer-for-net-25-6-release-notes/" target="_blank" rel="nofollow noopener noreferrer">versión 25.6</a>, la extracción de fuentes se mejoró, especialmente para la familia de formatos de Procesamiento de Texto, y la API pública sufrió ligeras modificaciones (se añadieron nuevas propiedades al tipo `UsedFontInfo`).

En la <a href="https://releases.groupdocs.com/viewer/net/release-notes/2025/groupdocs-viewer-for-net-25-9-release-notes/" target="_blank" rel="nofollow noopener noreferrer">versión 25.9</a>, la extracción de fuentes se reestructuró y mejoró significativamente, incluyendo el soporte para fuentes sustitutas en la familia de formatos de Procesamiento de Texto. Asimismo, la API pública sufrió cambios importantes: ahora cada familia de formatos tiene su propio tipo de información de fuente, que implementa la interfaz `IFontInfo`.
