## Limitaciones de la versión de evaluación {#evaluation-version-limitations}

Puede descargar fácilmente GroupDocs.Assembly para evaluación. La versión descargada para evaluación es idéntica a la versión adquirida. La versión de evaluación simplemente se convierte en una versión con licencia cuando agrega unas pocas líneas de código para aplicar la licencia. En caso de utilizar la API sin una licencia, se enfrentará a las siguientes limitaciones.  

| Documento | Hoja de cálculo | Presentación |
| --- | --- | --- |
| GroupDocs.Assembly (sin una licencia especificada) genera informes de documentos con todas las funcionalidades del producto, pero inserta una marca de agua de evaluación en la parte superior del documento | Al generar un informe de hoja de cálculo, este contiene una hoja adicional con una advertencia de derechos de autor de evaluación; no es posible ocultar dicha advertencia (la hoja adicional) | Al generar un informe de presentación mediante GroupDocs.Assembly, se inyecta una marca de agua de evaluación en el centro de cada diapositiva |
| Limita el tamaño máximo del documento a varios cientos de párrafos | Al ejecutar su programa, solo puede generar 100 informes de hojas de cálculo mediante GroupDocs.Assembly. Si su aplicación supera este número, se lanzará una excepción |  |
|  | No puede volver a especificar la ruta del script (por ejemplo, en el archivo web.config) |  |

## Licencia {#licensing}

El archivo de licencia contiene detalles como el nombre del producto, el número de desarrolladores a los que está licenciado, la fecha de vencimiento de la suscripción, entre otros. Contiene una firma digital, por lo que no debe modificar el archivo. Incluso la adición accidental de un salto de línea adicional invalidará el archivo. Debe establecer una licencia antes de utilizar la API de GroupDocs.Assembly si desea evitar sus limitaciones de evaluación. 

La licencia puede cargarse desde un archivo o desde un objeto de flujo (stream). La forma más sencilla de establecer una licencia es colocar el archivo de licencia en la misma carpeta que el archivo GroupDocs.Assembly.dll y especificar el nombre del archivo, sin ruta, como se muestra en los ejemplos siguientes.

:::info
Llamar a `License.SetLicense` varias veces no es perjudicial, pero simplemente desperdicia tiempo de procesamiento. Si está desarrollando una aplicación de Windows Forms o una aplicación de consola, invoque `License.SetLicense` en su código de inicio, antes de utilizar las clases de GroupDocs.Assembly.

Al desarrollar una aplicación ASP.NET, puede invocar `License.SetLicense` desde el archivo `Global.asax.cs` (`Global.asax.vb`) dentro del método protegido `Application_Start`. Este método se ejecuta una única vez al iniciar la aplicación. No invoque `License.SetLicense` dentro de los métodos `Page_Load`, ya que esto provocaría que la licencia se cargara cada vez que se cargue una página web.
:::

### Aplicación de la licencia por medición {#applying-metered-license}


:::info
También puede configurar una licencia medible como alternativa al archivo de licencia. Se trata de un nuevo mecanismo de licencias que se utilizará junto con el método de licencias existente. Es útil para los clientes que desean ser facturados según el uso de las características de la API. Para obtener más detalles, consulte la sección de preguntas frecuentes sobre licencias medibles.
:::


A continuación se presentan los pasos sencillos para utilizar la clase `Metered`.

1.  Crear una instancia de la clase `Metered`.
2.  Pasar las claves pública y privada al método `SetMeteredKey`.
3.  Realizar el procesamiento (ejecutar la tarea).
4.  Llamar al método `GetConsumptionQuantity` de la clase `Metered`.
5.  Este método devolverá la cantidad/cantidad de solicitudes de API que ha consumido hasta el momento.
6.  Llamar al método `GetConsumptionCredit` de la clase `Metered` (desde la versión 19.7).
7.  Este método devolverá el crédito que ha consumido hasta el momento.
