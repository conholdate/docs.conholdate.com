GroupDocs.Assembly para .NET es una API que le permite generar documentos en formatos populares de *Microsoft Office* y archivos de correo electrónico, basándose en documentos plantilla y datos obtenidos de diversas fuentes, incluidas bases de datos, XML, JSON, OData, objetos de tipos .NET personalizados, documentos externos, entre otros. A continuación se presenta la lista de las características más destacadas que ofrece la API GroupDocs.Assembly:

*   Soporte para múltiples formatos de datos
*   Usar fórmulas y realizar operaciones secuenciales sobre datos
*   Aplicar mayúsculas, minúsculas, capitalización y primera letra en mayúscula a cadenas en la sintaxis de plantillas
*   La sintaxis de plantillas admite el formato de números ordinales, cardinales y alfabéticos.
*   Soporte de documentos de plantilla con variables personalizadas y comentarios de texto dentro de las etiquetas de sintaxis de plantilla
*   Insertar dinámicamente el contenido de nuestro documento en el informe
*   Configurar dinámicamente el color de fondo de documentos HTML y generar códigos de barras en informes
*   Insertar dinámicamente hipervínculos en informes y aplicar atributos al cuerpo del mensaje de correo electrónico
*   Adjuntar dinámicamente archivos a correos electrónicos
*   Soporte del campo siguiente (análogo al campo NEXT de Microsoft Word)
*   Actualizar campos durante el ensamblaje de documentos de procesamiento de texto
*   Aplicar fórmula durante la compilación de la hoja de cálculo
*   Formato de plantilla para elementos numéricos, de texto, de imagen, de fecha-hora y de gráficos
*   Formato condicional de elementos de texto de plantilla
*   Sintaxis de plantillas basada en Linq
*   Cambiar el formato del archivo ensamblado utilizando especificaciones explícitas o la extensión del archivo
*   Eliminación automática de párrafos vacíos
*   Generar varios tipos de informes, por ejemplo: gráficos, imágenes, tablas, listas y más
*   Errores de sintaxis en plantillas en línea en documentos generados en lugar de lanzar excepciones.
*   Cargar documentos de plantilla desde HTML con recursos y guardar los documentos ensamblados en Word, Excel, PowerPoint y correos electrónicos como HTML con recursos.

A continuación se detalla cómo se ofrecen las características, junto con su uso y límites.

### Soporte explícito para múltiples fuentes de datos {#explicit-support-for-multiple-data-sources}

Una nueva sobrecarga <a href="https://reference.groupdocs.com/net/assembly/groupdocs.assembly/documentassembler/methods/assembledocument/index" target="_blank" rel="nofollow noopener noreferrer">**DocumentAssembler.AssembleDocument**</a> se agrega en la nueva versión. Con esta sobrecarga, el usuario puede hacer referencia a múltiples objetos de origen de datos y sus miembros en la plantilla. La sobrecarga acepta un array de nombres de orígenes de datos y un array de orígenes de datos. Obtenga más información sobre el soporte para múltiples orígenes de datos en <a href="/es/net/assembly/developer-guide/advanced-usage/working-with-multiple-data-sources/">esto</a> artículo.

## Formatos, Elementos y Sintaxis de Plantillas {#template-formats-elements-and-syntax}

### Formatos de Documentos de Plantilla {#template-document-formats}

#### Formatos de documentos de procesamiento de texto {#word-processing-document-formats}

Los formatos de documentos de procesamiento de texto, incluidos los formatos de documento de Microsoft Word y los formatos de documento de OpenOffice, están admitidos. Para obtener más detalles, visite [Soporte para formatos de documentos de procesamiento de texto](/net/assembly/getting-started/supported-document-formats/#supportfor-word-processing-document-formats#SupportedDocumentFormats-SupportforWordProcessingDocumentFormats).

#### Formatos de documentos de hojas de cálculo {#spreadsheet-document-formats}

Los formatos de documentos de hojas de cálculo, incluidos el libro de Microsoft Excel y los formatos de documento de hoja de cálculo de OpenOffice, están admitidos. Para obtener más detalles, visite [Soporte para formatos de documentos de hojas de cálculo](/net/assembly/getting-started/supported-document-formats/#supportfor-spreadsheet-document-formats#SupportedDocumentFormats-SupportforSpreadsheetDocumentFormats).

#### Formatos de Documentos de Presentación {#presentation-document-formats}

Se admiten formatos de documentos de presentación, incluidos los formatos de presentación de Microsoft PowerPoint y OpenOffice. Para obtener más detalles, visite [Soporte para formatos de documentos de presentación](/net/assembly/getting-started/supported-document-formats/#supportfor-presentation-document-formats#SupportedDocumentFormats-SupportforPresentationDocumentFormats).

#### Formatos de Documentos de Correo Electrónico {#email-document-formats}

Los formatos de documento de correo electrónico son compatibles. Para más detalles, visite <a href="https://docs.asposeptyltd.com/display/assemblynet/Supported+Document+Formats#SupportedDocumentFormats-EmailDocumentFormats" target="_blank" rel="nofollow noopener noreferrer">Soporte para formatos de documentos de correo electrónico</a>.

#### Más formatos de documento {#more-document-formats}

Los formatos de documento HTML y texto plano son compatibles con la API de GroupDocs.Assembly. En futuras versiones se añadirán más formatos de documento, como PDF, EPUB y XPS. Para obtener más información, visite [Soporte para más formatos de documento](/net/assembly/getting-started/supported-document-formats/#supportformore-document-formats#SupportedDocumentFormats-SupportformoreDocumentFormats).

#### Fusión dinámica de celdas de tabla {#dynamic-merging-of-table-cells}

Puedes fusionar celdas de tabla con contenidos textuales iguales dentro de tus informes de forma dinámica utilizando la etiqueta **cellMerge**. Para obtener más detalles, visita <a href="/es/net/assembly/developer-guide/advanced-usage/working-with-table-reports/merging-table-cells-dynamically/">Fusión dinámica de celdas en tablas</a>.

#### Comentarios textuales dentro de las etiquetas de sintaxis de plantilla {#textual-comments-within-template-syntax-tags}

Un comentario opcional que proporciona una explicación legible por humanos e ignorado por el motor

```csharp
<<tag_name [expression] -switch1 -switch2 ... // optional_comment >>
```

#### Incorporación de mensajes de error de sintaxis directamente en plantillas {#in-lining-of-syntax-error-messages-into-templates}

Incorporación de mensajes de error de sintaxis directamente en las plantillas, en lugar de lanzar excepciones. Para más detalles, consulte <a href="/es/net/assembly/developer-guide/advanced-usage/use-of-in-line-syntax-error-messages-into-templates/">Uso de mensajes de error de sintaxis incorporados en plantillas</a>.

### Formatos de sintaxis de plantilla para resultados de expresiones {#template-syntax-formats-for-expression-results}

#### Especificación de formatos de cadena {#specifying-string-formats}

La API ofrece una funcionalidad útil para dar formato a cadenas en la sintaxis de plantillas. El formato de cadenas incluye, por ejemplo, conversión a mayúsculas, minúsculas, capitalización, etc.

| Formato de cadena | Descripción |
| --- | --- |
| lower | Convierte una cadena a minúsculas ("la cadena") |
| upper | Convierte una cadena a mayúsculas ("LA CADENA") |
| caps | Capitaliza la primera letra de cada palabra en una cadena ("La Cadena") |
| firstCap | Capitaliza la primera letra de la primera palabra en una cadena ("La cadena") |

#### Especificación de formatos numéricos {#specifying-numeric-formats}

Mediante GroupDocs.Assembly para .NET, los usuarios también pueden aplicar formato numérico en la sintaxis de plantillas. El formato numérico incluye, por ejemplo, notación ordinal, cardinal, alfabética, etc.

| Formato numérico | Descripción |
| --- | --- |
| alphabetic | Formatea un número entero como una letra mayúscula (A, B, C, ...) |
| roman | Formatea un número entero como un numeral romano mayúsculo (I, II, III, ...) |
| ordinal | Añade un sufijo ordinal a un número entero (1.º, 2.º, 3.º, ...) |
| ordinalText | Convierte un número entero a su representación textual ordinal (Primero, Segundo, Tercero, ...) |
| cardinal | Convierte un número entero a su representación textual cardinal (Uno, Dos, Tres, ...) |
| hex | Formatea un número entero en hexadecimal (8, 9, A, B, C, D, E, F, 10, 11, ...) |
| arabicDash | Encierra un número entero entre guiones (- 1 -, - 2 -, - 3 -, ...) |

#### Variables en documentos de plantilla {#variables-in-template-documents}

La API permite a los usuarios definir variables en documentos de plantilla de la siguiente manera:

```csharp
<<var [st = "Hello, "]>><<[st]>><<var[st = "World!"]>><<[st]>>
```

### Configuración dinámica del color de fondo {#setting-background-color-dynamically}

Para <a href="/es/net/assembly/developer-guide/advanced-usage/working-with-list-reports-bulleted/bulleted-list-in-html-document/">documentos HTML</a>, no es posible configurar dinámicamente el color de fondo mediante la etiqueta backColor

```csharp
<<backColor ["red"]>>text with red background<</backColor>>

```

Además, puede utilizar el atributo `style` de HTML para lograr esto.

### Configuración dinámica de atributos del mensaje de correo electrónico {#setting-email-message-attributes-dynamically}

Además del cuerpo del mensaje de correo electrónico, puede utilizar GroupDocs.Assembly para configurar dinámicamente los siguientes atributos del mensaje de correo electrónico mediante la misma sintaxis de plantilla:

*   Asunto
*   De
*   Para
*   CC
*   CCO

Por ejemplo, dado que `recipients` es una enumeración de cadenas "Named Recipient &lt;named@example.com&gt;" y "unnamed@example.com", puede utilizar la siguiente plantilla para establecer el atributo `To` de un mensaje de correo electrónico.

```csharp
<<foreach [r in recipients]>><<[r]>>; <</foreach>>

```

Durante el tiempo de ejecución, el atributo `To` se establece en el siguiente valor.

```csharp
Named Recipient <named@example.com>; unnamed@example.com

```

### Generación dinámica de archivos adjuntos en mensajes de correo electrónico {#building-email-message-attachments-dynamically}

GroupDocs.Assembly le permite generar dinámicamente el contenido de los documentos adjuntos a mensajes de correo electrónico. Para lograrlo, adjunte documentos plantilla (en formatos de archivo compatibles con GroupDocs.Assembly) a su mensaje de correo electrónico plantilla. Luego, al ensamblar el mensaje de correo electrónico, el motor también ensamblará los documentos adjuntos utilizando las mismas fuentes de datos.
