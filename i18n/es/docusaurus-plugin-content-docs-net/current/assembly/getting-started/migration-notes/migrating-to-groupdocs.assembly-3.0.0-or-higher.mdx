## Razones para migrar {#reasons-to-migrate}

Con el fin de facilitar aún más la tarea de generación de informes, lanzamos **GroupDocs.Assembly for .NET 3.0.0**.

### Espacio(s) de nombres {#namespace-s}

En **GroupDocs.Assembly for .NET 3.0.0**, solo se requiere un único espacio de nombres **using GroupDocs.Assembly;** para generar informes en cualquiera de los formatos admitidos. En cambio, en **GroupDocs.Assembly for .NET 1.3.0**, para generar un informe en cualquiera de los formatos admitidos, era necesario agregar un espacio de nombres independiente correspondiente a ese formato; a continuación se muestran dichos espacios de nombres:

1.  using Groupdocs.Assembly;
2.  using Groupdocs.Assembly.Cells;
3.  using Groupdocs.Assembly.Data;
4.  using Groupdocs.Assembly.Exceptions;
5.  using Groupdocs.Assembly.Pdf;
6.  using Groupdocs.Assembly.Slides;
7.  using Groupdocs.Assembly.Words;

### Soporte para múltiples orígenes de datos {#support-of-multiple-data-sources}

**GroupDocs.Assembly for .NET 3.0.0** admite los siguientes orígenes de datos:

*   Base de datos
*   XML
*   JSON
*   OData
*   Objetos .NET personalizados

### Sintaxis sencilla para plantillas {#easy-template-syntax}

El motor de **GroupDocs.Assembly for .NET de nueva generación** admite la sintaxis subyacente de C# para consultas LINQ, la cual resulta más breve que LINQ propiamente dicho. Esto implica básicamente que los desarrolladores pueden utilizar la sintaxis de C# familiar y bien documentada para escribir consultas de enlace/recorrido de datos directamente en las plantillas de documentos. Como resultado, los desarrolladores pueden aprovechar numerosas ventajas, entre ellas una sintaxis de generación de informes breve y concisa, así como la capacidad de enlazar con cualquier tipo de origen de datos admitido, incluidos objetos empresariales.

### Edición de plantillas {#template-editing}

En **GroupDocs.Assembly for .NET 1.3.0**, el usuario debía editar la plantilla mediante código. En cambio, en **GroupDocs.Assembly for .NET 3.0.0**, la edición de plantillas resulta mucho más sencilla: el tamaño de fuente, la alineación del texto y otros elementos similares se configuran directamente en la plantilla.

### Código más cómodo {#comfy-code}

El código necesario para generar informes se ha reducido significativamente en **GroupDocs.Assembly for .NET 3.0.0**. El usuario ya no necesita escribir grandes bloques de líneas de código para generar informes extensos; en cambio, solo requiere escribir entre 2 y 3 líneas de código para generar documentos y reportes empresariales.
