:::warning
La inserción dinámica de documentos a partir de bytes codificados en Base64 está disponible únicamente para formatos de archivo donde la inserción dinámica de documentos esté habilitada, es decir, para documentos de procesamiento de textos y correos electrónicos con cuerpos en HTML y RTF únicamente.
:::


Puedes insertar dinámicamente el contenido de documentos externos en tus informes utilizando `doc` etiquetas. A `doc` `tag` denota un marcador de posición dentro de una plantilla para un documento que se insertará durante el tiempo de ejecución.

Sintaxis de un `doc` la etiqueta se define de la siguiente manera:

```csharp
<<doc [document_expression]>>
```

Y simplemente llame al método del ensamblador para generar el informe, como se muestra en los siguientes fragmentos de código:

<a href="https://gist.github.com/GroupDocsGists/b06d6c5655c84fc772c6411d66016943" target="_blank" rel="nofollow noopener noreferrer">Ver ejemplo de código en GitHub Gist</a>


:::warning
A `doc` La etiqueta `tag` se puede usar casi en cualquier lugar de un documento de plantilla, excepto en cuadros de texto y gráficos.
:::


Una expresión declarada dentro de una etiqueta `doc` es utilizada por el ensamblador para cargar un documento que será insertado durante el tiempo de ejecución. La expresión debe devolver un valor de uno de los siguientes tipos:

*   Una matriz de bytes que contiene los datos del documento
*   Una instancia de <a href="http://msdn.microsoft.com/en-us/library/system.io.stream(v=vs.110" target="_blank" rel="nofollow noopener noreferrer">Stream</a>.aspx) capaz de leer los datos del documento
*   Una instancia de la clase Document
*   Una cadena que contiene una URI, ruta o datos del documento codificados en Base64

Al construir un informe, una expresión declarada dentro de una etiqueta `doc` se evalúa y su resultado se utiliza para cargar un documento cuyo contenido reemplaza la etiqueta `doc` posteriormente.


:::warning
Si una expresión declarada dentro de un `doc` `tag` devuelve un objeto de flujo (`stream`), y luego el ensamblador cierra ese flujo tan pronto como se carga el documento correspondiente.
:::


De forma predeterminada, al insertar el contenido de un documento externo, el motor aplica los estilos correspondientes del documento de plantilla. Esto hace que el contenido del documento resultante se vea más coherente. Sin embargo, puedes conservar el formato de origen para el contenido que se inserta mediante un `sourceStyles` conmutador como se muestra en el siguiente fragmento:

```csharp
<<doc [document_expression] -sourceStyles>>
```

De forma predeterminada, un documento que se está insertando no se verifica contra la sintaxis de plantilla ni se completa con datos. Sin embargo, puedes habilitar esta funcionalidad mediante un `build` cambie de la siguiente manera:

```csharp
<<doc [document_expression] -build>>
```

Cuando se utiliza un interruptor `build`, el ensamblador trata el documento que se está insertando como una plantilla que puede acceder a los siguientes datos disponibles en el ámbito de la etiqueta `doc` correspondiente:

*   Fuentes de datos
*   Variables
*   Un objeto contextual (consulte <a href="https://docs.groupdocs.com/assembly/net/template-syntax-part-1-of-2/#using-contextual-object-member-access" target="_blank" rel="nofollow noopener noreferrer">"Uso del acceso a miembros de objetos contextuales"</a> para obtener más información)
*   Tipos externos conocidos (consulte <a href="https://docs.groupdocs.com/assembly/net/groupdocs-assembly-engine-apis/#setting-up-known-external-types" target="_blank" rel="nofollow noopener noreferrer">"Configuración de tipos externos conocidos"</a> para obtener más información)
