Para acceder a datos CSV mientras se construye un informe, puede pasar una instancia de <a href="https://reference.groupdocs.com/net/assembly/groupdocs.assembly.data/csvdatasource" target="_blank" rel="nofollow noopener noreferrer">CsvDataSource</a> al ensamblador como fuente de datos. El uso de *CsvDataSource* le permite trabajar con valores tipados en lugar de solo cadenas en los documentos de plantilla. Aunque el formato CSV no define una forma de almacenar valores de tipos distintos de cadenas, *CsvDataSource* es capaz de reconocer valores de los siguientes tipos a partir de sus representaciones en cadena:

*   Int32?
*   Int64?
*   Double?
*   Boolean?
*   DateTime?


:::warning
Para que el reconocimiento de tipos de datos funcione, las representaciones en cadena de los valores correspondientes deben formarse utilizando la configuración regional invariable.
:::


### Tratamiento de datos CSV simples {#treating-simple-csv-data}

En los documentos de plantilla, un <a href="https://reference.groupdocs.com/net/assembly/groupdocs.assembly.data/csvdatasource" target="_blank" rel="nofollow noopener noreferrer">CsvDataSource </a>la instancia debe tratarse de la misma manera que si fuera una instancia de *DataTable* (ver “<a href="/es/net/assembly/developer-guide/basic-usage/working-with-groupdocs.assembly-engine/template-syntax-part-1-of-2/#using-data-sources">Trabajar con objetos *DataTable* y *DataView*</a>“para más información) como se muestra en el siguiente ejemplo.”

Supongamos que tenemos datos CSV como:
```
John Doe,30,1989-04-01 4:00:00 pm
Jane Doe,27,1992-01-31 07:00:00 am
John Smith,51,1968-03-08 1:00:00 pm
```

Al usar la plantilla como la siguiente:
```
<<foreach \[in persons\]>>Name: <<\[Column1\]>>, Age: <<\[Column2\]>>, Date
of Birth: <<\[Column3\]:"dd.MM.yyyy">>
<</foreach>>
Average age: <<\[persons.Average(p => p.Column2)\]>>
```

Los resultados se producirán como:
```
Name: John Doe, Age: 30, Date of Birth: 01.04.1989
Name: Jane Doe, Age: 27, Date of Birth: 31.01.1992
Name: John Smith, Age: 51, Date of Birth: 08.03.1968
Average age: 36
```


:::warning
El uso del formato personalizado de fecha y hora, así como del método de extensión que involucra aritmética en el documento de plantilla, es posible porque los valores de texto de `Column3` y `Column2` se convierten automáticamente en `DateTime?` y `Int32?`, respectivamente.
:::


### Configurar la fuente de datos para leer los nombres de las columnas {#configure-data-source-to-read-column-names}

De forma predeterminada, <a href="https://reference.groupdocs.com/net/assembly/groupdocs.assembly.data/csvdatasource" target="_blank" rel="nofollow noopener noreferrer">CsvDataSource </a>utiliza nombres de columnas como "*Column1*", "*Column2*", etc., como se puede observar en el ejemplo anterior. Sin embargo, *CsvDataSource* se puede configurar para leer los nombres de las columnas desde la primera línea de los datos CSV, como se muestra en el siguiente ejemplo.

Supongamos que tenemos datos CSV como:
```
Name,Age,Birth
John Doe,30,1989-04-01 4:00:00 pm
Jane Doe,27,1992-01-31 07:00:00 am
John Smith,51,1968-03-08 1:00:00 pm
```

Al usar la plantilla como la siguiente:
```
<<foreach \[in persons\]>>Name: <<\[Name\]>>, Age: <<\[Age\]>>, Date of
Birth: <<\[Birth\]:"dd.MM.yyyy">>
<</foreach>>
Average age: <<\[persons.Average(p => p.Age)\]>>
```

El código debe escribirse como:
<a href="https://gist.github.com/GroupDocsGists/f59b71ca7e6345f9ac817297f3707f5f" target="_blank" rel="nofollow noopener noreferrer">Ver ejemplo de código en GitHub Gist</a>

Los resultados se generarán como:
```
Name: John Doe, Age: 30, Date of Birth: 01.04.1989
Name: Jane Doe, Age: 27, Date of Birth: 31.01.1992
Name: John Smith, Age: 51, Date of Birth: 08.03.1968
Average age: 36
```

Además, puede utilizar *CsvDataLoadOptions* para personalizar los siguientes caracteres que tienen un papel especial al cargar datos CSV:

*   Separador de valores (el valor predeterminado es la coma)
*   Inicio de comentario de una sola línea (el valor predeterminado es la almohadilla)
*   Comilla que permite utilizar otros caracteres especiales dentro de un valor (el valor predeterminado son las comillas dobles)
