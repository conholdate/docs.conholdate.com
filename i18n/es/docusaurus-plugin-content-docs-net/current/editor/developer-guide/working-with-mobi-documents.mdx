## Introducción {#introduction}

El formato Mobi es un formato de libro electrónico desarrollado por la empresa francesa MobiPocket y basado en XML. Los libros electrónicos en este formato pueden contener texto con formato avanzado, imágenes y distintos tipos de anotaciones, como marcadores, notas, subrayados, correcciones, etc. Los libros Mobi pueden estar protegidos mediante DRM.

A partir de la <a href="https://docs.groupdocs.com/editor/net/groupdocs-editor-for-net-20-7-release-notes/" target="_blank" rel="nofollow noopener noreferrer">versión 20.7</a>, GroupDocs.Editor para .NET permite abrir (cargar) documentos Mobi para su edición. Sin embargo, en esa versión aún no era posible guardar *en* formato Mobi, por lo que los usuarios se veían obligados a elegir otro formato (probablemente AZW3 o ePub) para guardar el documento Mobi editado.

A partir de la <a href="https://docs.groupdocs.com/editor/net/groupdocs-editor-for-net-22-7-release-notes/" target="_blank" rel="nofollow noopener noreferrer">versión 22.7</a>, GroupDocs.Editor permite editar libros electrónicos en el formato <a href="https://docs.fileformat.com/ebook/azw3/" target="_blank" rel="nofollow noopener noreferrer">AZW3</a>, también conocido como Kindle Format 8 (KF8), que puede considerarse como el sucesor de Mobi. A diferencia de MOBI, AZW3 es compatible tanto en la importación (desde la versión 22.7) como en la exportación (desde la versión 22.9).

A partir de la <a href="https://docs.groupdocs.com/editor/net/groupdocs-editor-for-net-23-4-release-notes/" target="_blank" rel="nofollow noopener noreferrer">versión 23.4</a>, GroupDocs.Editor para .NET permite guardar (exportar) documentos en formato Mobi; por lo tanto, desde esta versión se puede afirmar que Mobi es totalmente compatible: en importación, exportación y detección automática.

## Carga de un archivo Mobi para su edición {#loading-mobi-file-for-edit}

A pesar de tratarse de un formato distinto que no pertenece a ninguna familia de formatos existente, Mobi no dispone de opciones de carga específicas. Por lo tanto, para cargarlo en una instancia de la clase <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor" target="_blank" rel="nofollow noopener noreferrer">`Editor`</a>, los usuarios simplemente deben especificar la ruta al archivo Mobi o un flujo que contenga su contenido en el constructor:

```csharp
string inputMobiPath = "C://input/book.mobi";
Editor editorFromPath = new Editor(inputMobiPath);
  
FileStream inputMobiStream = File.OpenRead("C://input/book.mobi");
Editor editorFromStream = new Editor(inputMobiStream);
```

No existen opciones de carga, ya que Mobi no requiere ajustes durante la carga: no puede tener protección con contraseña y solo puede procesarse de una única manera.

## Edición de archivos Mobi {#editing-mobi-file}

Dado que Mobi pertenece a la familia de formatos de libros electrónicos, utiliza las opciones de edición comunes para todos los formatos de libros electrónicos: la clase <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/ebookeditoptions" target="_blank" rel="nofollow noopener noreferrer">`EbookEditOptions`</a>. Esta clase puede describirse como una versión simplificada de la clase <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingeditoptions" target="_blank" rel="nofollow noopener noreferrer">`WordProcessingEditOptions`</a>, ya que <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/ebookeditoptions" target="_blank" rel="nofollow noopener noreferrer">`EbookEditOptions`</a> contiene un subconjunto de opciones de <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingeditoptions" target="_blank" rel="nofollow noopener noreferrer">`WordProcessingEditOptions`</a> —específicamente, <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/ebookeditoptions/enablepagination" target="_blank" rel="nofollow noopener noreferrer">`EnablePagination`</a> y <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/ebookeditoptions/enablelanguageinformation" target="_blank" rel="nofollow noopener noreferrer">`EnableLanguageInformation`</a>— y, como ocurre en <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingeditoptions" target="_blank" rel="nofollow noopener noreferrer">`WordProcessingEditOptions`</a>, estas opciones están deshabilitadas (`false`) de forma predeterminada:

```csharp
public bool EnablePagination { get; set; }
  
public bool EnableLanguageInformation { get; set; }
```

Tienen exactamente el mismo significado que sus «hermanos» de <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingeditoptions" target="_blank" rel="nofollow noopener noreferrer">`WordProcessingEditOptions`</a>. <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/ebookeditoptions/enablepagination" target="_blank" rel="nofollow noopener noreferrer">`EnablePagination`</a> permite alternar entre el modo flotante y el modo de páginas en el documento HTML resultante. <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/ebookeditoptions/enablelanguageinformation" target="_blank" rel="nofollow noopener noreferrer">`EnableLanguageInformation`</a> permite habilitar la exportación de información lingüística en HTML. Esto resulta muy útil para libros que contienen fragmentos de texto escritos en distintos idiomas.

A continuación se muestra un ejemplo de uso (supongamos que ya se ha creado una instancia de <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor" target="_blank" rel="nofollow noopener noreferrer">`Editor`</a> con el documento Mobi cargado):

```csharp
Options.EbookEditOptions editOptions = new Options.EbookEditOptions();
editOptions.EnablePagination = true;
editOptions.EnableLanguageInformation = true;
using (EditableDocument opened = editor.Edit(editOptions))
{
    //save it or pass to the WYSIWYG-editor
}
```


:::info
El <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/ebookeditoptions" target="_blank" rel="nofollow noopener noreferrer">`EbookEditOptions`</a> la clase se introdujo por primera vez en GroupDocs.Editor para .NET <a href="https://docs.groupdocs.com/editor/net/groupdocs-editor-for-net-22-9-release-notes/" target="_blank" rel="nofollow noopener noreferrer">versión 22.9</a>. Sin embargo, antes de esta versión, existía una clase `MobiEditOptions`, que fue diseñado especialmente para el formato Mobi. En la versión 22.9 de GroupDocs.Editor para .NET, este `MobiEditOptions` la clase se eliminó a favor de la más generalizada <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/ebookeditoptions" target="_blank" rel="nofollow noopener noreferrer">`EbookEditOptions`</a>, por lo que, al actualizar desde las versiones 22.7 o anteriores a las versiones 22.9 o posteriores, actualice el nombre de la clase en consecuencia. Todos los miembros de clase en ambas clases son idénticos.
:::


## Guardar archivo Mobi tras la edición {#save-mobi-file-after-edit}

A partir de la <a href="https://docs.groupdocs.com/editor/net/groupdocs-editor-for-net-20-7-release-notes/" target="_blank" rel="nofollow noopener noreferrer">versión 20.7</a> y hasta la <a href="https://docs.groupdocs.com/editor/net/groupdocs-editor-for-net-23-4-release-notes/" target="_blank" rel="nofollow noopener noreferrer">versión 23.4</a>, GroupDocs.Editor para .NET solo permitía cargar y editar documentos Mobi, pero no guardar (exportar) en el formato Mobi. En otras palabras, podía abrir y editar un documento Mobi y, posteriormente, guardar la versión editada en otro formato, pero no en Mobi. A partir de la versión 23.4, finalmente se implementó la exportación al formato Mobi.

Para todas las familias de formatos, el procedimiento de guardado es el mismo: es necesario obtener el contenido del documento editado en el lado del servidor, crear una instancia de la clase <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">`EditableDocument`</a> a partir de dicho contenido y, a continuación, pasarlo al método de instancia de <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor/save" target="_blank" rel="nofollow noopener noreferrer">`GroupDocs.Editor.Editor.Save()`</a>. Dado que el formato Mobi pertenece a la familia de formatos de libros electrónicos (e-Book), para guardar el documento en formato Mobi se requiere la clase <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/ebooksaveoptions" target="_blank" rel="nofollow noopener noreferrer">`EbookSaveOptions`</a>.

Esta clase dispone de un <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/ebooksaveoptions/ebooksaveoptions/" target="_blank" rel="nofollow noopener noreferrer">constructor obligatorio con un único parámetro</a>: el <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.formats/ebookformats/" target="_blank" rel="nofollow noopener noreferrer">formato de libro electrónico</a> deseado. Para Mobi, debe utilizarse <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.formats/ebookformats/mobi/" target="_blank" rel="nofollow noopener noreferrer">`EBookFormats.Mobi`</a>. El resto de parámetros de la clase EbookSaveOptions son, de hecho, opcionales, aunque se describen a continuación:

- <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/ebooksaveoptions/splitheadinglevel/" target="_blank" rel="nofollow noopener noreferrer">`SplitHeadingLevel`</a> de tipo `System.Int32` controla la estructura interna del archivo Mobi generado: si su contenido interno se divide en paquetes y, en caso afirmativo, cómo se hace. Este parámetro existe porque el contenido del archivo Mobi se almacena en paquetes, normalmente uno por capítulo, y algunos usuarios pueden desear controlar la política de distribución del contenido en dichos paquetes. Por defecto, su valor es "`2`", que resulta el más óptimo.
- <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/ebooksaveoptions/exportdocumentproperties/" target="_blank" rel="nofollow noopener noreferrer">`ExportDocumentProperties`</a> de tipo `System.Boolean` también afecta a la estructura interna del archivo Mobi: decide si incrustar las propiedades integradas y personalizadas del documento dentro del archivo Mobi resultante (`true`) o no (`false`). Por defecto, su valor es `false` (no incrustar).

En resumen: para guardar el documento editado en formato Mobi, el usuario debe crear una instancia de la clase <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/ebooksaveoptions" target="_blank" rel="nofollow noopener noreferrer">`EbookSaveOptions`</a> pasando <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.formats/ebookformats/mobi/" target="_blank" rel="nofollow noopener noreferrer">`EBookFormats.Mobi`</a> como argumento al constructor, y luego pasar dicha instancia al método <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor/save" target="_blank" rel="nofollow noopener noreferrer">`Editor.Save()`</a> junto con los demás argumentos.

El siguiente ejemplo de código muestra el ciclo completo completo: abrir un documento Mobi, editarlo y guardar la versión editada en formato Mobi.

```csharp
//Create an Editor instance and load an input Mobi file
Editor editor = new Editor("Input.mobi");

//Create edit options
Options.EbookEditOptions editOptions = new EbookEditOptions();

//Edit the Mobi document and obtain
EditableDocument doc = editor.Edit(editOptions);

//Send EditableDocument to the client-side, edit it there, and obtain an edited version

//Create Mobi save options
Options.EbookSaveOptions saveOptions = new EbookSaveOptions(Formats.EBookFormats.Mobi);
saveOptions.ExportDocumentProperties = true;//Tune save options

//Save the edited document in a Mobi format
editor.Save(doc, "Output.mobi", saveOptions);

//Dispose document and Editor instances
doc.Dispose();
editor.Dispose();
```

## Detección de archivos Mobi {#detecting-mobi-file}

En cuanto a los documentos de todos los tipos admitidos, los documentos Mobi pueden detectarse mediante el método <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor/getdocumentinfo" target="_blank" rel="nofollow noopener noreferrer">`GetDocumentInfo()`</a> de la clase <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor" target="_blank" rel="nofollow noopener noreferrer">`Editor`</a>. En caso de que se cargue un documento Mobi válido en una instancia <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor" target="_blank" rel="nofollow noopener noreferrer">`Editor`</a>, el <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor/getdocumentinfo" target="_blank" rel="nofollow noopener noreferrer">`GetDocumentInfo()`</a> devolverá una instancia de la clase <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.metadata/ebookdocumentinfo" target="_blank" rel="nofollow noopener noreferrer">`Metadata.EbookDocumentInfo`</a>, la cual hereda de la interfaz <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.metadata/idocumentinfo" target="_blank" rel="nofollow noopener noreferrer">`IDocumentInfo`</a>, que a su vez define 4 propiedades: `Format`, `PageCount`, `Size` y `IsEncrypted`.

- <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.metadata/ebookdocumentinfo/format" target="_blank" rel="nofollow noopener noreferrer">`Format`</a> devuelve una estructura <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.formats/ebookformats" target="_blank" rel="nofollow noopener noreferrer">`Formats.EBookFormats`</a>, la cual, para archivos con la extensión `*.mobi`, puede tener un valor `Mobi` o `Azw3`.
- <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.metadata/ebookdocumentinfo/pagecount" target="_blank" rel="nofollow noopener noreferrer">`PageCount`</a> devuelve un número **aproximado** de páginas en el caso de MOBI o AZW3, o bien un número de capítulos en el caso de ePub. Para los documentos Mobi, este valor es aproximado, ya que el formato Mobi internamente es un conjunto de documentos HTML (capítulos) que no están separados en páginas y ni siquiera tienen dimensiones de página fijas, lo que permite dividir el contenido en bloques de página y así calcular el número de páginas. Esta decisión fue tomada intencionalmente por los diseñadores del formato Mobi para permitir tamaños (y cantidades) variables de página en distintos dispositivos, desde pantallas FullHD hasta teléfonos inteligentes. Por lo tanto, al devolver un recuento de páginas para un documento Mobi, GroupDocs.Editor asume un tamaño estándar de página A4 en orientación vertical, divide el contenido existente del documento en dichas “hojas” y luego calcula su cantidad. Por consiguiente, el número devuelto debe interpretarse con gran cautela y de forma aproximada, y los usuarios no deben confiar en él.
- <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.metadata/ebookdocumentinfo/size" target="_blank" rel="nofollow noopener noreferrer">`Size`</a> devuelve el número de bytes del documento Mobi.
- <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.metadata/ebookdocumentinfo/isencrypted" target="_blank" rel="nofollow noopener noreferrer">`IsEncrypted`</a> siempre devuelve un valor `false`, ya que los documentos Mobi no pueden estar cifrados con contraseña, a diferencia de los PDF o los documentos Office Open XML.
