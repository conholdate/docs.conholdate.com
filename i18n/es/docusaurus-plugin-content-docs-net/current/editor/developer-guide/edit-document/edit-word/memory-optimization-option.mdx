De forma predeterminada <a href="https://products.groupdocs.com/editor/net" target="_blank" rel="nofollow noopener noreferrer">**GroupDocs.Editor**</a> intenta realizar cálculos y completar la tarea lo más rápido posible, y si este desafío requiere el uso de mucha memoria, GroupDocs.Editor lo hace. Sin embargo, en algunos casos muy específicos, cuando el procesamiento del documento es muy grande, y GroupDocs.Editor se ejecuta en una aplicación de 32 bits, la cual está limitada a 2 GiB por proceso, o la máquina del usuario tiene una cantidad muy limitada de memoria libre, puede producirse una `SystemOutOfMemoryException`. Para solucionar este problema, <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingsaveoptions" target="_blank" rel="nofollow noopener noreferrer">WordProcessingSaveOptions</a> la clase contiene <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingsaveoptions/optimizememoryusage" target="_blank" rel="nofollow noopener noreferrer">`OptimizeMemoryUsage`</a> propiedad:

```csharp
public bool OptimizeMemoryUsage { get; set; }
```

De forma predeterminada, tiene un valor de "*falso*", lo que significa que la optimización de memoria está deshabilitada con el fin de lograr el mejor rendimiento posible. Al establecerlo en "*verdadero*", el usuario puede habilitar otro mecanismo de generación de documentos, el cual puede disminuir significativamente el consumo de memoria al generar documentos grandes, aunque a costa de un tiempo de generación más lento al realizar la <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor/save" target="_blank" rel="nofollow noopener noreferrer">`editor.Guardar()</a> método.
