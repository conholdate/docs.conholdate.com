Los documentos de todos los formatos de procesamiento de texto pueden contener texto en diferentes idiomas. Sin embargo, a diferencia de los documentos de texto sin formato (TXT), los documentos de procesamiento de texto también contienen metadatos sobre el idioma específico (configuración regional) de cada fragmento de texto. <a href="https://products.groupdocs.com/editor/net" target="_blank" rel="nofollow noopener noreferrer">**GroupDocs.Editor**</a> permite extraer y exportar esta información de idioma. Para lograrlo, la clase <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingeditoptions" target="_blank" rel="nofollow noopener noreferrer">WordProcessingEditOptions</a> contiene la propiedad pública booleana <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingeditoptions/enablelanguageinformation" target="_blank" rel="nofollow noopener noreferrer">`EnableLanguageInformation`</a>:

```csharp
public bool EnableLanguageInformation {get; set;}
```

De forma predeterminada, su valor es `false`, lo que significa que no se extraerá la metadatos de idioma. Sin embargo, cuando esta opción se habilita manualmente, GroupDocs.Editor extrae la información regional para cada fragmento de contenido textual y la conserva en la instancia <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a> mientras el documento se edita. Finalmente, cuando el usuario obtiene la instancia <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a> y genera el marcado HTML para transferirlo al editor HTML WYSIWYG con el fin de hacer que el documento sea editable en el navegador, esta información lingüística se representa como atributos HTML 'lang' con los valores correspondientes dentro de los elementos SPAN HTML.

Habilitar la información de idioma resulta útil cuando el documento contiene distintas secciones de texto en diferentes idiomas; si el documento contiene texto únicamente en un solo idioma, esta opción carece de gran utilidad y, por tanto, se deshabilita de forma predeterminada.

No obstante, cuando el documento es multilingüe, habilitar la información de idioma puede resultar muy conveniente en dos escenarios:

* Facilita la corrección ortográfica para correctores ortográficos basados en JavaScript que funcionan en el navegador. Sin embargo, esto depende en gran medida del corrector ortográfico específico, ya que no todos los correctores son capaces de extraer los valores de los atributos “lang” ni siquiera de utilizar la información lingüística en absoluto.
* Mejora la calidad del documento de procesamiento de texto de salida en escenarios de ida y vuelta (roundtrip). Cuando un documento con la opción <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/wordprocessingeditoptions/enablelanguageinformation" target="_blank" rel="nofollow noopener noreferrer">`EnableLanguageInformation`</a> habilitada se convierte a la instancia <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a>, luego se genera el marcado HTML, se edita en algún editor HTML y, a continuación, se crea una nueva instancia de la clase <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a> a partir del marcado editado, los metadatos lingüísticos contenidos en los atributos “lang” se conservan. Cuando la <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a> editada se convierta de nuevo al documento de salida en algún formato de procesamiento de texto, como DOCX o RTF, el contenido textual contendrá conexiones con la configuración regional adecuada.
