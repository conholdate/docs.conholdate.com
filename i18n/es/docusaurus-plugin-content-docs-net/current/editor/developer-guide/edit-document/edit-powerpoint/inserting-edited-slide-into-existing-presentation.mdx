De forma predeterminada, la secuencia completa de edición de presentaciones (ciclo) es la siguiente:  

1. Cargar la presentación, en forma de archivo o flujo, en el constructor de la clase <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor" target="_blank" rel="nofollow noopener noreferrer">Editor</a>.
2. Seleccionar una diapositiva específica para editarla y especificar su índice en la propiedad <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/presentationeditoptions/slidenumber" target="_blank" rel="nofollow noopener noreferrer">SlideNumber</a> de la clase <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/presentationeditoptions" target="_blank" rel="nofollow noopener noreferrer">PresentationEditOptions</a>.
3. Abrir la presentación para editarla llamando al método <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor/edit" target="_blank" rel="nofollow noopener noreferrer">Editor.Edit()</a>, pasando una instancia de <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/presentationeditoptions" target="_blank" rel="nofollow noopener noreferrer">PresentationEditOptions</a> que contenga la diapositiva seleccionada, y obteniendo una instancia de <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a> desde este método.
4. Generar marcado HTML y CSS que represente el contenido del documento editado, a partir de la instancia <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a>, utilizando distintos métodos como <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument/getcontent" target="_blank" rel="nofollow noopener noreferrer">GetContent()</a>.
5. Pasar este marcado HTML y CSS al editor WYSIWYG, ubicado en el lado del cliente y ejecutándose en el navegador.
6. El usuario final edita el contenido del documento en el editor WYSIWYG.
7. El contenido del documento editado, en forma de marcado HTML y CSS, se devuelve al lado del servidor.
8. A continuación, este contenido se pasa a la clase <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a>, mediante los métodos estáticos <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument/fromfile" target="_blank" rel="nofollow noopener noreferrer">FromFile</a>, <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument/frommarkup" target="_blank" rel="nofollow noopener noreferrer">FromMarkup</a> o <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument/frommarkupandresourcefolder/" target="_blank" rel="nofollow noopener noreferrer">FromBodyMarkupAndResourceFolder</a>.
9. La instancia <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a> creada, que contiene el contenido editado del documento, se pasa al método <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor/save" target="_blank" rel="nofollow noopener noreferrer">Editor.Save</a>.
10. <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor/save" target="_blank" rel="nofollow noopener noreferrer">Editor.Save</a> genera una nueva presentación que contiene únicamente una diapositiva: aquella que fue editada en el lado del cliente y cuyo contenido se pasó a través de la clase <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a> a este método.

Antes de GroupDocs.Editor <a href="https://releases.groupdocs.com/editor/net/release-notes/2020/groupdocs-editor-for-net-20-4-release-notes/" target="_blank" rel="nofollow noopener noreferrer">versión 20.4</a>, esta era la única secuencia disponible para el cliente.

A partir de la versión 20.4, el décimo paso de la secuencia descrita puede modificarse: la diapositiva editada puede insertarse en la presentación original cargada en el primer paso.

La clase <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/presentationsaveoptions" target="_blank" rel="nofollow noopener noreferrer">PresentationSaveOptions</a> ahora contiene dos propiedades nuevas: un entero <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/presentationsaveoptions/slidenumber" target="_blank" rel="nofollow noopener noreferrer">SlideNumber</a> y una bandera booleana <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/presentationsaveoptions/insertasnewslide" target="_blank" rel="nofollow noopener noreferrer">InsertAsNewSlide</a>. Ambas tienen valores predeterminados «habituales»: <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/presentationsaveoptions/slidenumber" target="_blank" rel="nofollow noopener noreferrer">SlideNumber</a> tiene el valor `0` y <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/presentationsaveoptions/insertasnewslide" target="_blank" rel="nofollow noopener noreferrer">InsertAsNewSlide</a> se establece en `false`.

```csharp
public int SlideNumber { get; set; }
public bool InsertAsNewSlide { get; set; }
```

De forma predeterminada, cuando estas propiedades no se modifican o, al menos, <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/presentationsaveoptions/slidenumber" target="_blank" rel="nofollow noopener noreferrer">SlideNumber</a> tiene un valor predeterminado `0`, GroupDocs.Editor generará una nueva presentación de una sola diapositiva, tal como ocurría en versiones anteriores. Sin embargo, si la propiedad <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/presentationsaveoptions/slidenumber" target="_blank" rel="nofollow noopener noreferrer">SlideNumber</a> contiene un número distinto de `0` y una presentación válida se carga en la clase <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor" target="_blank" rel="nofollow noopener noreferrer">Editor</a> (se espera que sea la presentación original que se editó, aunque en realidad puede ser cualquier presentación, incluso aquellas que no tengan relación alguna con la original), entonces la diapositiva editada se **insertará** en la presentación proporcionada.

## Propiedad SlideNumber  {#slidenumber-property}
  
La propiedad <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/presentationsaveoptions/slidenumber" target="_blank" rel="nofollow noopener noreferrer">SlideNumber</a>, si su valor no es cero, define *dónde*, es decir, *en qué posición exacta* de la presentación dada debe insertarse la nueva diapositiva editada. El parámetro `InsertAsNewSlide`, que es una bandera booleana, determina *cómo* debe insertarse esta diapositiva: si debe *reemplazar* la diapositiva existente que se encuentra en la posición especificada (`false`, valor predeterminado), o si debe *inyectarse entre* las diapositivas existentes, sin sobrescribirlas, aumentando así en una unidad el número total de diapositivas de la presentación dada.

Debido a que el valor predeterminado `0` del parámetro `SlideNumber` está reservado, la numeración efectiva de diapositivas comienza en `1`. Esto difiere del índice basado en cero ampliamente utilizado, pero tiene sentido, por lo que no se trata de un *índice* de diapositiva, sino más bien del *número* de diapositiva, tal como lo hace, por ejemplo, Microsoft PowerPoint. Esto significa que, por ejemplo, para una presentación dada que consta de 5 diapositivas, la primera tiene el número de diapositiva `1` y la quinta, `5`. Si el usuario especifica un número de diapositiva que excede el número total de diapositivas de la presentación, dicho número se ajustará automáticamente al último. Esto implica que, por ejemplo, para la misma presentación de 5 diapositivas, si el usuario especifica `6`, `7` o incluso `Int32.MaxValue`, internamente se establecerá `5`, es decir, el número de la última diapositiva.

Además de los números positivos de diapositivas, la propiedad `SlideNumber` también admite numeración negativa, lo que implica contar desde el final de la presentación. En este caso, '-1' se considera la última diapositiva, '-2' la penúltima, y así sucesivamente. Nuevamente, al igual que con la numeración positiva, si el número excede la cantidad de diapositivas, se ajustará al más cercano: la primera diapositiva para números negativos.

Una parte del código fuente a continuación explica este sistema de numeración:

```csharp
PresentationSaveOptions saveOptions = new PresentationSaveOptions(Formats.PresentationFormats.Pptx)

//let's say we have presentation with 5 slides

saveOptions.SlideNumber = 0;  // default value, given presentation will be ignored

//positive numbering
saveOptions.SlideNumber =  1;  // first slide
saveOptions.SlideNumber =  2;  // second slide 
saveOptions.SlideNumber =  3;  // third slide 
saveOptions.SlideNumber =  4;  // fourth slide 
saveOptions.SlideNumber =  5;  // fifth slide 
saveOptions.SlideNumber =  6;  // fifth slide, because value '6' exceeds the slides amount '5' and thus is adjusted to the closest

//negative numbering
saveOptions.SlideNumber = -1;  // fifth slide, which is first from end (last)
saveOptions.SlideNumber = -2;  // fourth slide, which is second from end (last but one)
saveOptions.SlideNumber = -3;  // third slide, which is third from end
saveOptions.SlideNumber = -4;  // second slide, which is fourth from end
saveOptions.SlideNumber = -5;  // first slide, which is fifth from end
saveOptions.SlideNumber = -6;  // first slide, because value '-6' exceeds the slides amount '5' and thus is adjusted to the closest
```

## Propiedad InsertAsNewSlide  {#insertasnewslide-property}
  
La propiedad <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/presentationsaveoptions/insertasnewslide" target="_blank" rel="nofollow noopener noreferrer">InsertAsNewSlide</a> complementa la propiedad <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/presentationsaveoptions/slidenumber" target="_blank" rel="nofollow noopener noreferrer">SlideNumber</a> descrita anteriormente y se ignora cuando `SlideNumber` tiene el valor `0`. Si `SlideNumber` apunta a una diapositiva con un número específico, <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/presentationsaveoptions/insertasnewslide" target="_blank" rel="nofollow noopener noreferrer">InsertAsNewSlide</a> determina cómo tratar este número de diapositiva y cómo insertarla:  


* Si la propiedad <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/presentationsaveoptions/insertasnewslide" target="_blank" rel="nofollow noopener noreferrer">InsertAsNewSlide</a> tiene el valor predeterminado `false`, la diapositiva existente en la presentación dada se borrará completamente, y el contenido de la nueva diapositiva (ubicado en la instancia <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a>) se insertará en su lugar. Como resultado, la presentación mantendrá el mismo número de diapositivas sin modificar, pero una de sus diapositivas (especificada por `SlideNumber`) se reemplazará por la nueva.
* Si la propiedad <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/presentationsaveoptions/insertasnewslide" target="_blank" rel="nofollow noopener noreferrer">InsertAsNewSlide</a> tiene el valor `true`, la diapositiva editada, obtenida de la instancia <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a>, se insertará entre las diapositivas existentes en la presentación dada, incrementando así su número total en una unidad. La nueva diapositiva se inserta en la posición indicada por `SlideNumber`, y todas las diapositivas subsiguientes (posteriores o anteriores) se desplazarán hacia el final o hacia el principio, según corresponda, dependiendo de si la numeración es positiva o negativa.  

El código fuente siguiente muestra cómo se trata el número de diapositiva cuando la propiedad `InsertAsNewSlide` está habilitada:

```csharp
PresentationSaveOptions saveOptions = new PresentationSaveOptions(Formats.PresentationFormats.Pptx)

//let's say we have presentation with 5 slides
saveOptions.SlideNumber = 0;  // default value, given presentation will be ignored, as well as InsertAsNewSlide
saveOptions.InsertAsNewSlide = true;//

//positive numbering
saveOptions.SlideNumber =  1;  // new slide is injected as first, while all following (including 'old' 1st) are shifting to the end
saveOptions.SlideNumber =  2;  // new slide is injected as second, while 2nd, 3rh, 4th and 5th are shifting to the end
saveOptions.SlideNumber =  3;  // new slide is injected as third, while 3rh, 4th and 5th are shifting to the end
saveOptions.SlideNumber =  4;  // new slide is injected as fourth, while 4th and 5th are shifting to the end
saveOptions.SlideNumber =  5;  // new slide is injected as fifth, while 5th is shifting to the end and becomes 6th
saveOptions.SlideNumber =  6;  // new slide is injected as sixth, it already becomes the latest, none of existing slides are shifthing to the end
saveOptions.SlideNumber =  7;  // same as previous

//negative numbering
saveOptions.SlideNumber = -1;  // new slide is inject as first from end (it becomes sixth if starting from beginning), none of existing slides are shifthing to the end
saveOptions.SlideNumber = -2;  // new slide is inject as second from end (it becomes fifth if starting from beginning), following single slide is shifting to the end
saveOptions.SlideNumber = -3;  // new slide is inject as third from end (it becomes fourth if starting from beginning), two following slides are shifting to the end
saveOptions.SlideNumber = -4;  // new slide is inject as fourth from end (it becomes third if starting from beginning), three following slides are shifting to the end
saveOptions.SlideNumber = -5;  // new slide is inject as fifth from end (it becomes second if starting from beginning), four following slides are shifting to the end
saveOptions.SlideNumber = -6;  // new slide is inject as sixth from end (it becomes first if starting from beginning), five following slides are shifting to the end
saveOptions.SlideNumber = -7;  // same as previous
```
