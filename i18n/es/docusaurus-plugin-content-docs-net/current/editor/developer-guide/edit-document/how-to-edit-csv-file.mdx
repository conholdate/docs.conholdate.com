> Esta demostración muestra y explica todos los momentos y opciones necesarios relacionados con el procesamiento de hojas de cálculo DSV (valores separados por delimitadores), como CSV y otros.

## Introducción {#introduction}
  
Los archivos DSV (valores separados por delimitadores) son una forma específica de hojas de cálculo basadas en texto, que utilizan delimitadores (separadores). Debido a su naturaleza, <a href="https://products.groupdocs.com/editor/net" target="_blank" rel="nofollow noopener noreferrer">**GroupDocs.Editor**</a> procesa esta clase de documentos de forma independiente de las hojas de cálculo binarias habituales. A diferencia de las hojas de cálculo convencionales, los documentos DSV, por su naturaleza textual, solo disponen de una única pestaña (hoja de cálculo) y no pueden ser codificados. No obstante, cualquier cadena no vacía puede considerarse como separador, por lo que el usuario siempre debe especificarlo explícitamente.

Los tipos más comunes de DSV son:  

1. CSV (valores separados por comas)
2. TSV (valores separados por tabulaciones)
3. Valores separados por punto y coma
4. Valores separados por espacios en blanco
5. … y cualquier otro

GroupDocs.Editor admite DSV con cualquier separador, ya sea un carácter o un conjunto de caracteres (cadena).

## Carga de un archivo CSV para su edición {#loading-csv-file-for-edit}
  
A diferencia de los documentos de procesamiento de textos y hojas de cálculo, los documentos DSV se cargan en la clase <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editor" target="_blank" rel="nofollow noopener noreferrer">Editor</a> sin ninguna opción de carga. Dado que son, por naturaleza, archivos de texto simples, no hay nada que ajustar:

```csharp
string inputCsvPath = "C://input/spreadsheet.csv";
Editor editor = new Editor(inputCsvPath);
```

## Editar archivo CSV  {#edit-csv-file}
  
Para abrir cualquier documento DSV para su edición, el usuario debe utilizar la clase <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/delimitedtexteditoptions" target="_blank" rel="nofollow noopener noreferrer">DelimitedTextEditOptions</a>, cuyo único constructor acepta un parámetro obligatorio: una cadena que representa el separador (delimitador), el cual no debe ser `null` ni una cadena vacía. Asimismo, existen varias propiedades opcionales. Dos de estas propiedades —<a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/delimitedtexteditoptions/convertdatetimedata" target="_blank" rel="nofollow noopener noreferrer">ConvertDateTimeData</a> y <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/delimitedtexteditoptions/convertnumericdata" target="_blank" rel="nofollow noopener noreferrer">ConvertNumericData</a>— son banderas booleanas que indican cómo deben tratarse los números. GroupDocs.Editor puede reconocer dígitos dentro de las celdas y tratarlos como valores numéricos o de fecha y hora. De forma predeterminada, este reconocimiento está deshabilitado, aunque el usuario puede activarlo. La siguiente propiedad, <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/delimitedtexteditoptions/treatconsecutivedelimitersasone" target="_blank" rel="nofollow noopener noreferrer">TreatConsecutiveDelimitersAsOne</a>, también es una bandera booleana que determina cómo deben tratarse los delimitadores consecutivos: como varios (valor predeterminado: `false`) o como uno solo (`true`).  

La última propiedad, <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/delimitedtexteditoptions/optimizememoryusage" target="_blank" rel="nofollow noopener noreferrer">OptimizeMemoryUsage</a>, también es una bandera booleana, pero con un propósito completamente distinto. De forma predeterminada, los algoritmos de GroupDocs.Editor están optimizados para un rendimiento máximo, con el fin de reducir el tiempo de latencia, mientras que el consumo de memoria tiene menor prioridad. Sin embargo, en algunos casos raros, el usuario podría necesitar cargar y abrir archivos DSV muy grandes, de varios cientos de MiB o incluso cercanos a 1 GiB. En tales situaciones, GroupDocs.Editor (.NET Framework, en realidad) podría lanzar una `OutOfMemoryException`. Para abordar estos casos de uso, se introdujo la bandera <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/delimitedtexteditoptions/optimizememoryusage" target="_blank" rel="nofollow noopener noreferrer">OptimizeMemoryUsage</a>. Al activarla, el usuario hace que GroupDocs.Editor utilice otros algoritmos de procesamiento, los cuales consumen una cantidad relativamente menor de memoria, aunque a costa de un rendimiento inferior.  

El ejemplo siguiente muestra cómo utilizar <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/delimitedtexteditoptions" target="_blank" rel="nofollow noopener noreferrer">DelimitedTextEditOptions</a> para editar un documento CSV en el que el carácter coma actúa como delimitador:

```csharp
DelimitedTextEditOptions editOptions = new DelimitedTextEditOptions(",");
editOptions.ConvertDateTimeData = false;
editOptions.ConvertNumericData = true;
editOptions.TreatConsecutiveDelimitersAsOne = true;
editOptions.OptimizeMemoryUsage = true;

EditableDocument document = editor.Edit(editOptions);
```

## Guardar archivo CSV tras la edición  {#save-csv-file-after-editing}
  
Tras su edición, el DSV de entrada puede guardarse nuevamente en formato DSV (no es necesario que utilice el mismo separador) o en cualquier documento de hoja de cálculo compatible. Para guardar el documento en formato DSV, el usuario debe utilizar la clase <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/delimitedtextsaveoptions" target="_blank" rel="nofollow noopener noreferrer">DelimitedTextSaveOptions</a>, la cual, al igual que la <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/delimitedtexteditoptions" target="_blank" rel="nofollow noopener noreferrer">DelimitedTextEditOptions</a>, tiene un único constructor que requiere un parámetro de tipo cadena obligatorio: el separador (delimitador), el cual no debe ser `NULL` ni una cadena vacía.

Existen también otras propiedades:  

1. <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/delimitedtextsaveoptions/encoding" target="_blank" rel="nofollow noopener noreferrer">Encoding</a>. Permite especificar la codificación del DSV generado. Por defecto, si no se especifica, es UTF8.  

2. <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/delimitedtextsaveoptions/trimleadingblankrowandcolumn" target="_blank" rel="nofollow noopener noreferrer">TrimLeadingBlankRowAndColumn</a>. Bandera booleana que indica si deben eliminarse las filas y columnas iniciales en blanco, tal como lo hace Microsoft Excel.  

3. <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor.options/delimitedtextsaveoptions/keepseparatorsforblankrow" target="_blank" rel="nofollow noopener noreferrer">KeepSeparatorsForBlankRow</a>. Bandera booleana que indica si deben generarse separadores para las filas vacías. El valor predeterminado es `false`, lo que significa que el contenido de una fila vacía será una cadena vacía.

El ejemplo siguiente demuestra cómo cargar un archivo CSV, abrirlo en una instancia de <a href="https://reference.groupdocs.com/editor/net/groupdocs.editor/editabledocument" target="_blank" rel="nofollow noopener noreferrer">EditableDocument</a> y guardarlo como TSV y XLSM.

```csharp
string inputCsvPath = "C://input/spreadsheet.csv";
Editor editor = new Editor(inputCsvPath);

DelimitedTextEditOptions editOptions = new DelimitedTextEditOptions(",");
EditableDocument document = editor.Edit(editOptions);

DelimitedTextSaveOptions tsvSaveOptions = new DelimitedTextSaveOptions("\t");
tsvSaveOptions.TrimLeadingBlankRowAndColumn = true;
tsvSaveOptions.KeepSeparatorsForBlankRow = false;

SpreadsheetSaveOptions xlsmSaveOptions = new SpreadsheetSaveOptions(SpreadsheetFormats.Xlsm);

string tsvSavePath = "C://output/spreadsheet.tsv";
string xlsmSavePath = "C://output/spreadsheet.xlsm";

editor.Save(document, tsvSavePath, tsvSaveOptions);
editor.Save(document, xlsmSavePath, xlsmSaveOptions);
```

En este ejemplo, la salida `spreadsheet.tsv` tendrá una codificación UTF-8.
