## Limitaciones de la versión de evaluación {#evaluation-limitations}
  
La versión de evaluación proporciona todas las funciones, excepto las siguientes:

### Soporte de escritura MPP {#mpp-write-support}
  
Guardar el proyecto como archivo MPP solo está disponible en las versiones con licencia de Aspose.Tasks para .NET. Tenga en cuenta que la escritura de un archivo MPP conserva la versión del formato MPP del archivo original. Por ejemplo, si el archivo MPP original está en el formato de Microsoft Project 2003, el archivo MPP actualizado mediante Aspose.Tasks para .NET también estará en el formato MPP de Microsoft Project 2003. Lo mismo se aplica a los formatos MPP de Microsoft Project 2007, 2010, 2013, 2016, 2019 y 2021.

### Soporte de escritura para Project Server / Project Online {#project-serverproject-online-write-support}
  
La creación o actualización de proyectos en Project Server o Project Online solo está disponible en las versiones con licencia de Aspose.Tasks para .NET.

### Limitación de DateTime {#datetime-limitation}
  
El año de la fecha se cambiará a 2000 en los proyectos que se escriban mediante Aspose.Tasks para .NET en formatos distintos de MPP. Esto puede demostrarse con el siguiente ejemplo de código: en el ejemplo, se crea un proyecto con dos tareas utilizando Aspose.Tasks para .NET sin una licencia configurada y, a continuación, se guarda el proyecto en el formato XML de Microsoft Project.

```java
// Create a project instance
Project project = new Project();

// Define Tasks
Task task1 = project.RootTask.Children.Add("Task1");
task1.Set(Tsk.ActualStart, DateTime.Parse("06-Apr-2010"));

Task task2 = project.RootTask.Children.Add("Task2");
task2.Set(Tsk.ActualStart, DateTime.Parse("10-Apr-2010"));

project.Save("EvalProject_out.xml", SaveFileFormat.XML);
```

## Aplicación de la licencia  {#applying-the-license}
  
Una vez que esté satisfecho con su evaluación de **Aspose.Tasks para .NET**, puede adquirir una licencia en el sitio web de Aspose: <a href="https://purchase.conholdate.com/buy" target="_blank">https://purchase.conholdate.com/buy</a>. Familiarícese con las distintas <a href="https://purchase.conholdate.com/policies//license-types/" target="_blank">licencias</a> ofrecidas. Si tiene alguna pregunta, <a href="https://about.conholdate.com/contact" target="_blank">póngase en contacto con el equipo de ventas de Conholdate</a> y con gusto le ayudarán.

Aspose.Tasks para .NET admite dos tipos de licencia: perpetua (pago único) y por uso (pago por uso). Para obtener más detalles, consulte la página <a href="https://purchase.conholdate.com/policies//license-types/" target="_blank">Tipos de licencia</a>.

La licencia perpetua de Aspose incluye una <a href="https://purchase.conholdate.com/policies#subscriptions" target="_blank">suscripción</a> gratuita de un año para recibir actualizaciones a nuevas versiones o correcciones lanzadas durante este período. El soporte técnico es gratuito, ilimitado y se proporciona tanto a usuarios con licencia como a usuarios en evaluación.

La licencia es un archivo XML de texto plano que contiene detalles como el nombre del producto, la cantidad de desarrolladores con licencia, la fecha de vencimiento de la suscripción, entre otros. Dicho archivo está firmado digitalmente, por lo que no debe modificarlo: incluso agregar un salto de línea adicional invalida el archivo.

### Cuándo aplicar una licencia  {#when-to-apply-a-license}
  
Siga estas reglas sencillas:

- La licencia solo debe establecerse una vez por dominio de aplicación.
- Debe establecer la licencia antes de utilizar cualquier otra clase de Aspose.Tasks para .NET.
- Establecer la licencia varias veces no es perjudicial, pero desperdicia tiempo de procesamiento.
- Si está desarrollando una aplicación de Windows Forms o de consola, establezca la licencia en su código de inicio, antes de utilizar las clases de Aspose.Tasks para .NET.
- Al desarrollar una aplicación ASP.NET, puede establecer la licencia desde el archivo Global.asax.cs (Global.asax.vb), en el método protegido Application_Start. Este método se invoca una única vez al iniciar la aplicación.
- No establezca la licencia dentro de los métodos Page_Load, ya que esto provocaría que la licencia se cargara cada vez que se cargue una página web.
- Si está desarrollando una biblioteca de clases, establezca la licencia en un constructor estático de su clase que utilice Aspose.Tasks. El constructor estático se ejecuta antes de que se cree una instancia de su clase, garantizando así que la licencia de Aspose.Tasks se configure correctamente.

### Aplicación de una licencia perpetua  {#applying-a-perpetual-license}
  
Utilice el método **License.SetLicense** para licenciar el componente. La forma más sencilla de establecer una licencia es colocar el archivo de licencia en la misma carpeta que Aspose.Tasks.dll y especificar el nombre del archivo (sin ruta) como se muestra a continuación.

```csharp
    Aspose.Tasks.License license = new Aspose.Tasks.License();
    license.SetLicense("license.lic");
```

#### Aplicación de una licencia mediante archivo o flujo  {#applying-a-license-using-file-or-stream}
  
Este fragmento de código inicializa una licencia almacenada en un archivo o en un recurso incrustado.

```java
License license = new License();
license.SetLicense("Aspose.Tasks.lic");
```

#### Aplicación de licencias mediante un recurso incrustado {#applying-a-licenses-using-an-embedded-resource}

Otra forma práctica de empaquetar la licencia junto con su aplicación y asegurarse de que no se pierda es incluirla como un recurso incrustado en uno de los ensamblados que llaman al DLL del componente. Para incluir el archivo de licencia como un recurso incrustado, realice los siguientes pasos:

1. En Visual Studio .NET, agregue el archivo de licencia (.lic) al proyecto mediante la opción **Agregar elemento existente** del menú **Archivo**.
2. Seleccione el archivo en el Explorador de soluciones.
3. Establezca **Acción de compilación** en **Recurso incrustado** en la ventana Propiedades.

Para acceder a la licencia incrustada en el ensamblado (como un recurso incrustado), no es necesario llamar a los métodos `GetExecutingAssembly` y `GetManifestResourceStream` de la clase `System.Reflection.Assembly` del Microsoft .NET Framework. En su lugar, simplemente agregue el archivo de licencia como un recurso incrustado a su proyecto y pase el nombre del archivo de licencia a la <a href="https://reference.aspose.com/tasks/net/aspose.tasks/license" target="_blank" rel="nofollow noopener noreferrer">Licencia</a> clase <a href="https://reference.aspose.com/tasks/net/aspose.tasks/license/methods/setlicense" target="_blank" rel="nofollow noopener noreferrer">EstablecerLicencia</a> método. La clase `License` encontrará automáticamente el archivo de licencia en los recursos incrustados.

### Aplicación de una licencia basada en uso (pay-per-use) {#applying-a-metered-pay-per-use-license}

Una licencia basada en medición es un mecanismo de licenciamiento que permite facturar a los clientes según el uso de las funciones de la API. Para obtener más detalles, consulte <a href="https://purchase.conholdate.com/faqs/licensing/metered" target="_blank">Sección de preguntas frecuentes sobre licencias por medición</a>. Para activar la licencia Metered, se necesitan claves pública y privada.

Aplicar una licencia Metered es tan sencillo como estas dos líneas de código:

```csharp
    var metered = new Metered();
    metered.SetMeteredKey("<public key>", "<private key>");
```
