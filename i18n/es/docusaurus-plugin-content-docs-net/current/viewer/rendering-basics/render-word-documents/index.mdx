<a href="https://products.groupdocs.com/viewer/net" target="_blank" rel="nofollow noopener noreferrer">GroupDocs.Viewer for .NET</a> le permite convertir sus documentos de Microsoft Word a los formatos HTML, PDF, PNG y JPEG. No es necesario utilizar Microsoft Word ni otros procesadores de texto para cargar y visualizar documentos de Word dentro de su aplicación .NET (web o de escritorio).

Para comenzar a utilizar la API GroupDocs.Viewer, cree una instancia de la clase <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer" target="_blank" rel="nofollow noopener noreferrer">Viewer</a>. Pase el documento que desea visualizar al constructor de la clase. Puede cargar el documento desde un archivo o un flujo. Llame a una de las sobrecargas del método <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer/methods/view/index" target="_blank" rel="nofollow noopener noreferrer">Viewer.View</a> para convertir el documento a formato HTML, PDF o imagen. Estos métodos le permiten renderizar todo el documento o páginas específicas.

## Formatos de archivo de procesamiento de texto admitidos {#supported-word-processing-file-formats}
  
GroupDocs.Viewer admite los siguientes formatos de archivo de procesamiento de texto:

* <a href="https://docs.fileformat.com/word-processing/docx" target="_blank" rel="nofollow noopener noreferrer">Documento de Microsoft Word</a> (.DOCX)  
* <a href="https://docs.fileformat.com/word-processing/doc" target="_blank" rel="nofollow noopener noreferrer">Documento de Microsoft Word 97-2003</a> (.DOC)  
* <a href="https://docs.fileformat.com/word-processing/docm" target="_blank" rel="nofollow noopener noreferrer">Documento habilitado para macros de Microsoft Word</a> (.DOCM)  
* <a href="https://docs.fileformat.com/word-processing/dot" target="_blank" rel="nofollow noopener noreferrer">Plantilla de Microsoft Word 97-2003</a> (.DOT)  
* <a href="https://docs.fileformat.com/word-processing/dotm" target="_blank" rel="nofollow noopener noreferrer">Plantilla habilitada para macros de Microsoft Word</a> (.DOTM)  
* <a href="https://docs.fileformat.com/word-processing/dotx" target="_blank" rel="nofollow noopener noreferrer">Plantilla de Microsoft Word</a> (.DOTX)  
* <a href="https://docs.fileformat.com/word-processing/odt" target="_blank" rel="nofollow noopener noreferrer">Texto OpenDocument</a> (.ODT)  
* <a href="https://docs.fileformat.com/word-processing/ott" target="_blank" rel="nofollow noopener noreferrer">Plantilla de texto OpenDocument</a> (.OTT)  
* <a href="https://docs.fileformat.com/word-processing/rtf" target="_blank" rel="nofollow noopener noreferrer">Documento de texto enriquecido</a> (.RTF)  
* <a href="https://docs.fileformat.com/word-processing/txt" target="_blank" rel="nofollow noopener noreferrer">Documento de texto sin formato</a> (.TXT)  

GroupDocs.Viewer puede detectar automáticamente el formato del documento basándose en la información del encabezado del archivo.

## Renderizar documentos de Word como HTML {#render-word-documents-as-html}
  
Cree una instancia de la clase <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/htmlviewoptions" target="_blank" rel="nofollow noopener noreferrer">HtmlViewOptions</a> y pásela al método <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer/methods/view/index" target="_blank" rel="nofollow noopener noreferrer">Viewer.View</a> para convertir un archivo de Word a HTML. Las propiedades de la clase `HtmlViewOptions` le permiten controlar el proceso de conversión. Por ejemplo, puede incrustar todos los recursos externos en el archivo HTML generado, minimizar el archivo de salida y optimizarlo para su impresión. Consulte la siguiente sección de documentación para obtener más detalles: [Renderizado en HTML](/net/viewer/developer-guide/rendering-documents/rendering-to-html/).

### Crear un archivo HTML con recursos incrustados {#create-an-html-file-with-embedded-resources}
  
Para guardar todos los elementos de una página HTML (incluidos texto, gráficos y hojas de estilo) en un único archivo, llame al método <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/htmlviewoptions/methods/forembeddedresources/index" target="_blank" rel="nofollow noopener noreferrer">HtmlViewOptions.ForEmbeddedResources</a> y especifique el nombre del archivo de salida.

<Tabs groupId="example1">

<TabItem value="c" label="C#" default>

```csharp
using GroupDocs.Viewer;
using GroupDocs.Viewer.Options;
// ...

using (var viewer = new Viewer("resume.docx"))
{
    // Create an HTML file for each document page.
    // {0} is replaced with the current page number in the file name.
    var viewOptions = HtmlViewOptions.ForEmbeddedResources("page_{0}.html");
    viewer.View(viewOptions);
}
```

</TabItem>

<TabItem value="vb-net" label="VB.NET">

```vb

Imports GroupDocs.Viewer.Options
' ...

            ' {0} is replaced with the current page number in the file name.
            Dim viewOptions = HtmlViewOptions.ForEmbeddedResources("page_{0}.html")
            viewer.View(viewOptions)
        End Using
    End Sub
End Module
```

</TabItem>

### Crear un archivo HTML con recursos externos  {#create-an-html-file-with-external-resources}
  
Si desea almacenar un archivo HTML y archivos de recursos adicionales (como fuentes, imágenes y hojas de estilos) por separado, invoque el método <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/htmlviewoptions/methods/forexternalresources/index" target="_blank" rel="nofollow noopener noreferrer">HtmlViewOptions.ForExternalResources</a> y pase los siguientes parámetros:

  * El formato de la ruta del archivo de salida  
  * El formato de la ruta de la carpeta que contiene los recursos externos  
  * El formato de la URL del recurso

<Tabs groupId="example2">

<TabItem value="c" label="C#" default>

```csharp
using GroupDocs.Viewer;
using GroupDocs.Viewer.Options;
// ...

using (var viewer = new Viewer("resume.docx"))
{
    // Create an HTML file for each document page.
    // Specify the HTML file names and location of external resources.
    // {0} and {1} are replaced with the current page number and resource name, respectively.
    var viewOptions = HtmlViewOptions.ForExternalResources("page_{0}.html", "page_{0}/resource_{0}_{1}", "page_{0}/resource_{0}_{1}");
    viewer.View(viewOptions);
}
```

</TabItem>

<TabItem value="vb-net" label="VB.NET">

```vb

Imports GroupDocs.Viewer.Options
' ...

Module Program
    Sub Main(args As String())
        Using viewer = New Viewer("resume.docx")
            ' Create an HTML file for each document page.
            ' Specify the HTML file names and location of external resources.
            ' {0} and {1} are replaced with the current page number and resource name, respectively.
            Dim viewOptions = HtmlViewOptions.ForExternalResources("page_{0}.html", "page_{0}/resource_{0}_{1}", "page_{0}/resource_{0}_{1}")
            viewer.View(viewOptions)
        End Using
    End Sub
End Module
```

</TabItem>

## Renderizar documentos de Word como PNG {#render-word-documents-as-png}

## Definir los márgenes de página {#define-page-margins}
  
Utilice las siguientes propiedades para especificar el tamaño de los márgenes de página en los archivos de salida cuando convierta sus documentos de Word a formatos HTML, PDF e imágenes:  

* <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/wordprocessingoptions/properties/topmargin" target="_blank" rel="nofollow noopener noreferrer">WordProcessingOptions.TopMargin</a> especifica la distancia (en puntos) entre el contenido del documento y el borde superior de la página.  
* <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/wordprocessingoptions/properties/bottommargin" target="_blank" rel="nofollow noopener noreferrer">WordProcessingOptions.BottomMargin</a> especifica la distancia (en puntos) entre el contenido del documento y el borde inferior de la página.  
* <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/wordprocessingoptions/properties/leftmargin" target="_blank" rel="nofollow noopener noreferrer">WordProcessingOptions.LeftMargin</a> especifica la distancia (en puntos) entre el contenido del documento y el borde izquierdo de la página.  
* <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/wordprocessingoptions/properties/rightmargin" target="_blank" rel="nofollow noopener noreferrer">WordProcessingOptions.RightMargin</a> especifica la distancia (en puntos) entre el contenido del documento y el borde derecho de la página.  

Puede acceder a estas propiedades en las siguientes clases:  

| Clase |  
|-------|  
| <a href="https://reference.groupdocs.com/net/viewer/groupdocs.viewer.options/htmlviewoptions" target="_blank" rel="nofollow noopener noreferrer">HtmlViewOptions</a> |  
| <a href="https://reference.groupdocs.com/net/viewer/groupdocs.viewer.options/pdfviewoptions" target="_blank" rel="nofollow noopener noreferrer">PdfViewOptions</a> |  
| <a href="https://reference.groupdocs.com/net/viewer/groupdocs.viewer.options/pngviewoptions" target="_blank" rel="nofollow noopener noreferrer">PngViewOptions</a> |  
| <a href="https://reference.groupdocs.com/net/viewer/groupdocs.viewer.options/jpgviewoptions" target="_blank" rel="nofollow noopener noreferrer">JpgViewOptions</a> |  

El ejemplo siguiente convierte un documento de Word a HTML y especifica los márgenes de página para el archivo de salida. 

<Tabs groupId="example6">

<TabItem value="c" label="C#" default>


## Renderizar cambios rastreados {#render-tracked-changes}
  
GroupDocs.Viewer no renderiza los cambios rastreados (modificaciones realizadas en un documento de Word) de forma predeterminada. Si desea mostrar los cambios rastreados en el archivo de salida, habilite la propiedad <a href="https://reference.groupdocs.com/net/viewer/groupdocs.viewer.options/wordprocessingoptions/properties/rendertrackedchanges" target="_blank" rel="nofollow noopener noreferrer">WordProcessingOptions.RenderTrackedChanges</a> para una de las siguientes clases (según el formato del archivo de salida):

| Clase | Descripción |
|-------|-------------|
| <a href="https://reference.groupdocs.com/net/viewer/groupdocs.viewer.options/htmlviewoptions" target="_blank" rel="nofollow noopener noreferrer">HtmlViewOptions</a> | Para generar salida en formato HTML |
| <a href="https://reference.groupdocs.com/net/viewer/groupdocs.viewer.options/pdfviewoptions" target="_blank" rel="nofollow noopener noreferrer">PdfViewOptions</a> | Para generar salida en formato PDF |
| <a href="https://reference.groupdocs.com/net/viewer/groupdocs.viewer.options/pngviewoptions" target="_blank" rel="nofollow noopener noreferrer">PngViewOptions</a> | Para generar salida en formato PNG |
| <a href="https://reference.groupdocs.com/net/viewer/groupdocs.viewer.options/jpgviewoptions" target="_blank" rel="nofollow noopener noreferrer">JpgViewOptions</a> | Para generar salida en formato JPG |

El siguiente ejemplo de código demuestra cómo renderizar un documento de Word con cambios rastreados:

<Tabs groupId="example7">

<TabItem value="c" label="C#" default>

```csharp
using GroupDocs.Viewer;
using GroupDocs.Viewer.Options;
// ...

using (var viewer = new Viewer("TrackChanges.docx"))
{
    // Convert the document to PDF.
    var viewOptions = new PdfViewOptions("output.pdf");
    // Enable tracked changes rendering.
    viewOptions.WordProcessingOptions.RenderTrackedChanges = true;
    viewer.View(viewOptions);
}
```

</TabItem>

```vb

```

</TabItem>

## Desvincular tabla de contenido {#unlink-table-of-contents}
  
Al generar HTML o PDF, puede establecer <a href="https://reference.groupdocs.com/net/viewer/groupdocs.viewer.options/wordprocessingoptions/properties/unlinktableofcontents" target="_blank" rel="nofollow noopener noreferrer">WordProcessingOptions.UnlinkTableOfContents</a> en `true` para desvincular la tabla de contenido. Para la generación de HTML, las etiquetas `<a>` con enlaces relativos se reemplazarán por etiquetas `<span>`, eliminando la funcionalidad pero preservando la apariencia visual. Para la generación de PDF, la tabla de contenido se representará como texto sin enlaces a las secciones del documento.  

El ejemplo de código siguiente genera un documento de Word que contiene una tabla de contenido como texto sin enlaces.

<Tabs groupId="example9">

<TabItem value="c" label="C#" default>

```csharp
using GroupDocs.Viewer;
using GroupDocs.Viewer.Options;
// ...

using (var viewer = new Viewer("resume.docx"))
{
    // Convert the document to HTML.
    var viewOptions = HtmlViewOptions.ForEmbeddedResources();
    // Unlink table of contents.
```

## Deshabilitar la actualización de campos al guardar  {#disable-updating-fields-when-saving}

La mayoría de los formatos dentro de la familia de formatos WordProcessing, como DOC, DOCX, ODT, etc., tienen el concepto de <a href="https://support.microsoft.com/en-us/office/list-of-field-codes-in-word-1ad6d91a-55a7-4a8d-b535-cf7888659a51" target="_blank" rel="nofollow noopener noreferrer">campos</a>, los cuales se procesan cuando el documento se abre en alguna aplicación visora, como Microsoft Word. Cuando el documento WordProcessing de entrada se carga en GroupDocs.Viewer y se guarda en formatos de salida como HTML (con recursos incrustados o externos), PDF, PNG o JPEG, todos los campos del documento de entrada se actualizan durante el guardado, imitando así el comportamiento de Microsoft Word. Sin embargo, en algunos escenarios, por ejemplo, cuando los valores de los campos son incorrectos, no es necesario e incluso no es deseable actualizar los campos.

A partir de la versión <a href="https://releases.groupdocs.com/viewer/net/release-notes/2024/groupdocs-viewer-for-net-24-12-release-notes/" target="_blank" rel="nofollow noopener noreferrer">24.12</a>, GroupDocs.Viewer for .NET obtuvo la capacidad de deshabilitar la actualización de campos al guardar los documentos. Se agregó la nueva propiedad pública <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/wordprocessingoptions/updatefields/" target="_blank" rel="nofollow noopener noreferrer">`UpdateFields`</a> de tipo <a href="https://learn.microsoft.com/dotnet/api/system.boolean" target="_blank" rel="nofollow noopener noreferrer">`System.Boolean`</a> a la clase <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/wordprocessingoptions/" target="_blank" rel="nofollow noopener noreferrer">`Options.WordProcessingOptions`</a>. De forma predeterminada, el valor de esta propiedad se establece en `true`, por lo que los campos se actualizan, como antes. Para desactivar la actualización de campos, establezca esta propiedad en `false`. El siguiente ejemplo de código muestra cómo abrir un documento DOCX de ejemplo y guardarlo en formatos HTML con recursos incrustados y PDF, sin actualizar los campos durante el guardado.

<Tabs groupId="example-UpdateFields">

<TabItem value="c" label="C#" default>

```csharp
using GroupDocs.Viewer;
using GroupDocs.Viewer.Options;
// ...

HtmlViewOptions htmlViewOptions = HtmlViewOptions.ForEmbeddedResources();
htmlViewOptions.WordProcessingOptions.UpdateFields = false;

PdfViewOptions pdfViewOptions = new PdfViewOptions("output.pdf");
pdfViewOptions.WordProcessingOptions.UpdateFields = false;

using (var viewer = new Viewer("resume.docx"))
{    
    viewer.View(htmlViewOptions);
	viewer.View(pdfViewOptions);
}
```

</TabItem>

## Eliminar o conservar JavaScript al guardar en HTML {#remove-or-preserve-javascript-when-saving-to-html}
  
La mayoría de los formatos de procesamiento de textos, como DOC, DOCX, ODT, etc., pueden almacenar scripts, generalmente escritos en VBA. Cuando el formato de salida es PDF, PNG o JPEG, no hay ningún problema. Sin embargo, cuando el formato de salida es HTML, esto puede provocar situaciones en las que scripts VBA maliciosos o dañinos del documento de entrada DOCX, por ejemplo, se traduzcan al documento HTML resultante. Antes de la <a href="https://releases.groupdocs.com/viewer/net/release-notes/2025/groupdocs-viewer-for-net-25-1-release-notes/" target="_blank" rel="nofollow noopener noreferrer">versión 25.1</a>, no existía la posibilidad de que el GroupDocs.Viewer desactivara la conservación y traducción de scripts: todos los scripts VBA se traducían a JavaScript en HTML. A partir de la versión 25.1, por motivos de seguridad, la traducción de scripts está desactivada de forma predeterminada: todos los enlaces que contienen JavaScript se sustituyen por la cadena inofensiva `"javascript:void(0)"` en la marca HTML resultante. No obstante, es posible activar la traducción de scripts, como ocurría en el GroupDocs.Viewer anterior, mediante la nueva propiedad pública `RemoveJavaScript` del tipo <a href="https://learn.microsoft.com/dotnet/api/system.boolean" target="_blank" rel="nofollow noopener noreferrer">`System.Boolean`</a> en la clase <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/htmlviewoptions/" target="_blank" rel="nofollow noopener noreferrer">`Options.HtmlViewOptions`</a>. De forma predeterminada, esta propiedad tiene el valor `true`: el JavaScript se eliminará del documento HTML resultante. Para conservar el JavaScript, como ocurría en las versiones anteriores del GroupDocs.Viewer, se debe asignar el valor `false` a esta propiedad. El siguiente ejemplo de código muestra cómo abrir un documento DOCX de ejemplo y renderizarlo en HTML con recursos incrustados, tanto con como sin JavaScript.

<Tabs groupId="example-RemoveJavaScript">

<TabItem value="c" label="C#" default>

```csharp
using GroupDocs.Viewer;
using GroupDocs.Viewer.Options;
// ...

HtmlViewOptions htmlViewOptionsWithoutJavaScript = HtmlViewOptions.ForEmbeddedResources("without-js-page{0}.html");

HtmlViewOptions htmlViewOptionsWithJavaScript = HtmlViewOptions.ForEmbeddedResources("with-js-page{0}.html");
htmlViewOptionsWithJavaScript.RemoveJavaScript = false;

using (var viewer = new Viewer("Doc-with-VBA.docx"))
{
    viewer.View(htmlViewOptionsWithoutJavaScript);
    viewer.View(htmlViewOptionsWithJavaScript);
}
```

</TabItem>

<TabItem value="vb-net" label="VB.NET">


## Especificar DPI al renderizar a formatos de mapa de bits {#specify-dpi-when-rendering-to-raster-formats}
  
Antes de la versión 26.8, al renderizar documentos WordProcessing cargados a formatos de mapa de bits ([PNG](#render-word-documents-as-png) y [JPEG](#render-word-documents-as-jpeg)), la resolución horizontal y vertical de la imagen resultante siempre era fija e igual a `96` DPI (puntos por pulgada). Como consecuencia, era imposible aumentar significativamente la calidad de las imágenes generadas. Para solucionar este problema, la <a href="https://releases.groupdocs.com/viewer/net/release-notes/2026/groupdocs-viewer-for-net-26-8-release-notes/" target="_blank" rel="nofollow noopener noreferrer">versión 26.8</a> introduce dos nuevas propiedades en <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/wordprocessingoptions/" target="_blank" rel="nofollow noopener noreferrer">`WordProcessingOptions`</a>: `HorizontalResolution` y `VerticalResolution`, ambas de tipo `Int32`, responsables respectivamente de la resolución horizontal y vertical.

De forma predeterminada, sus valores son `96` DPI, igual que en todas las versiones anteriores de GroupDocs.Viewer. Sin embargo, ahora el usuario puede modificar estos valores. El valor mínimo posible es `72` DPI: incluso si el usuario especifica un número menor, se aplicará `72` DPI. Asimismo, existe un valor máximo posible: `600` DPI. Si se especifican valores superiores, se aplicará `600` DPI. Esto es válido tanto para `HorizontalResolution` como para `VerticalResolution`.

Es necesario destacar adicionalmente que estas dos propiedades solo son válidas al renderizar a los formatos PNG y JPEG; para otros formatos, se ignoran.

El siguiente código fuente muestra el renderizado del documento cargado «sample.docs» al formato PNG, con resoluciones horizontal y vertical ajustadas a 192 DPI, y al formato JPEG, donde la resolución horizontal permanece sin cambios y predeterminada (96 DPI), mientras que solo se ajusta la resolución vertical: 120 DPI.

<Tabs groupId="example-SpecifyCustomResolution">

<TabItem value="c" label="C#" default>

```csharp
using GroupDocs.Viewer;
using GroupDocs.Viewer.Options;
// ...

PngViewOptions pngOpt = new PngViewOptions();
pngOpt.WordProcessingOptions.HorizontalResolution = pngOpt.WordProcessingOptions.VerticalResolution = 192;

JpgViewOptions jpegOpt = new JpgViewOptions();
jpegOpt.WordProcessingOptions.VerticalResolution = 120;

using (Viewer viewer = new Viewer("sample.docx"))
{
    viewer.View(pngOpt);
    viewer.View(jpegOpt);
}
```

</TabItem>


## Agregar números de página durante la renderización {#add-page-numbers-during-rendering}

De forma predeterminada, el GroupDocs.Viewer procesa los documentos de WordProcessing de entrada «tal como están», sin realizar ningún cambio. Esto también aplica a los números de página: cuando están presentes en el archivo original, también aparecerán en el PDF, HTML, PNG y JPEG generados, y viceversa. Inicialmente, no existía la posibilidad de agregar forzosamente los números de página a los documentos de salida generados.

Sin embargo, esto ha cambiado desde la versión 26.8. A partir de esta versión, es posible aplicar la numeración de páginas a los documentos de WordProcessing. Nota importante: el archivo de WordProcessing de entrada no se modifica en absoluto, independientemente de las opciones aplicadas. La característica descrita únicamente afecta a los documentos de salida generados por el GroupDocs.Viewer a partir de los archivos de entrada de Word.

Esta característica presenta el siguiente comportamiento: una nueva propiedad `PageNumberLocation` se agregó a la <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/wordprocessingoptions/" target="_blank" rel="nofollow noopener noreferrer">`WordProcessingOptions`</a> clase, que es accesible desde el <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/baseviewoptions/wordprocessingoptions/" target="_blank" rel="nofollow noopener noreferrer">`WordProcessingOptions`</a> propiedad. Es de tipo enum `WordsPageNumberLocation` y su valor predeterminado es `NotApply` - esto significa que, de forma predeterminada, los documentos de WordProcessing de entrada se renderizan como antes: cuando un documento de entrada tiene números de página, estos están presentes en los documentos de salida, pero cuando no los tiene, los números de página están ausentes. Pero cuando cualquier otro valor de `WordsPageNumberLocation` enum except from of `NotApply` se especifica en el `PageNumberLocation` propiedad, GroupDocs.Viewer agrega forzosamente los números de página a los documentos de salida generados. Si el documento original ya tenía los números de página, estos se eliminan inicialmente de los documentos de salida y luego se agregan los nuevos números de página.

El `WordsPageNumberLocation` el enum en realidad tiene 2 funciones: aplica forzosamente los números de página a las páginas y también especifica la posición donde deben ubicarse los números de página: `TopLeft`, `TopCenter`, `TopRight`, `BottomLeft`, `BottomCenter`, `BottomRight`Los números de página con ubicaciones diferentes pueden aplicarse a distintos formatos de salida para el mismo documento de entrada de WordProcessing. El ejemplo de código anterior muestra la aplicación de números de página en la esquina superior izquierda para la salida en PDF y números de página en el centro inferior para la salida en HTML.

<Tabs groupId="example-AddingPageNumbers">

<TabItem value="c" label="C#" default>

```csharp
using GroupDocs.Viewer;
using GroupDocs.Viewer.Options;
// ...

PdfViewOptions pdfOpt = new PdfViewOptions();
pdfOpt.WordProcessingOptions.PageNumberLocation = WordsPageNumberLocation.TopLeft;

HtmlViewOptions htmlEmbeddedOpt = HtmlViewOptions.ForEmbeddedResources();
htmlEmbeddedOpt.WordProcessingOptions.PageNumberLocation = WordsPageNumberLocation.BottomCenter;

using (Viewer viewer = new Viewer("sample.docx"))
{
    viewer.View(pdfOpt);
    viewer.View(htmlEmbeddedOpt);
}
```

</TabItem>
