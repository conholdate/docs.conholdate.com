<a href="https://products.groupdocs.com/viewer/net" target="_blank" rel="nofollow noopener noreferrer">GroupDocs.Viewer for .NET</a> le permite representar sus archivos PDF en formatos HTML, PNG y JPEG. Utilice esta biblioteca para implementar un visor de PDF sencillo dentro de su aplicación .NET (web o de escritorio).

Cree una instancia de la clase <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer" target="_blank" rel="nofollow noopener noreferrer">Viewer</a> para comenzar a utilizar la API de GroupDocs.Viewer. Pase al constructor de la clase el documento que desea visualizar; puede cargarlo desde un archivo o un flujo. Llame a una de las sobrecargas del método <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer/methods/view/index" target="_blank" rel="nofollow noopener noreferrer">Viewer.View</a> para convertir el documento en formato HTML o de imagen. Estos métodos le permiten representar todo el documento o páginas específicas.

## Formatos de archivo de diseño de página admitidos {#supported-page-layout-file-formats}
  
GroupDocs.Viewer admite los siguientes formatos de archivo PDF y de diseño de página:

* <a href="https://docs.fileformat.com/pdf/" target="_blank" rel="nofollow noopener noreferrer">Portable Document Format</a> (.PDF)  
* <a href="https://docs.fileformat.com/page-description-language/xps/" target="_blank" rel="nofollow noopener noreferrer">Microsoft XML Paper Specification</a> (.XPS)  
* <a href="https://docs.fileformat.com/page-description-language/oxps/" target="_blank" rel="nofollow noopener noreferrer">Open XML Paper Specification</a> (.OXPS)  
* <a href="https://docs.fileformat.com/page-description-language/tex/" target="_blank" rel="nofollow noopener noreferrer">LaTeX Source Document</a> (.TEX)  
* <a href="https://www.zhihuilib.com/en/article/detail/2/12" target="_blank" rel="nofollow noopener noreferrer">Open Fixed-layout Document</a> (.OFD)  

GroupDocs.Viewer puede detectar automáticamente el formato del documento basándose en la información del encabezado del archivo.

## Representar archivos PDF como HTML {#render-pdf-files-as-html}
  
Cree una instancia de la clase <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/htmlviewoptions" target="_blank" rel="nofollow noopener noreferrer">HtmlViewOptions</a> y pásela al método <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer/methods/view/index" target="_blank" rel="nofollow noopener noreferrer">Viewer.View</a> para convertir un archivo PDF en HTML. Las propiedades de la clase `HtmlViewOptions` le permiten controlar el proceso de conversión. Por ejemplo, puede incrustar todos los recursos externos en el archivo HTML generado, minimizar el archivo de salida y optimizarlo para su impresión. Consulte la siguiente sección de documentación para obtener más detalles: [Representación en HTML](/net/viewer/developer-guide/rendering-documents/rendering-to-html/).

### Crear un archivo HTML con recursos incrustados {#create-an-html-file-with-embedded-resources}
  
Para guardar todos los elementos de una página HTML (incluidos texto, gráficos y hojas de estilo) en un único archivo, llame al método <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/htmlviewoptions/methods/forembeddedresources/index" target="_blank" rel="nofollow noopener noreferrer">HtmlViewOptions.ForEmbeddedResources</a> y especifique el nombre del archivo de salida.

<Tabs groupId="example1">

<TabItem value="c" label="C#" default>

```csharp
using GroupDocs.Viewer;
using GroupDocs.Viewer.Options;
// ...

using (var viewer = new Viewer("resume.pdf"))
{
    // Create an HTML file for each PDF page.
    // {0} is replaced with the current page number in the file name.
    var viewOptions = HtmlViewOptions.ForEmbeddedResources("page_{0}.html");
    viewer.View(viewOptions);
}
```

</TabItem>

<TabItem value="vb-net" label="VB.NET">

```vb

Imports GroupDocs.Viewer.Options

            ' {0} is replaced with the current page number in the file name.
            Dim viewOptions = HtmlViewOptions.ForEmbeddedResources("page_{0}.html")
            viewer.View(viewOptions)
        End Using
    End Sub
End Module
```

</TabItem>

### Crear un archivo HTML con recursos externos  {#create-an-html-file-with-external-resources}
  
Si desea almacenar un archivo HTML y archivos de recursos adicionales (como fuentes, imágenes y hojas de estilo) por separado, invoque el método <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/htmlviewoptions/methods/forexternalresources/index" target="_blank" rel="nofollow noopener noreferrer">HtmlViewOptions.ForExternalResources</a> y pase los siguientes parámetros:

  * El formato de la ruta del archivo de salida  
  * El formato de la ruta de la carpeta con los recursos externos  
  * El formato de la URL del recurso

<Tabs groupId="example2">

<TabItem value="c" label="C#" default>

```csharp
using GroupDocs.Viewer;
using GroupDocs.Viewer.Options;
// ...

using (var viewer = new Viewer("resume.pdf"))
{
    // Create an HTML file for each PDF page.
    // Specify the HTML file names and location of external resources.
    // {0} and {1} are replaced with the current page number and resource name, respectively.
    var viewOptions = HtmlViewOptions.ForExternalResources("page_{0}.html", "page_{0}/resource_{0}_{1}", "page_{0}/resource_{0}_{1}");
    viewer.View(viewOptions);
}
```

</TabItem>

```vb
            Dim viewOptions = HtmlViewOptions.ForExternalResources("page_{0}.html", "page_{0}/resource_{0}_{1}", "page_{0}/resource_{0}_{1}")
```

### Crear HTML con diseño fijo {#create-html-with-fixed-layout}
  
De forma predeterminada, los documentos PDF y EPUB se renderizan en HTML con diseño fijo para garantizar que el HTML resultante tenga el mismo aspecto que el documento original. El renderizado con diseño fijo implica que todos los elementos HTML se posicionan de forma absoluta respecto al elemento contenedor. Además, el elemento contenedor tiene un tamaño fijo, por lo que el cambio de tamaño de la ventana del navegador no afectará la posición ni el tamaño de los elementos del documento.

La siguiente imagen muestra un documento PDF renderizado en HTML con diseño fijo:

![Create HTML with fixed layout](/net/viewer/images/rendering-basics/render-pdf-documents/render-pdf-to-html-with-fixed-layout.png)

### Crear HTML con diseño fluido  {#create-html-with-fluid-layout}
  
Al generar HTML con diseño fluido, el documento HTML no tiene un tamaño fijo. En caso de redimensionar la ventana del navegador, el contenido del documento intenta adaptarse a ella. Para crear HTML con diseño fluido, establezca la propiedad <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/pdfoptions/fixedlayout/" target="_blank" rel="nofollow noopener noreferrer">PdfOptions.FixedLayout</a> en `false`. 

<Tabs groupId="example3">

<TabItem value="c" label="C#" default>

```csharp
using GroupDocs.Viewer;
using GroupDocs.Viewer.Options;
// ...

using (var viewer = new Viewer("Letter.pdf"))
{
    // Create an HTML file for each PDF page.
    // {0} is replaced with the current page number in the file name.
    var viewOptions = HtmlViewOptions.ForEmbeddedResources("page_{0}.html");
    // Disable fixed layout.
    viewOptions.PdfOptions.FixedLayout = false;
    viewer.View(viewOptions);
}
```

</TabItem>

```vb
            ' Disable fixed layout.

            viewer.View(viewOptions)
        End Using

```

</TabItem>

### Ajustar la calidad de las imágenes en el archivo HTML de salida {#adjust-image-quality-in-the-output-html-file}
  
La opción <a href="https://reference.groupdocs.com/net/viewer/groupdocs.viewer.options/pdfoptions/properties/imagequality" target="_blank" rel="nofollow noopener noreferrer">HtmlViewOptions.PdfOptions.ImageQuality</a> le permite especificar la calidad de las imágenes en el archivo HTML de salida. Puede establecer esta propiedad en uno de los siguientes valores:

* <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/imagequality" target="_blank" rel="nofollow noopener noreferrer">ImageQuality.Low</a> — La resolución de la imagen es baja (96 DPI) y el tamaño de la imagen es pequeño. Utilice este valor para mejorar el rendimiento de la conversión.  
* <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/imagequality" target="_blank" rel="nofollow noopener noreferrer">ImageQuality.Medium</a> — La resolución de la imagen es media (192 DPI) y el tamaño de la imagen es mayor en comparación con las imágenes de baja calidad.  
* <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/imagequality" target="_blank" rel="nofollow noopener noreferrer">ImageQuality.High</a> — La resolución de la imagen es alta (300 DPI) y el tamaño de la imagen es grande. El uso de este valor puede disminuir el rendimiento de la conversión.  

El siguiente fragmento de código muestra cómo establecer una calidad media de imagen al convertir un documento PDF a HTML:

<Tabs groupId="example4">

<TabItem value="c" label="C#" default>

```csharp
using GroupDocs.Viewer;
using GroupDocs.Viewer.Options;
// ...

using (var viewer = new Viewer("resume.pdf"))
{
    // Create an HTML file for each document page.
    // {0} is replaced with the current page number in the file name.
    var viewOptions = HtmlViewOptions.ForEmbeddedResources("page_{0}.html");
    // Set image quality to medium.
    viewOptions.PdfOptions.ImageQuality = ImageQuality.Medium;
    viewer.View(viewOptions);
}
```

</TabItem>

<TabItem value="vb-net" label="VB.NET">


### Renderizar texto como imagen  {#render-text-as-an-image}
  
GroupDocs.Viewer admite la opción <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/pdfoptions/properties/rendertextasimage" target="_blank" rel="nofollow noopener noreferrer">HtmlViewOptions.PdfOptions.RenderTextAsImage</a>, que le permite renderizar el texto como una imagen al convertir un archivo PDF a HTML. En este caso, el diseño del archivo HTML resultante refleja fielmente el diseño del documento PDF original.  

El siguiente fragmento de código muestra cómo habilitar esta opción mediante código:

```csharp
using GroupDocs.Viewer;

    viewOptions.PdfOptions.RenderTextAsImage = true;
    viewer.View(viewOptions);
}
```

### Habilitar renderizado en múltiples capas {#enable-multi-layer-rendering}
  
Cuando convierte un archivo PDF a HTML, GroupDocs.Viewer crea un documento HTML con una sola capa (el `z-index` no se especifica para los elementos del documento). Esto ayuda a mejorar el rendimiento y reducir el tamaño del archivo de salida. Si convierte un documento PDF con múltiples capas y desea mejorar la posición de los elementos del documento en el archivo HTML de salida, active la propiedad <a href="https://reference.groupdocs.com/net/viewer/groupdocs.viewer.options/pdfoptions/properties/enablelayeredrendering" target="_blank" rel="nofollow noopener noreferrer">HtmlViewOptions.PdfOptions.EnableLayeredRendering</a> para renderizar texto y gráficos en el archivo HTML según su orden en profundidad (z-order) en el documento PDF original.  

El siguiente fragmento de código muestra cómo habilitar el renderizado en múltiples capas:

<Tabs groupId="example6">

<TabItem value="c" label="C#" default>

```csharp
using GroupDocs.Viewer;
using GroupDocs.Viewer.Options;
// ...

using (var viewer = new Viewer("sample.pdf"))
{
    // Create an HTML file for each document page.
    // {0} is replaced with the current page number in the file name.
    var viewOptions = HtmlViewOptions.ForEmbeddedResources("page_{0}.html");
    // Enable the multi-layer rendering.
    viewOptions.PdfOptions.EnableLayeredRendering = true;
    viewer.View(viewOptions);
}
```

</TabItem>

### Conservar el tamaño de las páginas del documento  {#preserve-the-size-of-document-pages}
  
Cuando se renderizan documentos PDF como imágenes, GroupDocs.Viewer calcula el tamaño óptimo de la imagen para lograr una mejor calidad de renderizado. ## Obtener información sobre un archivo PDF {#get-information-about-a-pdf-file}

### Extraer texto de un archivo PDF {#extract-text-from-a-pdf-file}

## Reparación de documentos PDF corruptos {#repairing-corrupted-pdf-documents}
  
De forma predeterminada, GroupDocs.Viewer no puede procesar documentos PDF con estructura o contenido corrupto: lanza una excepción al intentar abrir dichos archivos. Sin embargo, a partir de la versión <a href="https://releases.groupdocs.com/viewer/net/release-notes/2024/groupdocs-viewer-for-net-24-5-release-notes/" target="_blank" rel="nofollow noopener noreferrer">24.5</a>, GroupDocs.Viewer puede intentar reparar las corrupciones estructurales en documentos PDF. De forma predeterminada, esta función está deshabilitada. Para habilitarla, es necesario utilizar la nueva propiedad booleana `TryRepair` de la clase <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/loadoptions/" target="_blank" rel="nofollow noopener noreferrer">`LoadOptions`</a>, estableciendo su valor en `true`.

Cuando está habilitada, esta función aborda los siguientes problemas en un documento PDF:

* Referencias rotas dentro del documento (desplazamientos incorrectos de objetos en la lista de referencias cruzadas).
* Elementos críticos ausentes, como el objeto raíz, el objeto de página o el contenido de la página.
* Referencias circulares (objeto X de formulario que se referencia a sí mismo).

A continuación se muestra un ejemplo de código fuente:

<Tabs groupId="example18">

<TabItem value="c" label="C#" default>

```csharp

using GroupDocs.Viewer.Options;
// ...

loadOptions.TryRepair = true;

PngViewOptions viewOptions = new PngViewOptions();

using (Viewer viewer = new Viewer("resume.pdf", loadOptions))
{    
    viewer.View(viewOptions);
}
```

## Renderizar documentos OFD {#render-ofd-documents}
  
A partir de la <a href="https://releases.groupdocs.com/viewer/net/release-notes/2024/groupdocs-viewer-for-net-24-12-release-notes/" target="_blank" rel="nofollow noopener noreferrer">versión 24.12</a>, el GroupDocs.Viewer comenzó a admitir el formato <a href="https://www.zhihuilib.com/en/article/detail/2/12" target="_blank" rel="nofollow noopener noreferrer">OFD</a> (Open Fixed-layout Document), definido por GB/T 33190-2016, cuyo objetivo es reemplazar al PDF en las instituciones públicas chinas. Para procesar _todos_ los documentos de este formato, el GroupDocs.Viewer requiere que la fuente <a href="https://learn.microsoft.com/en-us/typography/font-list/simsun" target="_blank" rel="nofollow noopener noreferrer">SimSun.ttf</a> esté instalada en el sistema operativo. Al utilizar Microsoft Windows, esto no debería suponer un problema, ya que SimSun viene preinstalada en todas las versiones y ediciones de Windows a partir de _Windows 7_ (por ejemplo, _Windows 7_ incluye preinstalada la versión <a href="https://learn.microsoft.com/en-us/typography/fonts/windows_7_font_list" target="_blank" rel="nofollow noopener noreferrer">5.03</a> de SimSun, mientras que _Windows 10_ incluye la versión <a href="https://learn.microsoft.com/en-us/typography/fonts/windows_10_font_list" target="_blank" rel="nofollow noopener noreferrer">5.16</a>). Sin embargo, en Linux, SimSun normalmente no está instalada, y al intentar procesar un archivo de este tipo en Linux se lanzará una `GroupDocsViewerException : Could not load file. File is corrupted or damaged. - Font SimSun was not found` excepción.

Para poder visualizar y guardar archivos OFD arbitrarios en Linux, la fuente SimSun.ttf debe cargarse en el GroupDocs.Viewer mediante la clase <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.fonts/folderfontsource/" target="_blank" rel="nofollow noopener noreferrer">`FolderFontSource`</a> y el método <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.fonts/fontsettings/setfontsources/" target="_blank" rel="nofollow noopener noreferrer">`FontSettings.SetFontSources`</a>, y esto debe realizarse _antes_ de instanciar la clase <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer/viewer/" target="_blank" rel="nofollow noopener noreferrer">`Viewer`</a> con el archivo OFD. El artículo <a href="https://docs.groupdocs.com/viewer/net/set-custom-fonts/" target="_blank" rel="nofollow noopener noreferrer">«Configurar fuentes personalizadas»</a> describe en detalle cómo configurar una fuente personalizada; a continuación se muestra un ejemplo breve de cómo configurar SimSun y guardar un archivo OFD como HTML en Linux:

<Tabs groupId="example19">

<TabItem value="c" label="C#" default>

```csharp
using GroupDocs.Viewer;
using GroupDocs.Viewer.Options;
using GroupDocs.Viewer.Fonts;
// ...

//Put a SimSun.ttf to folder
string SimSunFolderPath = "full-valid-path\folder-with-SimSun-inside";
FolderFontSource fontSource = new FolderFontSource(SimSunFolderPath, SearchOption.TopFolderOnly);
FontSettings.SetFontSources(fontSource);

using (Viewer viewer = new Viewer("input.ofd"))
{
    HtmlViewOptions viewOptions = HtmlViewOptions.ForEmbeddedResources();
    viewer.View(viewOptions);
}
```

## Renderizar anotaciones emergentes  {#render-popup-annotations}

Los documentos PDF pueden contener anotaciones específicas, representadas como **emergentes** (también llamadas *balloon hints* o *sugerencias globulares*), las cuales, por defecto, están ocultas pero aparecen cuando el usuario pasa el cursor del ratón sobre ellas y/o hace clic en ellas. Otro tipo de anotación, denominado **anotaciones de resaltado**, resaltan una porción de texto o una zona de la página, y al mismo tiempo pueden tener comentarios asociados, los cuales, nuevamente, están ocultos por defecto pero aparecen al hacer clic en el resaltado. Antes de la <a href="https://releases.groupdocs.com/viewer/net/release-notes/2026/groupdocs-viewer-for-net-26-8-release-notes/" target="_blank" rel="nofollow noopener noreferrer">versión 26.8</a> de GroupDocs.Viewer, no era posible visualizar estos tipos de anotaciones, independientemente del formato de salida seleccionado; la única forma de verlas era abrir el documento PDF original en un visor de PDF de escritorio, como Adobe Reader o Foxit Reader. No obstante, no existía la posibilidad de conservar estas anotaciones al convertir PDF a formatos HTML o de imagen rasterizada.

En la GroupDocs.Viewer versión 26.8, esto ha cambiado. Las anotaciones emergentes siguen estando ocultas por defecto (de modo que el comportamiento conocido y habitual de GroupDocs.Viewer permanece inalterado), pero pueden activarse. Desde sus inicios, GroupDocs.Viewer dispone de una propiedad booleana <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/baseviewoptions/rendernotes/" target="_blank" rel="nofollow noopener noreferrer">`RenderNotes`</a>, ubicada en la clase abstracta <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/baseviewoptions/" target="_blank" rel="nofollow noopener noreferrer">`BaseViewOptions`</a> y, por tanto, disponible para las 4 opciones de renderizado: PDF, HTML, PNG y JPEG. Inicialmente, la propiedad `RenderNotes` solo se aplicaba a las familias de formatos de Presentación (PPT, PPTX, PPTM, …) y de Microsoft Project (MPP, MPT, MPX), y al renderizar documentos PDF, dicha propiedad no tenía efecto alguno. En GroupDocs.Viewer versión 26.8, las cosas han cambiado: ahora esta propiedad sí se aplica al formato PDF y es la responsable de activar las anotaciones emergentes: cuando está desactivada por defecto (valor `false`), las anotaciones emergentes permanecen ocultas; pero cuando se activa (valor `true`), las anotaciones emergentes sí están presentes en los formatos de salida HTML e imagen rasterizada.

El siguiente ejemplo de código fuente muestra cómo cargar un archivo PDF y renderizarlo en HTML con recursos incrustados, así como en PNG y JPEG, con las anotaciones emergentes activadas.

<Tabs groupId="example_RenderNotes">

<TabItem value="c" label="C#" default>

```csharp
using GroupDocs.Viewer;
using GroupDocs.Viewer.Options;
// ...

// Preparing output options
PngViewOptions pngOpt = new PngViewOptions();
JpgViewOptions jpegOpt = new JpgViewOptions();
HtmlViewOptions htmlEmbeddedOpt = HtmlViewOptions.ForEmbeddedResources();

// Enabling "RenderNotes" for all options
pngOpt.RenderNotes = jpegOpt.RenderNotes = htmlEmbeddedOpt.RenderNotes = true;

// Loading sample PDF file
using (Viewer viewer = new Viewer("sample.pdf"))
{
    // Rendering to output formats
    viewer.View(pngOpt);
    viewer.View(jpegOpt);
    viewer.View(htmlEmbeddedOpt);
}
```

Una nota importante a mencionar: la clase <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/pdfoptions/" target="_blank" rel="nofollow noopener noreferrer">`PdfOptions`</a> posee una propiedad booleana <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/pdfoptions/enablelayeredrendering/" target="_blank" rel="nofollow noopener noreferrer">`EnableLayeredRendering`</a>, la cual funciona al convertir PDF al formato HTML y está deshabilitada (`false`) de forma predeterminada. Esto significa que, de forma predeterminada, todos los objetos, como texto y gráficos, están presentes en el HTML de salida como una única capa. Sin embargo, cuando la propiedad <a href="https://reference.groupdocs.com/viewer/net/groupdocs.viewer.options/baseviewoptions/rendernotes/" target="_blank" rel="nofollow noopener noreferrer">`RenderNotes`</a> está habilitada y el usuario convierte PDF a HTML, el valor interno de `EnableLayeredRendering` se establecerá en `true`, por lo que se aplicará la representación por capas incluso si `EnableLayeredRendering` se establece forzosamente en `false`.
