## Renderizado de documentos {#rendering-documents}
  
Utilizamos el término ["renderizado"](/java/viewer/developer-guide/rendering-documents/) en GroupDocs.Viewer para describir el proceso de convertir un documento en un formato de archivo paginado o que tenga el concepto de páginas. Por ejemplo, si tiene un archivo DOCX con tres páginas, al renderizar este archivo a HTML obtendrá tres archivos HTML en la salida que representen cada una de las páginas del documento.

![Rendering diagram](/java/viewer/images/getting-started/features-overview/rendering.png)

### Renderizado a HTML {#rendering-to-html}
  
El renderizado a HTML es la opción más adecuada cuando se cumplen los siguientes requisitos:

* Estás desarrollando una aplicación basada en web;  
* El contenido del documento debe mostrarse dentro de un navegador web;  
* Necesitas interactuar con el texto del documento renderizado: seleccionarlo, copiarlo o buscar en él;  
* Deseas visualizar las páginas del documento por separado;  
* Necesitas ampliar el documento sin pérdida de calidad en la mayoría de los casos;  
* Quieres rotar, reordenar páginas o añadir marcas de agua.

GroupDocs.Viewer para Java ofrece dos opciones de gestión de recursos para CSS, fuentes, imágenes, etc.:

* **Renderizado a HTML con recursos externos**: almacena los recursos de la página junto con el archivo HTML, lo que permite reutilizar recursos comunes entre páginas distintas y reduce significativamente el tamaño y el tiempo de carga de cada página.  
* **Renderizado a HTML con recursos incrustados**: integra los recursos de la página directamente en el HTML, haciendo que cada página del documento sea autónoma. La desventaja es que el tamaño de la página y el tiempo de carga pueden aumentar.

### Renderizado a PNG o JPEG {#rendering-to-png-or-jpeg}
  
El renderizado a PNG o JPEG es la opción más adecuada cuando se cumplen los siguientes requisitos:

* Estás desarrollando cualquier tipo de aplicación;  
* No necesitas renderizar contenido textual o deseas restringir la interacción con el texto del documento renderizado. Por ejemplo: evitar la copia de texto. Aun así, puedes extraer el texto del documento si deseas añadir una capa de texto seleccionable sobre la imagen de la página (descrita a continuación);  
* Deseas visualizar las páginas del documento por separado;  
* Quieres rotar, reordenar páginas o añadir marcas de agua.

A continuación se presenta una breve descripción de ambos formatos de imagen, lo que puede ayudarte a elegir el más adecuado para tu caso:

* **Formato PNG**: es un formato de gráficos rasterizados sin pérdida que admite imágenes a todo color y transparencia. No es posible ajustar la calidad de la imagen PNG guardada. PNG es una buena opción para almacenar dibujos a línea, texto y gráficos icónicos con tamaños de archivo reducidos.  
* **Formato JPEG**: es un formato de archivo comprimido con pérdida que permite ajustar la calidad de la imagen guardada: al reducir la calidad, se eliminan detalles y se añade ruido a la imagen, aunque el tamaño del archivo se vuelve más compacto. JPEG es óptimo para imágenes con gran cantidad de colores (por ejemplo, fotografías). Es una opción común en la web debido a su eficaz compresión.

### Renderizado a PDF {#rendering-to-pdf}
  
GroupDocs.Viewer renderiza un documento como un único archivo PDF, por lo que el renderizado a PDF es la opción más adecuada cuando se cumplen los siguientes requisitos:

* Vas a imprimir documentos;  
* Deseas enviar documentos por correo electrónico;  
* No deseas mostrar las páginas del documento por separado, ya que todas las páginas del documento original se renderizan como un único archivo PDF.

## Obtención de información del documento {#retrieving-document-information}
  
GroupDocs.Viewer para Java permite obtener información básica sobre los documentos fuente, como el tipo de archivo, el número de páginas, el texto con coordenadas, etc.

Para los siguientes formatos de documento, también es posible extraer información adicional:

* **Archivos comprimidos**: lista de carpetas contenidas en el archivo;  
* **CAD**: lista de capas y diseños en un documento CAD;  
* **Correo electrónico**: lista de carpetas contenidas en un archivo de datos de Outlook;  
* **PDF**: información sobre las restricciones de impresión del documento;  
* **Gestión de proyectos**: fechas de inicio y finalización del proyecto.

### Extracción de texto {#text-extraction}
  
Puedes optar por extraer el texto del documento al renderizar a PNG o JPEG, y el texto puede extraerse junto con las coordenadas de cada palabra individual.

Esto resulta útil si deseas añadir una capa de texto seleccionable sobre la imagen de la página.

## Procesamiento de adjuntos {#processing-attachments}
  
En GroupDocs.Viewer utilizamos el término *adjuntos* para referirnos a archivos adjuntos de correo electrónico, archivos incrustados y archivos comprimidos.

Con GroupDocs.Viewer puedes listar y guardar:

* Archivos adjuntos de correo electrónico;  
* Archivos incrustados en documentos PDF;  
* Mensajes de correo electrónico contenidos en archivos de datos de Outlook y LotusNotes;  
* Archivos comprimidos.

## Transformación de salida {#output-transformation}
  
GroupDocs.Viewer para Java proporciona un conjunto de opciones para aplicar distintas transformaciones a las páginas del documento:

* **Rotar páginas**: cambiar la orientación de las páginas al renderizar a HTML, JPG, PNG y PDF;  
* **Añadir marca de agua de texto**: añadir una marca de agua de texto a cada página renderizada;  
* **Reordenar páginas**: renderizar las páginas en el orden que prefieras o reordenarlas al renderizar a PDF.

## Almacenamiento en caché de resultados {#caching-results}
  
GroupDocs.Viewer para Java proporciona una API de visor de documentos que admite almacenamiento en caché para acelerar la carga de documentos y optimizar el rendimiento de la aplicación.

De forma predeterminada, la caché de documentos se guarda en el disco local. No obstante, la API del visor de documentos también proporciona interfaces para la caché de documentos que pueden implementarse para admitir almacenamiento de terceros: FTP, Amazon S3, Dropbox, Google Drive, Microsoft Azure, Redis o cualquier otro.
