## **Limitaciones de la versión de evaluación** {#evaluation-version-limitations}
  
La versión de evaluación de Aspose.Email (sin una licencia especificada) proporciona toda la funcionalidad del producto, excepto en algunos de sus componentes, como Aspose.Email.Mail, Aspose.Email.Pop3 y Aspose.Email.Imap, que presentan ciertas limitaciones de evaluación.

1. Se agrega el archivo License.txt al archivo de mensaje guardado mediante Aspose.Email  
2. Solo se pueden extraer 50 correos electrónicos de una carpeta en un archivo PST  
3. Solo se pueden extraer 3 archivos adjuntos, así como imágenes incrustadas, desde un archivo MSG  
4. El número máximo de adjuntos procesados en formato CFB es 1  
5. El número máximo de destinatarios procesados en formato CFB es 1  
6. Se agrega "Evaluation Message" en el asunto al guardar en formatos CFB, EML o MSG  
7. La fecha final no puede ser posterior al 31-12-2004 en el método GenerateOccurrences del patrón de recurrencia. Esto permite probar el producto de forma significativa, pero lo hace imposible de usar en una aplicación de producción. Por ejemplo, puede crear un patrón como "comenzar el 1 de enero de 2000 y repetirse cada último día laborable del mes" y generar sus ocurrencias. Las ocurrencias posteriores al 31 de diciembre de 2004 no se generarán en modo de evaluación  
8. Se agrega una "imagen de marca de agua de evaluación" al guardar en formatos XPS o TIFF  
9. El número máximo de direcciones de correo electrónico y nombres para mostrar ambiguos resueltos por el servidor MS Exchange Server es 20  
10. La longitud máxima permitida para el archivo que se puede arrastrar y soltar con FileDropPanel es 51200 bytes  
11. Muestra un cuadro de mensaje con "Evaluation Message" durante una operación de arrastrar y soltar utilizada por FileDropPanel  
12. Solo se extrae 1 archivo del flujo MSO dado mediante el método InlineAttachmentExtractor.EnumerateMsoPackage  

### **Establecer una licencia** {#setting-a-license}
  
La licencia es un archivo XML de texto simple que contiene detalles como el nombre del producto, la cantidad de desarrolladores a los que está licenciado, la fecha de vencimiento de la suscripción, etc. El archivo está firmado digitalmente, por lo que no debe modificarlo; incluso la adición accidental de un salto de línea adicional invalidará el archivo.

Debe aplicar una licencia si desea evitar las limitaciones de la versión de evaluación. Solo es necesario establecer una licencia una vez por aplicación o proceso.

La licencia puede cargarse desde un flujo o archivo en las siguientes ubicaciones:

1. Ruta explícita.  
2. La carpeta que contiene el archivo Aspose.Email.jar.  

Utilice el método License.setLicense para licenciar el componente. A menudo, la forma más sencilla de establecer una licencia es colocar el archivo de licencia en la misma carpeta que Aspose.Email.jar y especificar únicamente el nombre del archivo, sin la ruta, como se muestra en el siguiente ejemplo:

#### **Establecer licencia desde un archivo** {#setting-license-from-file}
  
En este ejemplo, **Aspose.Email** intentará encontrar el archivo de licencia en la carpeta que contiene los JAR de su aplicación.

```java
// For complete examples and data files, please go to https://github.com/aspose-email/Aspose.Email-for-Java
com.aspose.email.License license = new com.aspose.email.License();
		
license.setLicense("Aspose.Email.Java.lic");
```

#### **Establecer licencia desde un flujo** {#setting-license-from-stream}
  
Inicializa una licencia a partir de un flujo.

```java
// For complete examples and data files, please go to https://github.com/aspose-email/Aspose.Email-for-Java
com.aspose.email.License license = new com.aspose.email.License();
		
license.setLicense(new java.io.FileInputStream("Aspose.Email.Java.lic"));
```

### **Aplicar licencia por uso (Metered)** {#apply-metered-license}
  
Aspose.Email permite a los desarrolladores aplicar una clave por uso (metered key). Se trata de un nuevo mecanismo de licenciamiento que se utilizará junto con el método de licenciamiento existente. Los clientes que deseen ser facturados según el uso de las características de la API pueden utilizar el licenciamiento por uso. Para más detalles, consulte la sección <a href="https://purchase.conholdate.com/faqs/licensing/metered" target="_blank">Preguntas frecuentes sobre licenciamiento por uso</a>.

Se ha introducido una nueva clase, `Metered`, para aplicar la clave por uso. A continuación se muestra un ejemplo de código que demuestra cómo establecer las claves pública y privada por uso.

```java
// For complete examples and data files, please go to https://github.com/aspose-email/Aspose.Email-for-Java
Metered metered = new Metered();
// Access the SetMeteredKey property and pass public and private keys as parameters
metered.setMeteredKey("*****", "*****");

// The path to the documents directory. 
String dataDir = Utils.getSharedDataDir(DisplayEmailInformation.class) + "email/";

// Load the document from disk.
MailMessage eml = MailMessage.load(dataDir + "test.eml");
//Get the page count of document
System.out.println(eml.getSubject());
```

### **Validar la licencia** {#validate-the-license}
  
Es posible validar si la licencia se ha configurado correctamente o no. La clase <a href="http://www.aspose.com/api/java/email/com.aspose.email/classes/License" target="_blank" rel="nofollow noopener noreferrer">License</a> tiene el campo `isLicensed`, que devolverá `true` si la licencia se ha configurado correctamente.  

**Java**

```cs

 License license = new License();

license.setLicense("Aspose.Email.Java.lic");

if (License.isLicensed()) {

    System.out.println("License is Set!");

}
```
